# COMPASS: FxRates

## Compass

Build a currency rates service, an executable named `fxrates` at the application root, as
described in `sources/INSTRUCTIONS.md`. A command line loads the ECB euro reference rate history
into SQLite, and a FastAPI JSON API serves the rates on a date, conversions between any two
currencies, and a currency's history with minimum, maximum, and mean.

Correctness is measured by `sources/run.sh`: it loads the supplied ECB files, starts the server on
a free local port, and makes 35 checks of command output and HTTP status and JSON body. The goal is
every check passing.

- Implement in Python 3.11 or newer with FastAPI and uvicorn over SQLite.

- Store rates as the ECB's published text; compute with `decimal`, never with floating point.

Operations:
- `rates.replace_rate(date: str, currency: str, rate: str)` → row(date, currency, rate). Upsert on (date, currency).
- `rates.list_for_date(date: str)` → rows(date, currency, rate), exact date, order currency asc.
- `rates.list_on_or_before(as_of: str | None = None)` → rows(date), date <= as_of inclusive, order date desc. First row is the effective date; no rows means none.
- `rates.list_all_keys(since: str | None = None)` → rows(date, currency), date >= since, order date asc.
- `rates.list_currencies(since: str | None = None)` → rows(currency), date >= since, order currency asc; one row per stored rate, so dedupe in the service.

- `rates.delete_from_date(from_date: str)` → int removed count, date >= from_date. `init` passes `0000-01-01`.

# FEATURE: History Errors

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | GET /history/{code} answers 404 for a currency with no stored rate and 422 for a malformed start or end. |
| Depends On | FEATURE-HistoryStats.md, DATABASE.md |
| Provides | history error contract |
| Consumes | GET /history/{code} |

## Purpose

Define the failure statuses of `GET /history/{code}`.

## Behavior

- A currency with no stored rate at all answers `404`. This includes `EUR`, which is the base and
  is never stored as a rate.
- A currency that has stored rates but none inside the requested bounds is not an error: it answers
  `200` with `count` 0.
- A malformed `start` or `end` (not a real calendar date `YYYY-MM-DD`, for example `2025-01-31-x`
  or `2025-13-01`) answers `422`. The status is produced by FastAPI request validation of date
  query parameters.
- Existence of a currency is judged on the whole stored history, not on the requested bounds.

## Database Interface

- `FEATURE-RATE-006` — read: list a currency's rates over a period - supplies: `currency` - returns: `date`
