# FEATURE: Fetch

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | `fxrates fetch` downloads the ECB history archive, extracts the CSV, and loads it through the validated load path. |
| Depends On | FEATURE-LoadStore.md, FEATURE-LoadUnreadable.md |
| Provides | fxrates fetch, fxrates_app.fetch.download_archive |
| Consumes | fxrates load, fxrates_app.ecb.parse_history |

## Questions

- None.

## Purpose

`fxrates fetch` obtains the ECB euro reference rate history without a file argument. It downloads
`https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts the member
`eurofxref-hist.csv`, and loads that text exactly as `fxrates load` does.

## Trigger

The command line: `./fxrates fetch`. It takes no arguments; a wrong argument count is a usage error
(exit 2) handled by the shared validation.

## Sequence

1. Call `fxrates_app.fetch.download_archive(url)` for the ECB URL. It returns the archive bytes and
   uses `urllib` with a builder-chosen timeout. It is the only function in the application that
   opens a network connection.
2. The handler must call it through the module attribute (`fxrates_app.fetch.download_archive(...)`),
   never through a name imported into another module, so tests replace the single seam.
3. Open the bytes as a zip archive and read the member `eurofxref-hist.csv`.
4. Pass its text through the same parse, validate, and transactional store path used by `load`
   (`fxrates_app.ecb.parse_history`, then one transaction of upserts).
5. Print `dates,rates` then `<dates>,<rates>`, as `load` does, and exit 0.

## Exit codes

| Condition | Exit | Stdout | Stderr | Stored |
|-----------|------|--------|--------|--------|
| Success | 0 | `dates,rates` then counts | diagnostics only | the rates |
| Download fails or times out | 1 | empty | one line | nothing |
| Bytes are not a zip archive | 1 | empty | one line | nothing |
| Archive lacks `eurofxref-hist.csv` | 1 | empty | one line | nothing |
| Member is a rejected file | 3 | empty | one line | nothing |

## Database Interface

- None — persistence is owned by DATABASE.md and reached through the load path.

# FEATURE: Serve Health

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | `fxrates serve` runs the FastAPI service on 127.0.0.1 and answers health, OpenAPI, and docs requests. |
| Depends On | FEATURE-WebFoundation.md, FEATURE-CliUsageErrors.md, FEATURE-DatabaseSelection.md |
| Provides | fxrates serve, GET /health, GET /openapi.json, GET /docs |
| Consumes | app_server.create_app, cli.main |

## Questions

- None.

## Purpose

Start the HTTP API in the foreground and prove it is alive.

## Trigger

`./fxrates serve [--port <n>]`. Port validation (integer, 1 to 65535, otherwise exit 2) is owned by
the usage-error story and runs before any socket is bound.

## Sequence

1. Register the `serve` handler with the dispatcher.
2. Run uvicorn on `app_server.main:app` bound to `127.0.0.1` at the port, default `8000`, in the
   foreground. Nothing is required on standard output.
3. On SIGTERM stop cleanly and exit 0.
4. If the port is already bound, exit 1 with one stderr line and answer no requests.

## Routes

| Route | Status | Body |
|-------|--------|------|
| `GET /health` | 200 | `{"status": "ok"}` |
| `GET /openapi.json` | 200 | the FastAPI OpenAPI description |
| `GET /docs` | 200 | the interactive reference |

The OpenAPI and docs endpoints stay enabled. `/health` does not touch the database.

## Database Interface

- None — persistence is owned by DATABASE.md and `/health` reaches no store.

=== AC serve-live-sigterm ===
Intent: The serve command listens on 127.0.0.1 at the requested port, answers /health within a bounded wait, and exits 0 when it receives SIGTERM.
Requires: executable=python3; scope=test
Requires: python-package=uvicorn; scope=test

import json
import os
import signal
import socket
import subprocess
import tempfile
import time
import urllib.request

s = socket.socket()
s.bind(("127.0.0.1", 0))
port = s.getsockname()[1]
s.close()

work = tempfile.mkdtemp()
env = {**os.environ, "DATABASE_URL": os.path.join(work, "serve.db")}
proc = subprocess.Popen(
    [os.path.abspath("fxrates"), "serve", "--port", str(port)],
    stdin=subprocess.DEVNULL, stdout=subprocess.PIPE, stderr=subprocess.PIPE, env=env,
)
try:
    deadline = time.time() + 30
    body = None
    while time.time() < deadline:
        if proc.poll() is not None:
            break
        try:
            with urllib.request.urlopen(f"http://127.0.0.1:{port}/health", timeout=2) as r:
                assert r.status == 200
                body = json.loads(r.read())
            break
        except OSError:
            time.sleep(0.25)
    assert proc.poll() is None, "server exited before answering /health"
    assert body == {"status": "ok"}
    proc.send_signal(signal.SIGTERM)
    rc = proc.wait(timeout=20)
    assert rc == 0
finally:
    if proc.poll() is None:
        proc.kill()
    out, err = proc.communicate()
    print(out.decode("utf-8", "replace"))
    print(err.decode("utf-8", "replace"))
=== END AC serve-live-sigterm ===

## Purpose

Give a summary of what the store holds.

## Route

`GET /stats` returns status 200 with `{"dates": <n>, "rates": <n>, "first": <date>, "last": <date>}`.

takes the first and last date. Nothing is hardcoded.

# FEATURE: Rates By Date

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | `GET /rates/{date}` resolves the effective publication date and lists the rates published on it. |
| Depends On | FEATURE-ServeHealth.md, FEATURE-LoadStore.md |
| Provides | GET /rates/{date}, fxrates_app.rates.effective_date |
| Consumes | rates.list_on_or_before, rates.list_for_date, app_server.create_app |

## Questions

- None.

## Purpose

Answer which rates applied on a calendar day. The ECB publishes on working days only, so a request
for any date uses the latest publication on or before it.

## Effective date

`fxrates_app.rates.effective_date(d)` returns the latest publication date on or before `d`, or
`None` when no such date exists. It is computed with `rates.list_on_or_before(as_of=d)`; the first
row's date is the effective date. Other stories (`/convert`, `/history`, `/rates/latest`) reuse it.

## Route

`GET /rates/{date}`:

| Condition | Status | Body |
|-----------|--------|------|
| `date` is a real calendar date `YYYY-MM-DD` with an effective date | 200 | `{"date": <effective>, "requested": <date>, "base": "EUR", "rates": {<code>: <stored text>, ...}}` |
| `date` is a real date with no publication on or before it | 404 | any |
| `date` is malformed or not a real date (for example `2025-13-01`) | 422 | any |

- `rates` holds every currency with a rate on the effective date, as the stored text in a JSON
  string, and has no `EUR` entry.
- The date is validated through FastAPI request validation, which produces 422.
- Static routes such as `/rates/latest` are registered before this dynamic route so `latest` is not
  parsed as a date.

## Database Interface

- `FEATURE-RATE-003` — read: list publication dates on or before a date - supplies: `as_of` - returns: `date`
- `FEATURE-RATE-002` — read: list every rate published on one date - supplies: `date` - returns: `date`, `currency`, `rate`
