# ARCHITECTURE: FxRates

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |

## Questions

- None.

## Overview

FxRates keeps the ECB euro reference rate history in one SQLite table and serves it two ways: the
`fxrates` executable (`init`, `load`, `fetch`, `serve`) and a FastAPI JSON API bound to
`127.0.0.1`. EUR is the base currency. Rates are stored as the ECB's published text, and all
arithmetic uses `decimal`, never floating point.

## Project Layout

| Path | Purpose |
|------|---------|
| `pyproject.toml`, `uv.lock` | Python 3.11+ project; dependencies fastapi, uvicorn, httpx2, pytest; committed lockfile. |
| `.venv` | Environment created by `uv venv`; launchers in `bin/` and `fxrates` activate it. |
| `fxrates` | Executable at the application root; a POSIX sh launcher that calls `cli.main`. |
| `bin/test.sh` | Runs `pytest -q` offline. |
| `fxrates_app/` | Application package: `config`, `ecb`, `fetch`, `rates`, `history`, `convert`, `commands`. |
| `cli/` | Command line foundation: `main`, dispatcher, usage validation, `testing.cli_runner`. |
| `app_server/` | Web foundation: `create_app`, module-level `app`, `testing.web_client`. |
| `persistence/` | Generated by Drydock from `DATABASE.md`; never hand-written. |
| `tests/` | pytest suite with `conftest.py`, written beside the code. |
| `sources/` | Read-only scoring assets; never read by application code. |

## Module Ownership

| Boundary | Owning module | Allowed low-level access |
|----------|---------------|--------------------------|
| Persistence | `persistence` (generated) | The only module that imports a database driver. |
| Configuration | `fxrates_app.config` | Reads `DATABASE_URL`, `DATABASE_PATH`; opens the store via `persistence.open_database`. |
| ECB parsing | `fxrates_app.ecb` | Pure functions over CSV text; no I/O to the store. |
| Network | `fxrates_app.fetch` | `download_archive(url)` is the only network call and the test seam. |
| Rate queries | `fxrates_app.rates`, `history`, `convert` | Call `db.rates.<operation>(...)` only. |
| Command line | `cli` | Dispatch, usage validation, exit codes; diagnostics to standard error. |
| HTTP | `app_server` | Application factory and shared router registry. |

Routes and commands call services; services call `db.rates.<operation>(...)`. SQL, table names, and
column names never cross the persistence boundary. Application code never imports `sqlite3` or any
other driver.

## Technology Stack

| Technology | Where it applies |
|------------|------------------|
| Python 3.11+ | Whole application. |
| FastAPI, uvicorn | JSON API served on `127.0.0.1`, default port 8000. |
| SQLite | The `rates` table, reached through the shipped persistence library. |
| CLI | The `fxrates` executable. |
| pytest, FastAPI `TestClient` | Test suite behind `bin/test.sh`. |
| ECB reference rates | Input: `eurofxref-hist.csv`, downloaded as `eurofxref-hist.zip`. |
| POSIX sh | `fxrates` launcher and `bin/test.sh`. |

## Technical Decisions

- Exit codes: `0` success, `1` operational failure, `2` usage error, `3` rejected file.
- Failing commands write nothing to standard output and one diagnostic line to standard error.
- Database location: `DATABASE_URL` (optional `sqlite://` prefix), then `DATABASE_PATH`, then `data/app.db`.
- Tests never open a network connection; `fetch` tests replace `fxrates_app.fetch.download_archive`.
- Diagnostics go to standard error and are never compared.

# FEATURE: Command Line Foundation

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |

| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | fxrates, cli.main, cli.testing.cli_runner |

## Questions

- None.

## Purpose

Provide the shell every command story plugs into: `cli.main(argv) -> int`, a registry mapping a
command name to a handler, and the `fxrates` launcher. This story proves only the interface.

## Interface

```python
# cli/__init__.py
def main(argv: list[str] | None = None) -> int: ...
def register_command(name: str, handler: Callable[[list[str]], int]) -> None: ...

# cli/testing.py
def cli_runner(*args: str) -> tuple[int, str, str]: ...
```

- `main` dispatches `argv[0]` to the registered handler, passing the remaining arguments, and
  returns the handler's integer exit code. Diagnostics go to standard error.
- `register_command` is called by command stories at import time; registering a name again replaces
  the earlier handler.
- `cli_runner` calls `main` in-process and returns `(exit_code, stdout, stderr)`.
- `fxrates` is a POSIX sh script at the application root with the executable bit set. It activates
  `.venv` when present, runs `cli.main` with its arguments, and exits with the returned code.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: CLI Usage Errors

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Argument validation that reports usage errors with exit 2, empty stdout, and one stderr line. |
| Depends On | FEATURE-CliFoundation.md |
| Provides | fxrates usage validation |
| Consumes | cli.main |

## Questions

- None.

## Purpose

Reject malformed invocations before any handler, database, or socket is touched.

## Behavior

`cli/usage.py` provides `UsageError` and `validate(argv: list[str]) -> None`; `cli.main` calls it
before dispatch and, on `UsageError`, writes one line to standard error, nothing to standard output,
and returns `2`.

| Command | Arguments |
|---------|-----------|
| `init` | none |
| `load` | exactly one (the CSV path) |
| `fetch` | none |
| `serve` | optional `--port <n>`; `n` an integer from 1 to 65535 |

- No command, or a command in neither this table nor the handler registry, is a usage error.
- A wrong argument count, a `--port` without a value, a non-integer `--port`, and a `--port`
  outside 1 to 65535 are usage errors.
- A command registered but absent from the table is not arity-checked.
- A lone `--help` after a known command is passed through to its handler.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Database Selection

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Resolve the database location from DATABASE_URL, then DATABASE_PATH, then data/app.db, and open it through the persistence library. |
| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | fxrates_app.config.database_path |
| Consumes | persistence.open_database |

## Questions

- None.

## Purpose

Give every command and route one place that decides which SQLite file to use.

## Interface

```python
# fxrates_app/config.py
def database_path() -> str: ...
def open_store() -> Database: ...   # persistence.open_database(database_path())
```

Resolution order:

1. `DATABASE_URL`, when set and nonempty; an optional `sqlite://` prefix is removed.
2. `DATABASE_PATH`, when set and nonempty.
3. `data/app.db`.

An empty value counts as unset. The function reads the environment at call time. Application code
opens the store only through `persistence.open_database` and never imports a driver.

## Database Interface

- None — persistence is owned by DATABASE.md.
