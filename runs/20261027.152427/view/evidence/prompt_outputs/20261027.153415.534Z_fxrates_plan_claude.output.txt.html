# FEATURE: Rates Latest

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | GET /rates/latest returns the rates of the latest publication date with requested set to "latest". |
| Depends On | FEATURE-RatesByDate.md, DATABASE.md |
| Provides | GET /rates/latest |
| Consumes | GET /rates/{date}, rates repository operations |

## Questions

- None.

## Purpose

Serve the most recent publication without the caller knowing its date.

## Behavior

- `GET /rates/latest` finds the latest publication date overall with `rates.list_on_or_before` called without `as_of`; the first row is the latest date.
- The 200 body has the same shape as `/rates/{date}`: `date`, `requested`, `base` "EUR", and `rates` mapping each stored currency to its stored rate text. `requested` is the string `"latest"`.
- When nothing is stored the response is 404.
- The route is registered before `/rates/{date}` so `latest` is never parsed as a malformed date (which would yield 422).

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Load Visibility

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | A completed load is visible to the next API request, and a rejected load changes nothing a request can see. |
| Depends On | FEATURE-LoadStore.md, FEATURE-Stats.md, DATABASE.md |
| Provides | load visibility contract |
| Consumes | fxrates load, GET /stats |

## Questions

- None.

## Purpose

Loads happen while the server runs. This integration story proves the API reads committed state on every request and that a load is applied as one transaction.

## Behavior

- The API opens its store per request and caches no rows or connection state that could hide a later commit.
- `load` validates the whole file, then writes inside one transaction, so a reader sees the rates from before the load or from after it, never part of it.
- A rejected load (exit 3) leaves `/stats` unchanged.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: Convert

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | GET /convert converts an amount between two currencies with exact decimal arithmetic rounded half to even. |
| Depends On | FEATURE-RatesByDate.md, DATABASE.md |
| Provides | GET /convert |
| Consumes | fxrates_app.rates.effective_date, rates repository operations |

## Questions

- None.

## Purpose

Answer "how much of currency B is this amount of currency A" on a date, from stored ECB rates.

## Behavior

- Query parameters: `from`, `to`, `amount` matching `[0-9]+(\.[0-9]+)?`, and optional `date`.
- Effective date: with `date`, `effective_date(date)`; without it, the latest publication date.
- EUR has the implicit rate 1. Any other currency's rate is read from the effective date's rates.
- `rate = rate(to) / rate(from)` computed with `decimal`, rounded half to even to six decimals, returned as a string with exactly six decimals.
- `result = amount * rate(to) / rate(from)` computed exactly from the stored rates, not from the rounded `rate`, rounded half to even to two decimals, returned as a string with exactly two decimals.
- `amount` is echoed as given, as a string. The body is `{date, from, to, amount, rate, result}`.
- Same `from` and `to` gives rate `1.000000` and the amount rounded half to even to two decimals. Amount `0` gives `0.00`.
- No floating point is used anywhere.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

from decimal import Decimal, ROUND_HALF_EVEN
from persistence.testing import db_session
from app_server.testing import web_client

d = "2999-01-01"
rate_from = "1.0298"
rate_to = "0.84453"
amount = "100"

with db_session() as db:
    db.rates.replace_rate(date=d, currency="ZZA", rate=rate_from)
    db.rates.replace_rate(date=d, currency="ZZB", rate=rate_to)

    assert body["from"] == "ZZA"
    assert body["to"] == "ZZB"

# FEATURE: Convert Errors

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | GET /convert refuses unknown currencies and missing publications with 404 and bad or missing inputs with 422. |
| Depends On | FEATURE-Convert.md |
| Provides | convert error contract |
| Consumes | GET /convert |

## Questions

- None.

## Purpose

Fix the failure statuses of `/convert`.

## Behavior

- 404: a currency other than EUR with no rate on the effective date; no publication on or before the requested date; no publication stored at all.
