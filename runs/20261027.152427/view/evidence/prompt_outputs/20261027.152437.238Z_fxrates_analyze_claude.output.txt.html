# Blueprint Analysis: drydock FxRates Uat Case

## Commander Expectations

- assert the product loads ECB euro reference rate history files into a local SQLite database through a command line
- assert the product serves rates by date, currency conversion, and currency history as JSON over HTTP on 127.0.0.1
- assert every rate is stored and returned as published text, never as floating point
- assert every conversion and statistic uses exact decimal arithmetic rounded half to even
- assert the supplied grader `sources/run.sh` exits zero

### Feature: ECB History Loading

| ID | Story | High-level AC |
|---|---|---|
| LOAD-001 | Validate an ECB history file before writing | The header, field counts, real and unique dates, and value rules are checked over the whole file. Any violation exits 3 and writes nothing. |
| LOAD-002 | Store published rates as text | Each non-N/A rate is stored as published text, replacing any existing row for the same date and currency. The `dates,rates` counts are reported, and reloading leaves data unchanged. |
| LOAD-003 | Report an unreadable file | A missing or unreadable file exits 1 with one stderr line and writes nothing. |
| LOAD-004 | Make loads visible to a running server | A load completed while the server runs is visible to the next request. |
| LOAD-005 | Fetch and load the ECB archive | `fetch` downloads the ECB zip, extracts `eurofxref-hist.csv`, and loads it. A failed download exits 1. Tests stub the download. |

### Feature: Rate Lookup

| ID | Story | High-level AC |
|---|---|---|
| RATES-001 | Serve the API and report health | `fxrates serve --port n` listens on 127.0.0.1 (default 8000), and `GET /health` returns 200 with `{"status": "ok"}`. |
| RATES-002 | Report store statistics | `GET /stats` returns `dates`, `rates`, `first`, and `last`, with `first` and `last` null when the table is empty. |
| RATES-003 | List stored currencies | `GET /currencies` returns base EUR and the ascending codes that have a stored rate. |
| RATES-004 | Resolve rates for a date | `GET /rates/{date}` uses the latest publication on or before the date. It returns 404 when none exists and 422 for a malformed date. |
| RATES-005 | Report the latest rates | `GET /rates/latest` returns the latest publication with `"requested": "latest"`. |

### Feature: Conversion

| ID | Story | High-level AC |
|---|---|---|
| CONVERT-001 | Convert an amount between currencies | `GET /convert` returns the effective date, a six-decimal rate, and a two-decimal result, computed exactly and rounded half to even. EUR has the implicit rate 1. The latest publication is used when `date` is omitted. |
| CONVERT-002 | Refuse unknown currencies and bad inputs | An unknown currency, or no rate on the effective date, returns 404. A missing or malformed `amount`, `date`, or required parameter returns 422. |

### Feature: Currency History

| ID | Story | High-level AC |
|---|---|---|
| HIST-001 | List a currency's points over a period | `GET /history/{code}` returns ascending publication points from `start` through `end` inclusive. Both bounds are optional. |
| HIST-002 | Summarize a currency's history | `count`, `min`, and `max` (stored text), and `mean` (six decimals, half to even) are returned. An empty history yields `count` 0 and null statistics. |
| HIST-003 | Refuse unknown currencies and bad bounds | A currency with no stored rate, including EUR, returns 404. A malformed `start` or `end` returns 422. |

**Selected behaviors (unattended resolution).** These are the narrowest behaviors consistent with the sources, and they are the planning baseline:

1. `/rates` maps list only stored currencies. EUR is not listed, matching H4 and H8. EUR appears only as the implicit rate 1 in `/convert`.
2. `/convert` with the same `from` and `to` returns rate `1.000000` (AC-008).
3. `/history` with `start` after `end` returns 200 with an empty result (AC-012).
4. A syntactically valid but impossible date such as `2025-13-01` counts as malformed and returns 422 (H7).

6. `--port` must be an integer from 1 to 65535. Otherwise the command exits 2.
7. The API has no authentication. It serves public ECB reference rates, binds only to 127.0.0.1, and has no protected resource.
8. A load is applied as one transaction, so readers never see a partial load (AC-011).
9. `fetch` bounds its download with a timeout chosen by the builder. The sources state no timeout value, so none is invented. A failed or timed-out download exits 1 and stores nothing (st-013).
10. Deployment is a local foreground process started by `./fxrates serve`. A SIGTERM stops it and exits 0 (AC-004).
11. Sensitive data: none. ECB euro reference rates are public.
12. Schema evolution: none. `init` builds the single table once, so migrations are not used within a release.
