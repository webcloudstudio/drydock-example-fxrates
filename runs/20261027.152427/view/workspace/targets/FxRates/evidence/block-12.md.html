  • summary: load-004 single-transaction commit is unmet because the shipped persistence library has no public write transaction.
  • detail:

fxrates load autocommits each db.rates.replace_rate call, so a concurrent request can see a partial load. The only available hook is Database.execute_script with raw BEGIN/COMMIT, which the library documents as DDL-only and forbids under the acceptance harness, so I did not use it. To rerun: add a transaction operation to the shipped persistence library (or update DATABASE.md and regenerate), then wrap the replace loop in fxrates_app/cli/load_command.py in that transaction. The rates-005 story and the other load-004 checks are already satisfied.

The gap is the atomic commit. load writes each rate through db.rates.replace_rate, and each call autocommits. A request that arrives mid-load can see part of the file. The shipped persistence/db.py has no public write transaction. I did not wrap the load in raw transaction SQL: that would bypass the declared operations and break the harness-shared tests. Closing the gap needs a transaction operation in the shipped persistence library (or a DATABASE.md change), which is outside this build.
