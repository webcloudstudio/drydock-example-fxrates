Store: SQLite or PostgreSQL via open_database(dsn); only the generated persistence package reaches the store. Calls are db.rates.<op>(...); rows expose .date, .currency, .rate (text, never float).

Table rates: id INTEGER PK; date TEXT NOT NULL (YYYY-MM-DD); currency TEXT NOT NULL (3-letter uppercase); rate TEXT NOT NULL (as published). UNIQUE(date, currency).

Operations:

  • rates.replace_rate(date: str, currency: str, rate: str) → row(date, currency, rate). Upsert on (date, currency).
  • rates.list_for_date(date: str) → rows(date, currency, rate), exact date, order currency asc.
  • rates.list_on_or_before(as_of: str | None = None) → rows(date), date <= as_of inclusive, order date desc. First row is the effective date; no rows means none.
  • rates.list_all_keys(since: str | None = None) → rows(date, currency), date >= since, order date asc.
  • rates.list_currencies(since: str | None = None) → rows(currency), date >= since, order currency asc; one row per stored rate, so dedupe in the service.
  • rates.list_currency_history(currency: str | None, start_date: str | None, end_date: str | None) → rows(date, currency, rate), inclusive bounds, order date asc. Empty with only currency means no stored rate.
  • rates.delete_from_date(from_date: str) → int removed count, date >= from_date. init passes 0000-01-01.

Config: DATABASE_URL (takes precedence, optional sqlite:// prefix), DATABASE_PATH (default data/app.db).
Testing: persistence.testing.db_session() yields a rolled-back session over the provisioned store. Services derive counts, first/last dates, and distinct currencies from list results; no aggregate operations exist. </reusable-compact>

SUMMARY: Built both block-3 stories, cli-foundation and web-foundation.

  • cli: main(argv) -> int dispatches argv[0] to a registered handler and returns its exit code. An empty argv or an unknown command returns 2 with a diagnostic on stderr. register_command replaces an existing name. cli/testing.py provides cli_runner, and cli/__main__.py makes python -m cli work. The fxrates launcher is POSIX sh with the executable bit set. It activates .venv when present and runs python -m cli "$@".
  • app_server: create_app() returns a new FastAPI instance that includes app_server.routes.router. The module-level app is created from it. web_client() returns TestClient(create_app()). The pytest cli_runner and web_client fixtures in tests/conftest.py delegate to these callables.

Decisions for the user to review (Low severity):

  • The dispatcher lives in cli/dispatcher.py. I did not add a parser.py, since no story here needs argparse yet.
  • fxrates runs cd to the application root before invoking Python. This keeps python -m cli importable and makes the default data/app.db resolve correctly, but it means relative file paths passed by callers resolve against the root. Later command stories should be aware of this.

Caveat for later blocks: create_app() copies the routes that exist on routes.router at the moment it is called. Routes that feature stories add to the registry after app_server.main has been imported will not appear on the module-level app. Stories should either import app_server.routes before app_server.main, or create_app should be changed to defer inclusion.
