Blueprint Analysis: drydock FxRates Uat Case

Commander Expectations

  • assert the product loads ECB euro reference rate history files into a local SQLite database through a command line
  • assert the product serves rates by date, currency conversion, and currency history as JSON over HTTP on 127.0.0.1
  • assert every rate is stored and returned as published text, never as floating point
  • assert every conversion and statistic uses exact decimal arithmetic rounded half to even
  • assert the supplied grader sources/run.sh exits zero

Planning Instructions

Delivery Shape

The inferred system is a command line (fxrates) plus a FastAPI JSON API served by uvicorn, over one SQLite table named rates. The project type is ambiguous: it has described commands and described HTTP endpoints with no screens. Inputs are ECB history CSV files and, for fetch, the ECB zip archive. Outputs are stdout counts for load, JSON responses for the API, and exit codes throughout. The required flow is init, then load, then serve, with loads allowed while serving.

Test and Acceptance Strategy

Feature stories prove their own behavior with pytest against a real temporary SQLite database. The API tests use FastAPI's TestClient, and fetch tests use a stubbed download. Each feature story declares Suite: scoped and runs only its own pytest selector. sources/run.sh has no scope selector, so no feature story runs it.

ACCEPT-001 is the single terminal verification story. It depends on all 20 other stories, and its acceptance assertion declares Suite: full. It runs sh sources/run.sh unfiltered, and its verdict is that script's exit status. Sea Trial st-001 is the matching proof.

Source Conflicts and Gaps

Cross-source conflicts. None found. The brief and run.sh agree on every checked known answer, including the rounding examples in H9–H12, H17, H18, and L5. No conflicting definitions require a decision.

Selected behaviors (unattended resolution). These are the narrowest behaviors consistent with the sources, and they are the planning baseline:

  1. /rates maps list only stored currencies. EUR is not listed, matching H4 and H8. EUR appears only as the implicit rate 1 in /convert.
  2. /convert with the same from and to returns rate 1.000000 (AC-008).
  3. /history with start after end returns 200 with an empty result (AC-012).
  4. A syntactically valid but impossible date such as 2025-13-01 counts as malformed and returns 422 (H7).
  5. /rates/latest is matched before /rates/{date}, so latest is not parsed as a malformed date.
  6. --port must be an integer from 1 to 65535. Otherwise the command exits 2.
  7. The API has no authentication. It serves public ECB reference rates, binds only to 127.0.0.1, and has no protected resource.
  8. A load is applied as one transaction, so readers never see a partial load (AC-011).
  9. fetch bounds its download with a timeout chosen by the builder. The sources state no timeout value, so none is invented. A failed or timed-out download exits 1 and stores nothing (st-013).
  10. Deployment is a local foreground process started by ./fxrates serve. A SIGTERM stops it and exits 0 (AC-004).
  11. Sensitive data: none. ECB euro reference rates are public.
  12. Schema evolution: none. init builds the single table once, so migrations are not used within a release.

Gaps. No Gap Checklist item requires a human decision. The Core Baseline gaps (help text and an API reference entry point) are covered by AC-001 and AC-005. Success criteria are not stated in the sources. The supplied grader is the acceptance verdict (st-001).
