FEATURE: Load Validation

FieldValue
Version20261027 V1
DescriptionValidate a whole ECB history file before any write and return the non-N/A rates as published text.
Depends OnFEATURE-InitCommand.md
Providesfxrates_app.ecb.parse_history

Purpose

fxrates_app.ecb.parse_history(text) checks an entire ECB history file and returns (date, currency, rate_text) for every non-N/A value, or raises RejectedFile. It performs no database access. The load command (FEATURE-LoadStore.md) maps RejectedFile to exit 3.

Rules

  1. The header's first field is Date; every other field is a three-letter uppercase currency code.

The ECB writes a trailing comma on each line; the resulting empty last field is ignored.

  1. Each row has exactly as many fields as the header, and begins with a date YYYY-MM-DD that is a

real calendar date and is not repeated within the file.

  1. A value is N/A (no rate, nothing returned) or matches [0-9]+(\.[0-9]+)? and is nonzero.
  2. The whole file is checked before the function returns; any violation raises RejectedFile, a

subclass of Exception.

  1. Rates are returned as the published text, never as a number.

Database Interface

  • None — persistence is owned by DATABASE.md.

User Acceptance

  • None.

Guardrails

  • The whole file is checked before any result is returned; callers never see a partial parse.
  • Rates are never converted to a float; the published text is preserved.
  • The parser performs no database access and reads no file.
