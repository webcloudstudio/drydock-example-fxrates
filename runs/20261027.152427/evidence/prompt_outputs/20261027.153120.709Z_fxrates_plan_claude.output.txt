# FEATURE: Init Command

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | `fxrates init` empties the rates table, prints nothing, and exits 0. |
| Depends On | FEATURE-CliUsageErrors.md, FEATURE-DatabaseSelection.md, DATABASE.md |
| Provides | fxrates init |
| Consumes | cli.main, fxrates_app.config.database_path, rates.delete_from_date |

## Questions

- None.

## Purpose

`fxrates init` resets the rates store to empty. The schema is provisioned by the DATABASE step and
application code never runs DDL or opens a driver, so init removes every stored rate through the
declared `rates.delete_from_date` operation, passing a `from_date` earlier than any publication
(`0000-01-01`). Afterward the table exists and holds no rows.

## Behavior

- Registers the `init` handler with the dispatcher in `cli`.
- Opens the store through `persistence.open_database` using the configured database location.
- Removes every row, prints nothing to standard output, and exits `0`.
- Init takes no arguments; a wrong argument count is a usage error owned by FEATURE-CliUsageErrors.md.
- Running init on an already empty store succeeds and changes nothing.

## Database Interface

- `FEATURE-RATE-007` — write: remove every stored rate - supplies: `from_date` - returns: —

# FEATURE: Load Validation

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Validate a whole ECB history file before any write and return the non-N/A rates as published text. |
| Depends On | FEATURE-InitCommand.md |
| Provides | fxrates_app.ecb.parse_history |

## Questions

- None.

## Purpose

`fxrates_app.ecb.parse_history(text)` checks an entire ECB history file and returns
`(date, currency, rate_text)` for every non-N/A value, or raises `RejectedFile`. It performs no
database access. The load command (FEATURE-LoadStore.md) maps `RejectedFile` to exit 3.

## Rules

1. The header's first field is `Date`; every other field is a three-letter uppercase currency code.
   The ECB writes a trailing comma on each line; the resulting empty last field is ignored.
2. Each row has exactly as many fields as the header, and begins with a date `YYYY-MM-DD` that is a
   real calendar date and is not repeated within the file.
3. A value is `N/A` (no rate, nothing returned) or matches `[0-9]+(\.[0-9]+)?` and is nonzero.
4. The whole file is checked before the function returns; any violation raises `RejectedFile`, a
   subclass of `Exception`.
5. Rates are returned as the published text, never as a number.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

# FEATURE: Load Store

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | `fxrates load <csv>` validates an ECB history file, stores its rates as text in one transaction, and reports the dates and rates counts. |
| Depends On | FEATURE-LoadValidation.md, FEATURE-InitCommand.md, DATABASE.md |
| Provides | fxrates load |
| Consumes | fxrates_app.ecb.parse_history, rates.replace_rate, fxrates_app.config.database_path, cli.main |

## Questions

- None.

## Purpose

`fxrates load <csv>` reads an ECB history file, validates it completely with
`fxrates_app.ecb.parse_history`, and then upserts every non-N/A rate through `rates.replace_rate`
in a single transaction, so a reader sees all or none of the load.

## Behavior

- A rejected file (`RejectedFile`) exits `3`, prints nothing to standard output, writes one
  diagnostic line to standard error, and stores nothing.
- On success it prints `dates,rates` on the first line and `<dates>,<rates>` on the second, where
  `dates` counts the dates in the file with at least one stored rate and `rates` counts the rates stored.
- A rate for a (date, currency) already stored replaces it, so loading the same file twice leaves the
  database unchanged.
- A file holding only N/A values prints `0,0` and stores nothing.
- Unreadable files are handled by FEATURE-LoadUnreadable.md.

## Database Interface

- `FEATURE-RATE-001` — write: store a rate, replacing the stored one - supplies: `date`, `currency`, `rate` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

=== AC load-counts-and-text ===

Requires: executable=python3; scope=test

import csv
import os
import tempfile
from persistence.testing import db_session
from cli.testing import cli_runner

header = ["Date", "ZZA", "ZZB", "ZZH"]

    ["1900-08-03", "1.50", "N/A", "N/A"],

# FEATURE: Load Unreadable File

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | A missing or unreadable file makes `fxrates load` exit 1 with one stderr line and write nothing. |
| Depends On | FEATURE-LoadStore.md |
| Provides | fxrates load unreadable-file handling |

## Questions

- None.

## Purpose

Operational failures reading the input file are distinct from a rejected file. An `OSError` (missing
file, directory, permission) or undecodable content while reading makes `load` exit `1`, print
nothing to standard output, write exactly one diagnostic line to standard error, and write nothing
to the database.
