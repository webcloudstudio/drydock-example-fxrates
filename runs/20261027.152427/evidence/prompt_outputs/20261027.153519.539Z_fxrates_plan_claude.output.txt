# FEATURE: History Points

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | GET /history/{code} lists a currency's stored rates in ascending date order between optional inclusive bounds. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-RatesByDate.md, FEATURE-WebFoundation.md |
| Provides | GET /history/{code} |
| Consumes | fxrates_app.rates.effective_date, rates repository operations, app_server.create_app |

## Questions

- None.

## Purpose

Serve a currency's history over a period. The response is a JSON object with `currency`, `base`
(always `EUR`), `count`, `min`, `max`, `mean`, and `points`. This story delivers `currency`, `base`,
and `points`; the statistics fields are specified by `FEATURE-HistoryStats.md` and implemented
over the same route.

## Route

`GET /history/{code}` with optional query parameters `start` and `end`, each a calendar date
`YYYY-MM-DD`.

## Behavior

- `points` holds one `{"date": <date>, "rate": <stored text>}` object per publication date of the
  currency from `start` through `end` inclusive, in ascending date order.
- Both bounds are optional. Without `start` the history begins at the earliest stored date; without
  `end` it runs to the latest.
- Each `rate` is the stored text as a JSON string, exactly as the ECB published it (`0.943` stays
  `0.943`). No arithmetic or float conversion is applied to a point.
- When `start` is later than `end`, the response is 200 with an empty `points` list.
- A currency code is matched as given; the response `currency` echoes it.
- A history is read through the persistence library by one call per request, so a load completed
  before the request is visible to it.

## Database Interface

- `FEATURE-RATE-006` — read: list a currency's rates over a period - supplies: `currency`, `start_date`, `end_date` - returns: `date`, `currency`, `rate`

code = "ZZH"

# FEATURE: History Statistics

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | GET /history/{code} reports count, min, max, and mean over the points it returns. |
| Depends On | FEATURE-HistoryPoints.md |
| Provides | history statistics |
| Consumes | GET /history/{code} |

## Questions

- None.

## Purpose

Add the summary fields `count`, `min`, `max`, and `mean` to the `/history/{code}` response, computed
over exactly the points the response lists.

## Behavior

- `count` is the number of points.
- `min` and `max` are the stored text, as JSON strings, of the smallest and largest rate by numeric
  value (compared as `Decimal`, never as text or float). The returned text is the stored text
  unchanged: `0.943` stays `0.943`.
- `mean` is the exact arithmetic mean of the point rates, computed with `decimal`, rounded half to
  even to six decimal places and written with exactly six decimals, as a JSON string.
- With no points, `count` is `0` and `min`, `max`, and `mean` are all `null`; `points` is `[]`.
- Statistics cover only the points inside the requested bounds.

## Database Interface

- None — persistence is owned by FEATURE-HistoryPoints.md.

## Programmatic Acceptance

=== AC history-stats-min-max-count ===
Intent: Count, min, and max are derived from the seeded rate texts by Decimal value, and min and max keep the stored text unchanged.
Requires: executable=python3; scope=test
Requires: python-package=fastapi; scope=test
Requires: python-package=httpx2; scope=test

from decimal import Decimal

from app_server.testing import web_client
from persistence.testing import db_session

code = "ZZH"
rates = {
    "1900-12-01": "0.9453",
    "1900-12-02": "0.943",
    "1900-12-03": "0.9441",
    "1900-12-04": "10.5",
    "1900-12-05": "9.75",
}

    for d, r in rates.items():
        db.rates.replace_rate(date=d, currency=code, rate=r)
    client = web_client()
    resp = client.get(f"/history/{code}")
    assert resp.status_code == 200
    body = resp.json()
    texts = list(rates.values())
    assert body["count"] == len(texts)
    assert body["min"] == min(texts, key=Decimal)
    assert body["max"] == max(texts, key=Decimal)

=== AC history-stats-mean-half-even ===
Intent: Mean is the exact mean rounded half to even at six decimals and printed with six decimals; the two cases are exact ties at the seventh decimal, so they distinguish half-even from half-up.
Requires: executable=python3; scope=test
Requires: python-package=fastapi; scope=test
Requires: python-package=httpx2; scope=test

from decimal import Decimal, ROUND_HALF_EVEN

from app_server.testing import web_client
from persistence.testing import db_session

cases = {
    "ZZM": {"1901-01-01": "1.000000", "1901-01-02": "1.000001"},
    "ZZN": {"1901-01-01": "1.000001", "1901-01-02": "1.000002"},
}

with db_session() as db:
    for code, rates in cases.items():
        for d, r in rates.items():
            db.rates.replace_rate(date=d, currency=code, rate=r)
    client = web_client()
    for code, rates in cases.items():
        resp = client.get(f"/history/{code}")
        assert resp.status_code == 200
        body = resp.json()
        total = sum(Decimal(r) for r in rates.values())
        mean = (total / len(rates)).quantize(Decimal("0.000001"), rounding=ROUND_HALF_EVEN)
        assert body["mean"] == f"{mean:.6f}"
=== END AC history-stats-mean-half-even ===

=== AC history-stats-bounded ===
Intent: Statistics cover only the points inside the requested bounds, not the whole stored history.
Requires: executable=python3; scope=test
Requires: python-package=fastapi; scope=test
Requires: python-package=httpx2; scope=test

from decimal import Decimal, ROUND_HALF_EVEN

from app_server.testing import web_client
from persistence.testing import db_session

code = "ZZH"
rates = {
    "1901-02-01": "100",
    "1901-02-02": "1.5",
    "1901-02-03": "2.25",
    "1901-02-04": "0.5",
}
start = "1901-02-02"
end = "1901-02-03"

with db_session() as db:
    for d, r in rates.items():
        db.rates.replace_rate(date=d, currency=code, rate=r)
    client = web_client()
    resp = client.get(f"/history/{code}", params={"start": start, "end": end})
    assert resp.status_code == 200
    body = resp.json()
    inside = [rates[d] for d in sorted(rates) if start <= d <= end]
    assert body["count"] == len(inside)
    assert body["min"] == min(inside, key=Decimal)
    assert body["max"] == max(inside, key=Decimal)
    mean = (sum(Decimal(r) for r in inside) / len(inside)).quantize(
        Decimal("0.000001"), rounding=ROUND_HALF_EVEN
    )
    assert body["mean"] == f"{mean:.6f}"
=== END AC history-stats-bounded ===

# FEATURE: History Errors

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | GET /history/{code} answers 404 for a currency with no stored rate and 422 for a malformed start or end. |
| Depends On | FEATURE-HistoryStats.md, DATABASE.md |
| Provides | history error contract |
| Consumes | GET /history/{code} |

## Questions

- None.

## Purpose

Define the failure statuses of `GET /history/{code}`.

## Behavior

- A currency with no stored rate at all answers `404`. This includes `EUR`, which is the base and
  is never stored as a rate.
- A currency that has stored rates but none inside the requested bounds is not an error: it answers
  `200` with `count` 0.
- A malformed `start` or `end` (not a real calendar date `YYYY-MM-DD`, for example `2025-01-31-x`
  or `2025-13-01`) answers `422`. The status is produced by FastAPI request validation of date
  query parameters.
- Existence of a currency is judged on the whole stored history, not on the requested bounds.

## Database Interface

- `FEATURE-RATE-006` — read: list a currency's rates over a period - supplies: `currency` - returns: `date`

## Programmatic Acceptance
