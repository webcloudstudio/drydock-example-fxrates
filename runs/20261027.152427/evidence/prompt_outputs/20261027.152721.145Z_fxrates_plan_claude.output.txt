## story database
summary:      Declare the rates table and every repository operation the stories need; Drydock generates the persistence package.
type:         foundational
kind:         capability
phase:        1
implements:   DATABASE.md
stack:        common.md, python.md, persistence.md, sqlite.md
provides:     persistence.open_database, rates repository operations
depends:      foundation-python
instructions: |
  Author-level contract only; the builder writes no persistence code. Declare one table `rates`
  (date TEXT, currency TEXT, rate TEXT, PK surrogate id, UNIQUE (date, currency)). Declare an
  operation for each need: upsert a rate by (date, currency); list all rates for a date; the latest
  publication date on or before a date; the latest publication date overall; count of dates and
  rates; first and last date; distinct currencies ascending; history list for a currency between
  optional bounds ordered by date ascending; and a reset operation that removes every row for init.
acceptance:   yes

## story load-001-validate
summary:      Validate a whole ECB history file before any write.
type:         service
kind:         capability
phase:        1
implements:   FEATURE-LoadValidation.md
covers:       LOAD-001
stack:        common.md, python.md
provides:     fxrates_app.ecb.parse_history
depends:      cli-002-init
instructions: |
  Implement `fxrates_app.ecb.parse_history(text)` returning a list of (date, currency, rate_text)
  for non-N/A values, raising `RejectedFile` otherwise. Rules: header first field `Date`, other
  fields three-letter uppercase codes, the empty trailing field from the trailing comma ignored;
  every row has the header's field count; dates are real calendar YYYY-MM-DD and unique within the
  file; values are `N/A` or match [0-9]+(\.[0-9]+)? and are nonzero. The entire file is checked
  before returning. Rates keep their published text.
acceptance:   yes

## story load-002-store
summary:      `fxrates load <csv>` stores published rates as text, replacing existing rows, and reports dates,rates counts.
type:         service
kind:         capability
phase:        1
implements:   FEATURE-LoadStore.md
covers:       LOAD-002
accepts:      st-003
stack:        common.md, python.md, cli.md
provides:     fxrates load
consumes:     fxrates_app.ecb.parse_history, rates repository operations, fxrates_app.config.database_path, cli.main
depends:      load-001-validate, cli-002-init, database
instructions: |
  Register the load handler. Read the file, parse and validate fully, then upsert each rate in one
  transaction so a reader sees all or none of the load. A rejected file exits 3, prints nothing to
  stdout, writes one stderr line, and stores nothing. On success print `dates,rates` then
  `<dates>,<rates>` where dates counts dates with at least one stored rate in the file and rates the
  rates stored. A file of only N/A prints 0,0 and stores nothing. Reloading leaves data unchanged.
acceptance:   yes

## story convert-001-convert
summary:      GET /convert computes exact, half-even rounded conversions.
type:         service
kind:         capability
phase:        3

consumes:     fxrates_app.rates.effective_date, rates repository operations
depends:      rates-004-rates-by-date
instructions: |
  Parameters from, to, amount [0-9]+(\.[0-9]+)?, optional date; without date use the latest
  publication. EUR has rate 1. rate = rate(to)/rate(from) rounded half-even to six decimals;
  result = amount*rate(to)/rate(from) computed exactly from stored rates, rounded half-even to two

  echoed as given. Same from and to gives rate 1.000000. Amount 0 gives 0.00.
