# ARCHITECTURE: FxRates

| Field | Value |
|-------|-------|
| Version | 20261024 V1 |
| Description | Defines the application modules and boundaries for the FxRates service. |
| Provides | application module boundaries |

## Questions

- None.

## Technology Stack

- Python 3.11 or newer provides the application language and runtime.
- FastAPI provides the JSON API, served by uvicorn.
- SQLite stores rates through the generated persistence package.
- The root `fxrates` executable exposes the command line.
- pytest and FastAPI TestClient support automated tests.

## Modules

| Module | Responsibility |
|--------|----------------|
| `cli` | Dispatches `init`, `load`, `fetch`, and `serve` commands. |
| `app_server` | Creates the FastAPI application and serves API routes. |
| `persistence` | Provides generated database operations from `DATABASE.md`. |
| `services` | Implements loading, rate lookup, conversion, and history behavior using `persistence`. |

## Module Ownership

| Boundary | Owner | Allowed access |
|----------|-------|----------------|
| Configuration | `config` | Reads `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. |
| Persistence | `persistence` | Only this generated package accesses the database driver and store. |
| File input | `services` | Reads a caller-supplied CSV or the extracted fetch file; does not read grader assets by application-specific paths. |
| External service | `services.fetch` | Downloads the ECB archive; tests replace the download with a stub. |
| HTTP | `app_server` | Calls service functions and returns JSON/status responses. |
| CLI | `cli` | Calls service functions and maps outcomes to stdout, stderr, and exit codes. |

Application modules must not import or open a database driver directly. Rates remain published text; arithmetic uses `decimal.Decimal`.

## Purpose

Provide the executable `./fxrates` at the application root and dispatch the four supported commands: `init`, `load`, `fetch`, and `serve`.

## Command Contract

- `init` takes no arguments, initializes the rates table, and returns exit code 0 on success.
- `load` takes one CSV path.
- `fetch` takes no arguments.
- `serve` accepts optional `--port <n>` and defaults to port 8000. It serves on `127.0.0.1` until stopped.
- Success output and command-specific behavior are defined by the implementing feature specifications.
- Usage errors return 2. A non-integer port is a usage error.
- A failing command writes no stdout and one diagnostic line to stderr.

# FEATURE: Load ECB History

| Field | Value |
|-------|-------|
| Version | 20261024 V1 |
| Description | Defines validation, atomic loading, and reporting for ECB CSV history files. |
| Depends On | FEATURE-CLI.md, DATABASE.md |
| Provides | fxrates load |
| Consumes | rates.upsert |

## Questions

- None.

## Purpose

`./fxrates load <csv>` validates the complete input before writing, then stores every non-`N/A` rate as the exact published text. A matching `(date, currency)` replaces the stored rate. Successful output is CSV with header `dates,rates` and counts for dates containing at least one stored rate and rates stored from this file.

## Validation and Failure Behavior

- The first header field is `Date`; remaining fields are three-letter uppercase currency codes. Ignore a trailing empty field.
- Every row has a real `YYYY-MM-DD` date, unique within the file, and the expected number of fields.
- Values are `N/A` or nonzero strings matching `[0-9]+(\.[0-9]+)?`.
- Any invalid row rejects the entire file with exit 3 and no database changes.
- An unreadable file is an operational failure with exit 1.
- Failures write no stdout and one diagnostic line to stderr.
