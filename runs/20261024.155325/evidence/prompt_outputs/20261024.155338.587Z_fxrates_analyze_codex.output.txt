## Story List

### Feature: ECB Data Operations

| ID | Story | High-level AC |
|---|---|---|
| DATA-001 | Initialize the rates database | `fxrates init` drops and recreates an empty rates table and prints nothing. |
| DATA-002 | Load an ECB history file | Valid files load atomically, preserving published rate text, skipping `N/A`, replacing matching records, and reporting date and rate counts. |
| DATA-003 | Fetch and load ECB history | `fxrates fetch` downloads and extracts the ECB history file, then loads it using the same validation and reporting behavior as `load`. |

### Feature: Rates JSON API

| ID | Story | High-level AC |
|---|---|---|
| API-001 | Report service health and stored-data statistics | `/health` reports `{"status":"ok"}`; `/stats` reports date and rate counts and publication bounds, using null bounds for an empty store. |
| API-002 | List available currencies | `/currencies` returns EUR as the base and stored currencies in ascending order. |
| API-003 | Retrieve rates by date | `/rates/{date}` resolves to the latest publication on or before the requested date, returns stored rates as strings, and returns 404 when no publication exists. |
| API-004 | Retrieve the latest rates | `/rates/latest` returns rates for the latest publication date and identifies the request as `latest`. |
| API-005 | Convert between currencies | `/convert` uses the latest publication by default or resolves a supplied date, computes with exact decimal arithmetic and half-even rounding, and returns the specified string values. |
| API-006 | Retrieve currency history | `/history/{code}` returns ascending points within optional inclusive bounds and exact count, extrema, and half-even rounded mean; an empty range returns null statistics and no points. |

## Planning Instructions

### Delivery Shape

Build a Python command-line executable and a FastAPI JSON service over persistent SQLite-backed rates. The command flow initializes storage, validates and loads a complete ECB history file, and optionally fetches and loads the published history. The service reads that shared store to report health, statistics, available currencies, effective-date rates, conversions, and currency history. The supplied harness exercises the executable, loads staged CSV fixtures, starts the service locally, and verifies the combined behavior.

### Test and Acceptance Strategy

Feature stories use focused pytest checks for their CLI or endpoint behavior. Tests use a real temporary database and stub the fetch download. The terminal verification story runs the complete supplied grader using `sh sources/run.sh`; its acceptance assertion declares `Suite: full`. Project-wide proof criteria are recorded in Sea Trials.

### Sequencing and Dependencies

The database initialization and persistence boundary precede loading and database-backed API behavior. CSV validation and atomic load behavior precede fetch’s reuse of the loader. The API stories depend on storage access and effective-date resolution where applicable. Focused tests accompany implementation; the full supplied grader is the terminal verification gate and depends on every implementation story. Stage the grader’s three CSV inputs at the expected paths.
