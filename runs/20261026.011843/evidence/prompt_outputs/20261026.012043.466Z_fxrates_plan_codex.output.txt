# ARCHITECTURE: FxRates

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Defines the application modules and boundaries for the FxRates CLI and API. |
| Provides    | application module boundaries |

## Questions

- None.

## Purpose

The application loads ECB euro reference rates into SQLite through the CLI and exposes them through a local JSON API. The `fxrates` executable is the application entry point; `fxrates serve` runs the API in the foreground.

## Modules and interfaces

| Module | Responsibility | Interface |
|--------|----------------|-----------|
| `config` | Resolve the database location. | `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. |
| `persistence` | Own database connections, schema access, and declared repository operations. | Generated package; callers use `open_database(dsn)` and `db.rates.<operation>(...)`. |
| `cli` | Parse commands and arguments, perform initialization and loading, and start the server. | `main(argv: list[str] | None = None) -> int`; root executable `fxrates`. |
| `services` | Coordinate rate loading and read queries through `persistence`. | Internal application services. |
| `app_server` | Build the FastAPI application and expose JSON endpoints. | `create_app() -> FastAPI`; `app_server.main:app`. |

## Ownership and boundaries

| Boundary | Owner | Allowed access |
|----------|-------|----------------|
| Configuration | `config` | Read the database environment variables and provide the resolved location. |
| Persistence | `persistence` | The only module that opens database connections or accesses the database driver. |
| File loading | `services` | Read the requested CSV or fetched archive and call declared repository operations. |
| External download | `services` | Download the ECB archive only for `fxrates fetch`; tests replace the download with a stub. |
| CLI | `cli` | Parse user commands, invoke services, and write specified output and diagnostics. |
| HTTP API | `app_server` | Validate requests, call services, and return JSON status and bodies. |

Application code must not open SQLite drivers directly. Persist rates as the ECB publishes them, using text values and decimal arithmetic for calculations. Resolve the database location from `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`.

## Runtime and failure boundaries

The API uses FastAPI with uvicorn and listens on `127.0.0.1`; it remains in the foreground until stopped and handles SIGTERM cleanly. The CLI returns the specified exit status for success, usage errors, rejected files, and operational failures. Diagnostics go to standard error. The health route responds independently of stored rates.

## Technology Stack

| Technology | Use |
|------------|-----|
| Python | Application modules and executable implementation, Python 3.11 or newer. |
| FastAPI | JSON API request handling. |
| SQLite | Persistent rate storage through the generated persistence package. |
| CLI | `fxrates` commands: `init`, `load`, `fetch`, and `serve`. |
| pytest | Automated project tests; fetch tests use a stub and no network. |
| ECB reference rates | Published history CSV inside the downloaded ECB ZIP archive. |
| Shell | POSIX `bin/test.sh` and supplied grader invocation. |

# FEATURE: Database Initialization

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Initializes the rates table through the `fxrates init` command. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | `fxrates init` |

## Questions

- None.

## Purpose

Allow operators and the supplied harness to initialize an empty rates table before loading history.

## Trigger and behavior

`fxrates init` drops the existing `rates` table if present and creates it empty. It writes nothing to standard output on success. A later initialization removes previously stored rates.

The command line provides usable help text. Unknown commands, incorrect argument counts, and a non-integer `serve --port` are usage errors with exit code 2.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: ECB History Loading

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Validates and atomically loads ECB history CSV files. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | `fxrates load` |

## Questions

- None.

## Purpose

Load ECB historical rates supplied as a CSV file while preserving their published text.

## Trigger and workflow

`fxrates load <csv>` reads the requested file, validates the entire file before the first database write, and then upserts every valid rate through the declared persistence operations. Loading a row for an existing date and currency replaces its rate. The input may include a trailing empty field, which is ignored. `N/A` values are skipped.

The header begins with `Date`; remaining fields are three-letter uppercase currency codes. Each row has one date and one value per currency. Dates must be real `YYYY-MM-DD` calendar dates and cannot repeat within the file. Rates must match `[0-9]+(\.[0-9]+)?` and must be nonzero. A wrong field count, invalid or repeated date, or invalid value rejects the whole file without storing anything.

On success, standard output is CSV with header `dates,rates`, followed by the count of dates having at least one stored rate and the number of rates stored from the file. A read failure exits 1; a rejected file exits 3; usage errors exit 2. A failing command writes nothing to standard output and one diagnostic line to standard error.

## Database Interface

- `FEATURE-RATE-001` — write: replace a stored rate - supplies: `date`, `currency`, `rate` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

# FEATURE: ECB History Fetch

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Downloads the ECB history archive and loads its CSV through the shared loader. |
| Depends On  | ARCHITECTURE.md, FEATURE-HistoryLoading.md |
| Provides    | `fxrates fetch` |
| Consumes    | `fxrates load` |

## Questions

- None.

## Purpose

Provide an operator command that downloads and loads the ECB euro reference-rate history archive.

## Trigger and workflow

`fxrates fetch` downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts `eurofxref-hist.csv`, and applies the same validation, persistence, and reporting behavior as `fxrates load`. Download failure is operational failure with exit code 1.

Tests must replace the download operation with a stub and must never use a network connection.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

=== AC fetch-stubbed ===
Intent: The fetch command loads a ZIP archive supplied by a stub without accessing the network.

from cli.testing import cli_runner
from unittest.mock import patch
from io import BytesIO
from zipfile import ZipFile
from persistence.testing import db_session

csv_data = b"Date,ZZZ,\n2097-01-02,1.25,\n"
archive = BytesIO()
with ZipFile(archive, "w") as bundle:
    bundle.writestr("eurofxref-hist.csv", csv_data)

with patch("services.fetch.download_archive", return_value=archive.getvalue()):
    code, stdout, stderr = cli_runner("fetch")
assert code == 0
with db_session() as db:
    rows = db.rates.by_date(date="2097-01-02")
    assert any(row.currency == "ZZZ" and row.rate == "1.25" for row in rows)
=== END AC fetch-stubbed ===

=== AC fetch-operational-error ===
Intent: A failed archive download returns the operational failure exit code.

from cli.testing import cli_runner
from unittest.mock import patch

with patch("services.fetch.download_archive", side_effect=OSError()):
    code, _, _ = cli_runner("fetch")
assert code == 1
=== END AC fetch-operational-error ===

## User Acceptance

- None.

## Guardrails

- Never connect to the network in automated tests; replace the download with a stub.
- Feed the extracted CSV through the shared history loader so validation and reporting remain consistent.
- Do not open SQLite directly; use the declared persistence library through application services.

# FEATURE: Service Overview

| Field       | Value |

| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /health, GET /stats, GET /currencies |

## Questions

- None.

## Purpose

Expose basic service health and a summary of the rates currently stored.

## Routes

| Method and path | Behavior |
|-----------------|----------|
| GET `/health` | Always returns status 200 and `{"status":"ok"}`. |
| GET `/stats` | Returns distinct publication-date count, stored-rate count, and earliest/latest publication dates. Empty date bounds are null. |
| GET `/currencies` | Returns base `EUR` and the ascending codes with at least one stored rate. |

## Database Interface

- `FEATURE-RATE-005` — read: list all stored rates - supplies: — - returns: `date`, `currency`, `rate`
