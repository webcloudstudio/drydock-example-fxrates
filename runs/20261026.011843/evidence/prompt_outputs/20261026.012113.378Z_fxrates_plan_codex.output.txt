# FEATURE: Effective Rates

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Resolves stored rates for a requested or latest ECB publication date. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-HistoryLoading.md |
| Provides    | GET /rates/{date}, GET /rates/latest |
| Consumes    | rates.effective_rates, rates.by_date |

## Questions

- None.

## Purpose

Return the rates for the latest publication date on or before a valid requested date. The latest endpoint resolves the most recent stored publication date.

## Behavior

- `GET /rates/{date}` accepts a real calendar date in `YYYY-MM-DD` form and returns `{"date": effective_date, "requested": requested_date, "base": "EUR", "rates": {currency: published_rate_text}}`.
- `GET /rates/latest` returns the same shape, with `"requested": "latest"`.
- Rates include every currency stored on the effective date, in a JSON object.
- Return 404 when no publication exists on or before the requested date, or when the database contains no rates.
- A malformed path date returns 422.
- Choose the effective date using `rates.effective_rates`; fetch that date's full set with `rates.by_date`.

## Database Interface

- `FEATURE-RATE-002` — read: find rates on or before a date - supplies: `as_of` - returns: `date`, `currency`, `rate`
- `FEATURE-RATE-003` — read: list rates for one date - supplies: `date` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

# FEATURE: Currency Conversion

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Converts amounts between currencies using effective ECB rates. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-HistoryLoading.md |
| Provides    | GET /convert |
| Consumes    | rates.effective_rates, rates.by_date |

## Questions

- None.

## Purpose

Convert an amount from one currency to another. EUR is the base currency with implicit rate one.

## Behavior

- Require `from`, `to`, and `amount`; optional `date` defaults to the latest publication date.
- Accept amount strings matching `[0-9]+(\.[0-9]+)?`; malformed or missing inputs return 422.
- Apply the effective publication date rule. Return 404 if no publication exists or a non-EUR currency has no rate for that date.
- Compute the conversion rate exactly as target rate divided by source rate. Round half to even to six decimal places and return exactly six decimals.
- Compute the result from the exact stored rates, not the rounded display rate. Round half to even to two decimal places and return exactly two decimals.
- Echo the amount as supplied. Return JSON fields `date`, `from`, `to`, `amount`, `rate`, and `result`.
- A missing currency rate is not inferred from another date.

## Database Interface

- `FEATURE-RATE-002` — read: find rates on or before a date - supplies: `as_of` - returns: `date`, `currency`, `rate`
- `FEATURE-RATE-003` — read: list rates for one date - supplies: `date` - returns: `date`, `currency`, `rate`

=== AC conversion-rounding ===
Intent: The conversion rate and result use exact source rates and half-even rounding at their specified precisions.

Requires: python-package=fastapi; scope=test
Requires: python-package=httpx; scope=test

from decimal import Decimal, ROUND_HALF_EVEN
from app_server.testing import web_client
from persistence.testing import db_session

date = "2099-03-02"
amount = "2.00"
source_rate = "2"
target_rate = "5"
expected_rate = (Decimal(target_rate) / Decimal(source_rate)).quantize(
    Decimal("0.000001"), rounding=ROUND_HALF_EVEN
)
expected_result = (Decimal(amount) * Decimal(target_rate) / Decimal(source_rate)).quantize(
    Decimal("0.01"), rounding=ROUND_HALF_EVEN
)

with db_session() as db:
    db.rates.upsert(date=date, currency="AAA", rate=source_rate)
    db.rates.upsert(date=date, currency="ZZZ", rate=target_rate)

response = web_client().get(
    "/convert",
    params={"from": "AAA", "to": "ZZZ", "amount": amount, "date": date},
)
assert response.status_code == 200
body = response.json()
assert body["rate"] == f"{expected_rate:.6f}"
assert body["result"] == f"{expected_result:.2f}"
=== END AC conversion-rounding ===

# FEATURE: Currency History

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Returns a currency’s stored rates and summary statistics over a date range. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-HistoryLoading.md |
| Provides    | GET /history/{code} |
| Consumes    | rates.history |

## Questions

- None.

## Purpose

Return the stored history for one currency across an inclusive optional date range, with summary statistics.

## Behavior

- `start` and `end` are optional valid calendar dates. Include points on either bound and return points in ascending date order.
- Each point includes the stored rate as published text.
- Report `count`, `min`, `max`, and `mean`. `min` and `max` are the stored text for the lowest and highest rates by numeric value.
- Compute mean exactly with decimal arithmetic, round half to even to six decimal places, and format with exactly six decimals.
- If there are no points, return count zero, null statistics, and an empty points array.
- Return 404 when the currency has no stored rate at all, including EUR. A valid currency and range with no points returns the empty-period response.
- Malformed date bounds return 422.

## Database Interface

- `FEATURE-RATE-004` — read: retrieve a currency's history in date bounds - supplies: `currency`, `start_date`, `end_date` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

=== AC history-route ===
Intent: The history route returns stored points in ascending date order for the requested currency and range.

Requires: python-package=fastapi; scope=test
Requires: python-package=httpx; scope=test

from app_server.testing import web_client
from persistence.testing import db_session

currency = "ZZZ"
first_date = "2099-04-01"
second_date = "2099-04-02"
rate = "1.5"

with db_session() as db:
    db.rates.upsert(date=second_date, currency=currency, rate=rate)
    db.rates.upsert(date=first_date, currency=currency, rate=rate)

    f"/history/{currency}",
    params={"start": first_date, "end": second_date},
)
assert response.status_code == 200
body = response.json()
assert [point["date"] for point in body["points"]] == [first_date, second_date]
assert [point["rate"] for point in body["points"]] == [rate, rate]
=== END AC history-route ===

=== AC history-summary-and-empty ===
Intent: History reports the count and extrema of stored points and represents a valid empty period with null statistics.

Requires: python-package=fastapi; scope=test
Requires: python-package=httpx; scope=test

from decimal import Decimal, ROUND_HALF_EVEN
from app_server.testing import web_client
from persistence.testing import db_session

currency = "ZZZ"
date = "2099-04-03"
rate = "1.5"
expected_mean = Decimal(rate).quantize(Decimal("0.000001"), rounding=ROUND_HALF_EVEN)

    db.rates.upsert(date=date, currency=currency, rate=rate)

assert empty_body["min"] is None

assert empty_body["mean"] is None

- None.

## Purpose

Provide one command that runs the application's pytest suite from the project root. It succeeds only when pytest reports the complete suite passes.
