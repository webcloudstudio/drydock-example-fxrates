<requirement name="application-stack" stories="architecture">
Implement in Python 3.11 or newer with FastAPI, served by uvicorn, over SQLite.
</requirement>
<requirement name="fxrates-executable" stories="architecture">
The product is an executable named `fxrates` at the application root.
</requirement>
<requirement name="run-supplied-grader" stories="qa-002">
`sources/run.sh` is the scoring entry point. It is supplied, not authored, and is staged verbatim into the application root with the data files.
</requirement>
<requirement name="score-cli-and-http-behavior" stories="qa-002">
`drydock uat` runs `sh sources/run.sh` from the completed application root and takes its exit code and output as the score.
</requirement>
<requirement name="initialize-rates-table" stories="data-001,database">
| `fxrates init` | Drops the `rates` table if present and creates it empty. | Nothing. |
</requirement>
<requirement name="declare-rates-table" stories="database">
| `rates` | `date` text `YYYY-MM-DD`, `currency` text, `rate` text | unique (`date`, `currency`) |
</requirement>
<requirement name="select-database-path" stories="database">
`DATABASE_URL` names the SQLite database file, optionally prefixed `sqlite://`. When it is unset, `DATABASE_PATH` is used, then `data/app.db`.
</requirement>
<requirement name="use-shipped-persistence-layers" stories="database">
All database access goes through the shipped persistence library and the relational layer generated from `DATABASE.md`. Application code never opens a database driver directly.
</requirement>
<requirement name="load-ecb-history-csv" stories="data-002">
| `fxrates load <csv>` | Loads an ECB history file (rules below). | `dates,rates`, then the number of dates and of rates stored from the file. |
</requirement>
<requirement name="validate-ecb-csv-header" stories="data-002">
The header's first field is `Date`, and every other field is a three-letter uppercase currency code.
</requirement>
<requirement name="ignore-trailing-empty-field" stories="data-002">
The ECB writes a trailing comma on every line, and the resulting empty last field is ignored.
</requirement>
<requirement name="validate-history-rows" stories="data-002">
Each row is a date (`YYYY-MM-DD`, a real calendar date, not repeated within the file) followed by one value per currency.
</requirement>
<requirement name="skip-unavailable-rates" stories="data-002">
The value `N/A` means no rate, and nothing is stored for it.
</requirement>
<requirement name="validate-nonzero-rate-values" stories="data-002">
Any other value must match `[0-9]+(\.[0-9]+)?` and be nonzero.
</requirement>
<requirement name="reject-invalid-file-atomically" stories="data-002">
**A rejected file changes nothing.** The whole file is checked before the first write. A row with the wrong field count, an invalid or repeated date, or an invalid value rejects the file.
</requirement>
<requirement name="replace-existing-rates" stories="data-002">
A rate for a (`date`, `currency`) that is already stored replaces it, so loading the same file twice leaves the database unchanged.
</requirement>
<requirement name="report-loaded-date-and-rate-counts" stories="data-002">
The reported `dates` counts the dates with at least one stored rate, and `rates` counts the rates stored.
</requirement>
<requirement name="report-cli-failures" stories="data-002,data-003">
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="fetch-ecb-history" stories="data-003">
| `fxrates fetch` | Downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts `eurofxref-hist.csv`, and loads it as `load`. | As `load`. |
</requirement>
<requirement name="serve-http-api" stories="api-001,api-002,api-003,api-004">
| `fxrates serve [--port <n>]` | Serves the HTTP API on `127.0.0.1:<n>` with uvicorn until stopped. Default port `8000`. | Nothing required. |
</requirement>
<requirement name="handle-cli-exit-codes" stories="data-001,data-002,data-003">
**Exit codes.** `0` success. `1` operational failure: the file cannot be read, or a `fetch` download fails. `2` usage error: unknown command, wrong argument count, `--port` not an integer. `3` rejected file.
</requirement>
<requirement name="store-published-rates-exactly" stories="database,data-002">
A rate is stored exactly as the ECB publishes it, as text. `0.943` stays `0.943`, never `0.9430` and never a float.
</requirement>
<requirement name="calculate-with-decimal-arithmetic" stories="api-003,api-004">
Arithmetic on rates uses Python's `decimal` module.
</requirement>
<requirement name="resolve-effective-publication-date" stories="api-002,api-003">
A request for date D uses the latest publication date on or before D. If none exists, the response is `404`.
</requirement>
<requirement name="serve-health-status" stories="api-001">
| `GET /health` | `{"status": "ok"}` |
</requirement>
<requirement name="serve-database-statistics" stories="api-001">
| `GET /stats` | `{"dates": <n>, "rates": <n>, "first": <date>, "last": <date>}`. `first` and `last` are `null` when the table is empty. |
</requirement>
<requirement name="list-stored-currencies" stories="api-001">
| `GET /currencies` | `{"base": "EUR", "currencies": [<code>, ...]}`: every currency with at least one stored rate, ascending. |
</requirement>
<requirement name="serve-effective-date-rates" stories="api-002">
| `GET /rates/{date}` | `{"date": <effective date>, "requested": <date>, "base": "EUR", "rates": {<code>: <rate>, ...}}`: every currency with a rate on the effective date. |
</requirement>
<requirement name="serve-latest-rates" stories="api-002">
| `GET /rates/latest` | As `/rates/{date}` for the latest publication date, with `"requested": "latest"`. |
</requirement>
<requirement name="convert-currency-amount" stories="api-003,api-002">
| `GET /convert?from=<code>&to=<code>&amount=<amount>[&date=<date>]` | `{"date": <effective date>, "from": <code>, "to": <code>, "amount": <amount>, "rate": <rate>, "result": <result>}`. Without `date`, the latest publication date is used. |
</requirement>
<requirement name="report-currency-history" stories="api-004">
| `GET /history/{code}[?start=<date>][&end=<date>]` | `{"currency": <code>, "base": "EUR", "count": <n>, "min": <rate>, "max": <rate>, "mean": <mean>, "points": [{"date": <date>, "rate": <rate>}, ...]}` for the publication dates from `start` through `end` inclusive, ascending. Both bounds are optional. With no points, `count` is `0`, `min`, `max`, and `mean` are `null`, and `points` is `[]`. |
</requirement>
<requirement name="preserve-stored-rate-text-in-api" stories="api-002,api-004">
`<rate>` in `/rates`, `min`, `max`, and `points` is the stored text, as a JSON string.
</requirement>
<requirement name="validate-and-echo-conversion-amount" stories="api-003">
`/convert` `amount` matches `[0-9]+(\.[0-9]+)?` and is echoed as given, as a JSON string.
</requirement>
<requirement name="round-conversion-rate" stories="api-003">
`/convert` `rate` is `rate(to) / rate(from)`, computed exactly and rounded half to even to six decimal places, written with exactly six decimals, as a JSON string: `"161.770000"`.
</requirement>
<requirement name="round-conversion-result" stories="api-003">
`/convert` `result` is `amount × rate(to) / rate(from)`, computed exactly from the stored rates (not from the rounded `rate`) and rounded half to even to two decimal places, written with exactly two decimals, as a JSON string: `"82.01"`.
</requirement>
<requirement name="summarize-history-rates" stories="api-004">
`/history` `min` and `max` are the stored text of the smallest and largest rate by value. `mean` is the exact mean rounded half to even to six decimal places, written with exactly six decimals, as a JSON string.
</requirement>
<requirement name="return-not-found-for-unavailable-data" stories="api-002,api-003,api-004">
`404` | No publication on or before the requested date; a `/convert` currency other than EUR with no rate on the effective date; a `/history` currency with no stored rate at all (including `EUR`). |
</requirement>
<requirement name="validate-request-parameters" stories="api-002,api-003,api-004">
`422` | A malformed date in the path or query, a malformed `amount`, or a missing required query parameter. FastAPI's request validation produces this status. |
</requirement>
<requirement name="reflect-loads-while-serving" stories="api-001,api-002,api-003,api-004">
A load that completes while the server is running is visible to the next request.
</requirement>
<requirement name="provide-test-runner" stories="qa-001">
The completed application provides a POSIX-compatible `bin/test.sh` that runs its own pytest suite from the application root and exits zero only when every test passes.
</requirement>
<requirement name="cover-commands-loading-api-and-fetch-tests" stories="qa-001">
The suite covers each command, each load rule, each endpoint, the effective-date rule, rounding, and each error status, against a real temporary database, with `fetch` stubbed.
</requirement>
