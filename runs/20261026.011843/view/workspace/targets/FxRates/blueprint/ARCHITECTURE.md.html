ARCHITECTURE: FxRates

FieldValue
Version20261026 V1
DescriptionDefines the application modules and boundaries for the FxRates CLI and API.
Providesapplication module boundaries

Purpose

The application loads ECB euro reference rates into SQLite through the CLI and exposes them through a local JSON API. The fxrates executable is the application entry point; fxrates serve runs the API in the foreground.

Modules and interfaces

ModuleResponsibilityInterface
configResolve the database location.DATABASE_URL, then DATABASE_PATH, then data/app.db.
persistenceOwn database connections, schema access, and declared repository operations.Generated package; callers use open_database(dsn) and db.rates.<operation>(...).
cliParse commands and arguments, perform initialization and loading, and start the server.`main(argv: list[str]None = None) -> int; root executablefxrates`.
servicesCoordinate rate loading and read queries through persistence.Internal application services.
app_serverBuild the FastAPI application and expose JSON endpoints.create_app() -> FastAPI; app_server.main:app.

Ownership and boundaries

BoundaryOwnerAllowed access
ConfigurationconfigRead the database environment variables and provide the resolved location.
PersistencepersistenceThe only module that opens database connections or accesses the database driver.
File loadingservicesRead the requested CSV or fetched archive and call declared repository operations.
External downloadservicesDownload the ECB archive only for fxrates fetch; tests replace the download with a stub.
CLIcliParse user commands, invoke services, and write specified output and diagnostics.
HTTP APIapp_serverValidate requests, call services, and return JSON status and bodies.

Application code must not open SQLite drivers directly. Persist rates as the ECB publishes them, using text values and decimal arithmetic for calculations. Resolve the database location from DATABASE_URL, then DATABASE_PATH, then data/app.db.

Runtime and failure boundaries

The API uses FastAPI with uvicorn and listens on 127.0.0.1; it remains in the foreground until stopped and handles SIGTERM cleanly. The CLI returns the specified exit status for success, usage errors, rejected files, and operational failures. Diagnostics go to standard error. The health route responds independently of stored rates.

Programmatic Acceptance

User Acceptance

  • None.

Guardrails

  • Database access goes only through the shipped persistence library.
  • Do not read sources/run.sh or supplied data files from application code.
  • Do not hardcode rates, dates, counts, or computed values in application code.
  • Store published rates as text and use decimal for arithmetic.
  • The fxrates executable is located at the application root and serves on 127.0.0.1.
