# ARCHITECTURE: FxRates

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Defines the application modules, runtime configuration, and service boundaries for FxRates. |
| Provides    | application module boundaries |

## Questions

- None.

## Purpose

FxRates loads ECB euro reference rates into the configured SQLite store and serves them through a JSON API. The root `fxrates` executable provides `init`, `load`, `fetch`, and `serve`.

## Module Boundaries

| Module | Owns | Allowed low-level access |
|--------|------|-------------------------|
| `cli` | Argument parsing and command dispatch | Calls application services and the ASGI application; does not access a database driver. |
| Rate loading service | CSV validation and atomic load workflow | Calls declared `persistence` operations. |
| Fetch service | ECB archive download and CSV extraction | Passes extracted CSV content to the rate loading service. |
| API application | FastAPI routes and request handling | Calls rate and conversion/history services. |
| Rate services | Effective-date lookup, conversion, and history calculations | Call declared `persistence` operations; use `decimal.Decimal` for arithmetic. |
| `persistence` | Database connections and declared rate operations | Sole owner of database driver access. |

## Runtime Configuration

Resolve the database location in this order: `DATABASE_URL`, `DATABASE_PATH`, then `data/app.db`. Store published rates as text. Do not use floating-point arithmetic for rates.

## Technology Stack

- Python 3.11 or newer implements the CLI, application services, API, and tests.
- FastAPI defines the JSON API; uvicorn serves it on `127.0.0.1`.
- SQLite is accessed through the generated persistence package.
- pytest runs the project test suite, with FastAPI `TestClient` for API tests.
- The `fxrates` CLI is the application entry point, and POSIX shell is used by test and conformance runners.
- Python `decimal` provides exact rate arithmetic.

## Guardrails

# FEATURE: CLI Initialize

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Specifies the command that recreates an empty rates table. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | fxrates init |
| Consumes    | rates persistence operations |

## Questions

- None.

## Purpose

`fxrates init` initializes the configured rates store by dropping the existing rates table, if present, and creating it empty.

## Workflow

1. Resolve the configured store using the project database configuration.
2. Recreate the rates table through the persistence boundary.
3. On success, exit with status `0` and write nothing to standard output.

Usage errors return `2`; operational failures return `1`. A failing command writes no standard output and one diagnostic line to standard error.

# FEATURE: CLI Load

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Specifies validation and atomic loading of ECB history CSV files. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | fxrates load |
| Consumes    | rates persistence operations |

## Questions

- None.

## Purpose

`fxrates load <csv>` validates the complete file before writing, then inserts or replaces all eligible rates.

## CSV Rules

- The first header field is `Date`; remaining fields are three-letter uppercase currency codes. Ignore the trailing empty field produced by the ECB trailing comma.
- Each data row contains one valid real date in `YYYY-MM-DD` form and one value per header currency. Dates cannot repeat within the file.
- `N/A` means no rate and creates no stored row. Every other value must match `[0-9]+(\.[0-9]+)?` and be nonzero.
- A wrong field count, invalid or repeated date, or invalid rate rejects the entire file before any write.
- Loading an existing `(date, currency)` replaces that rate. Repeating a successful load leaves the store unchanged.

On success, stdout is CSV with header `dates,rates` and the number of dates with at least one stored rate plus the number of rates stored from that file. A read failure exits `1`; a rejected file exits `3`. Failures write nothing to stdout and one diagnostic line to stderr.

## Programmatic Acceptance

=== AC load-valid-file ===
Intent: A valid staged ECB file loads successfully and reports its parsed counts.

import csv
import subprocess
import sys
from pathlib import Path

fixture = Path("sources/eurofxref-hist_2025-01.csv")
with fixture.open(newline="") as source:
    rows = list(csv.reader(source))
dates = {row[0] for row in rows[1:] if row[0]}
rate_count = sum(
    1 for row in rows[1:] if row[0]
    for value in row[1:] if value and value != "N/A"
)
result = subprocess.run(
    ["./fxrates", "load", str(fixture)],
    capture_output=True, text=True,
)
print(result.stdout)
print(result.stderr, file=sys.stderr)
assert result.returncode == 0
assert dates
assert rate_count
=== END AC load-valid-file ===

=== AC load-rejected-file-is-atomic ===
Intent: A rejected staged file returns the declared rejection status without changing stored rates.

import subprocess
import sys
from pathlib import Path
from persistence.testing import db_session

fixture = Path("sources/eurofxref-hist_bad.csv")
with db_session() as db:
    before = db.rates.list_all()
result = subprocess.run(
    ["./fxrates", "load", str(fixture)],
    capture_output=True, text=True,
)
print(result.stdout)
print(result.stderr, file=sys.stderr)
assert result.returncode == 3
with db_session() as db:
    after = db.rates.list_all()
assert len(after) == len(before)
=== END ARTIFACT ===

## User Acceptance

- None.

## Guardrails

- Validate the entire file before the first write.
- Preserve published rate strings exactly and omit `N/A` values.
- Never open the database driver directly from application code.

| Depends On  | ARCHITECTURE.md, FEATURE-CLI-Load.md |

## Questions

- None.

## Purpose

`fxrates fetch` downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts `eurofxref-hist.csv`, and applies the same full-file validation, atomicity, replacement, and count reporting as `fxrates load`.

A failed download is an operational failure: exit `1`, no stdout, and one diagnostic line on stderr.

- None.

## Guardrails

- Automated fetch tests must stub the download and must not use the network.

# FEATURE: CLI Serve

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Specifies starting the HTTP API from the command line. |
| Depends On  | ARCHITECTURE.md |
| Provides    | fxrates serve |
| Consumes    | application ASGI app |

## Questions

- None.

## Purpose

`fxrates serve [--port <n>]` serves the API on `127.0.0.1`, using port `8000` by default, and runs in the foreground until stopped. It stops cleanly on SIGTERM.

A non-integer port is a usage error with exit status `2`. Successful startup requires no standard output.

## Programmatic Acceptance

=== AC serve-application-client ===

=== END AC serve-application-client ===

## User Acceptance

- None.

## Guardrails

- Bind the server to `127.0.0.1`.
- Keep the server in the foreground and stop cleanly on SIGTERM.
