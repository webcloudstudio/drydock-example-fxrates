<requirement name="python-fastapi-sqlite-stack" stories="architecture,database">
Implement in Python 3.11 or newer with FastAPI, served by uvicorn, over SQLite.
</requirement>
<requirement name="pytest-api-testclient" stories="project_tests">
Tests run under pytest, using FastAPI's `TestClient` for the API.
</requirement>
<requirement name="fxrates-executable" stories="architecture,cli_initialize,cli_load,cli_fetch,cli_serve">
The product is an executable named `fxrates` at the application root.
</requirement>
<requirement name="load-ecb-history" stories="cli_load">
A command-line tool loads the ECB's published history file into a local database.
</requirement>
<requirement name="serve-json-api" stories="cli_serve,api_rates,api_statistics,conversion,history,api_health">
A JSON HTTP API serves the answers.
</requirement>
<requirement name="scoring-harness" stories="verification">
`sources/run.sh` is the scoring entry point. It is supplied, not authored, and is staged verbatim into the application root with the data files. `drydock uat` runs `sh sources/run.sh` from the completed application root and takes its exit code and output as the score.
</requirement>
<requirement name="database-location" stories="architecture,database">
`DATABASE_URL` names the SQLite database file, optionally prefixed `sqlite://`. When it is unset, `DATABASE_PATH` is used, then `data/app.db`.
</requirement>
<requirement name="centralized-database-access" stories="architecture,database">
All database access goes through the shipped persistence library and the relational layer generated from `DATABASE.md`. Application code never opens a database driver directly.
</requirement>
<requirement name="rates-schema-and-precision" stories="database">
One table:

| Table | Columns | Keys |
|---|---|---|
| `rates` | `date` text `YYYY-MM-DD`, `currency` text, `rate` text | unique (`date`, `currency`) |

A rate is stored exactly as the ECB publishes it, as text. `0.943` stays `0.943`, never `0.9430` and never a float. Arithmetic on rates uses Python's `decimal` module.
</requirement>
<requirement name="initialize-rates-table" stories="cli_initialize">
`fxrates init` | Drops the `rates` table if present and creates it empty. | Nothing.
</requirement>
<requirement name="load-history-command" stories="cli_load">
`fxrates load <csv>` | Loads an ECB history file (rules below). | `dates,rates`, then the number of dates and of rates stored from the file.
</requirement>
<requirement name="fetch-history-command" stories="cli_fetch">
`fxrates fetch` | Downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts `eurofxref-hist.csv`, and loads it as `load` does. | As `load`.
</requirement>
<requirement name="serve-command" stories="cli_serve">
`fxrates serve [--port <n>]` | Serves the HTTP API on `127.0.0.1:<n>` with uvicorn until stopped. Default port `8000`. | Nothing required.
</requirement>
<requirement name="validate-ecb-csv-format" stories="cli_load">
1. The file is CSV. The header's first field is `Date`, and every other field is a three-letter uppercase currency code. The ECB writes a trailing comma on every line, and the resulting empty last field is ignored.
</requirement>
<requirement name="validate-csv-rows-and-rates" stories="cli_load">
2. Each row is a date (`YYYY-MM-DD`, a real calendar date, not repeated within the file) followed by one value per currency. The value `N/A` means no rate, and nothing is stored for it. Any other value must match `[0-9]+(\.[0-9]+)?` and be nonzero.
</requirement>
<requirement name="reject-invalid-csv-atomically" stories="cli_load">
3. **A rejected file changes nothing.** The whole file is checked before the first write. A row with the wrong field count, an invalid or repeated date, or an invalid value rejects the file.
</requirement>
<requirement name="replace-existing-rates" stories="cli_load">
4. A rate for a (`date`, `currency`) that is already stored replaces it, so loading the same file twice leaves the database unchanged.
</requirement>
<requirement name="load-counts" stories="cli_load">
5. The reported `dates` counts the dates with at least one stored rate, and `rates` counts the rates stored.
</requirement>
<requirement name="command-error-output" stories="cli_initialize,cli_load,cli_fetch,cli_serve">
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="command-exit-codes" stories="cli_initialize,cli_load,cli_fetch,cli_serve">
**Exit codes.** `0` success. `1` operational failure: the file cannot be read, or a `fetch` download fails. `2` usage error: unknown command, wrong argument count, `--port` not an integer. `3` rejected file.
</requirement>
<requirement name="stubbed-fetch-network" stories="cli_fetch">
`fetch` is never run by the harness. Its tests replace the download with a stub and never use the network.
</requirement>
<requirement name="json-responses-and-eur-base" stories="api_rates,api_statistics,conversion,history,api_health">
Every response is JSON. EUR is the base. A rate is the number of units of a currency per euro, and EUR itself has the implicit rate `1`.
</requirement>
<requirement name="effective-publication-date" stories="api_rates,conversion">
**Effective date.** The ECB publishes on working days only. A request for date D uses the latest publication date on or before D. If none exists, the response is `404`.
</requirement>
<requirement name="health-endpoint" stories="api_health">
| `GET /health` | `{"status": "ok"}` |
</requirement>
<requirement name="statistics-endpoint" stories="api_statistics">
| `GET /stats` | `{"dates": <n>, "rates": <n>, "first": <date>, "last": <date>}`. `first` and `last` are `null` when the table is empty. |
</requirement>
<requirement name="currencies-endpoint" stories="api_statistics">
| `GET /currencies` | `{"base": "EUR", "currencies": [<code>, ...]}`: every currency with at least one stored rate, ascending. |
</requirement>
<requirement name="rates-by-date-endpoint" stories="api_rates">
| `GET /rates/{date}` | `{"date": <effective date>, "requested": <date>, "base": "EUR", "rates": {<code>: <rate>, ...}}`: every currency with a rate on the effective date. |
</requirement>
<requirement name="latest-rates-endpoint" stories="api_rates">
| `GET /rates/latest` | As `/rates/{date}` for the latest publication date, with `"requested": "latest"`. |
</requirement>
<requirement name="currency-conversion-endpoint" stories="conversion">
| `GET /convert?from=<code>&to=<code>&amount=<amount>[&date=<date>]` | `{"date": <effective date>, "from": <code>, "to": <code>, "amount": <amount>, "rate": <rate>, "result": <result>}`. Without `date`, the latest publication date is used.
</requirement>
<requirement name="currency-history-endpoint" stories="history">
| `GET /history/{code}[?start=<date>][&end=<date>]` | `{"currency": <code>, "base": "EUR", "count": <n>, "min": <rate>, "max": <rate>, "mean": <mean>, "points": [{"date": <date>, "rate": <rate>}, ...]}` for the publication dates from `start` through `end` inclusive, ascending. Both bounds are optional. With no points, `count` is `0`, `min`, `max`, and `mean` are `null`, and `points` is `[]`.
</requirement>
<requirement name="rate-string-values" stories="api_rates,history">
- `<rate>` in `/rates`, `min`, `max`, and `points` is the stored text, as a JSON string.
</requirement>
<requirement name="conversion-amount-format" stories="conversion">
- `/convert` `amount` matches `[0-9]+(\.[0-9]+)?` and is echoed as given, as a JSON string.
</requirement>
<requirement name="conversion-rate-rounding" stories="conversion">
- `/convert` `rate` is `rate(to) / rate(from)`, computed exactly and rounded half to even to six decimal places, written with exactly six decimals, as a JSON string: `"161.770000"`.
</requirement>
<requirement name="conversion-result-rounding" stories="conversion">
- `/convert` `result` is `amount × rate(to) / rate(from)`, computed exactly from the stored rates (not from the rounded `rate`) and rounded half to even to two decimal places, written with exactly two decimals, as a JSON string: `"82.01"`.
</requirement>
<requirement name="history-summary-values" stories="history">
- `/history` `min` and `max` are the stored text of the smallest and largest rate by value.
</requirement>
<requirement name="history-mean-rounding" stories="history">
- `mean` is the exact mean rounded half to even to six decimal places, written with exactly six decimals, as a JSON string.
</requirement>
<requirement name="not-found-errors" stories="api_rates,conversion,history">
| `404` | No publication on or before the requested date; a `/convert` currency other than EUR with no rate on the effective date; a `/history` currency with no stored rate at all (including `EUR`). |
</requirement>
<requirement name="validation-errors" stories="api_rates,conversion,history">
| `422` | A malformed date in the path or query, a malformed `amount`, or a missing required query parameter. FastAPI's request validation produces this status.
</requirement>
<requirement name="live-load-visibility" stories="cli_load,api_rates,api_statistics,conversion,history">
A load that completes while the server is running is visible to the next request.
</requirement>
