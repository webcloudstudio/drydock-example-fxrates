# FEATURE: CLI Serve

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Starts the FxRates HTTP service from the command line. |
| Depends On  | ARCHITECTURE.md, FEATURE-API-Health.md |
| Provides    | `fxrates serve` |
| Consumes    | application ASGI app |

## Questions

- None.

## Purpose

Run the API on `127.0.0.1` in the foreground until stopped. `--port <n>` selects the port; when omitted, use port `8000`. Stop cleanly on SIGTERM.

## Workflow

1. Parse `serve` and its optional `--port` argument.
2. Run the application ASGI app with uvicorn bound to `127.0.0.1` and the selected port.
3. Keep the command in the foreground and exit cleanly after SIGTERM.

A non-integer port is a usage error with exit code `2`. The server writes no required standard output.

## Programmatic Acceptance

=== AC serve-health ===
Intent: The serve command starts the declared application and exposes its health route.

from app_server.main import create_app
from fastapi.testclient import TestClient

client = TestClient(create_app())
response = client.get("/health")
assert response.status_code == 200
=== END AC serve-health ===

=== AC serve-cli-usage ===
Intent: A non-integer port is rejected with the declared usage exit code.

from cli.testing import cli_runner

exit_code, stdout, stderr = cli_runner("serve", "--port", "notaport")
assert exit_code == 2
=== END AC serve-cli-usage ===

## User Acceptance

- None.

## Guardrails

- Bind only to `127.0.0.1`.
- Run in the foreground and stop cleanly on SIGTERM.
- Do not require standard output from the serving command.

# FEATURE: API Statistics

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Reports stored-rate statistics and currencies available in the store. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /stats, GET /currencies |
| Consumes    | rates persistence operations |

## Questions

- None.

## Purpose

Expose database-derived publication statistics and the set of currencies with at least one stored rate.

## Routes

### `GET /stats`

Return the number of distinct publication dates, total stored rates, and the earliest and latest stored dates. When no rates exist, the date bounds are `null`.

### `GET /currencies`

Return base currency EUR and all currencies with stored rates in ascending order.

## Data Access

Use the declared rates persistence operations. Derive counts, date bounds, and currency membership from stored records. Do not hardcode values.

## Programmatic Acceptance

=== AC stats-route ===
Intent: The statistics route is reachable and returns the declared response fields.

response = client.get("/stats")
assert response.status_code == 200
body = response.json()

assert isinstance(body["dates"], int)
assert isinstance(body["rates"], int)
=== END AC stats-route ===

# FEATURE: API Rates

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Retrieves stored rates for an effective publication date. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /rates/{date}, GET /rates/latest |
| Consumes    | rates persistence operations |

## Questions

- None.

## Purpose

Return every available currency rate for the latest ECB publication on or before the requested date. `GET /rates/latest` uses the latest publication overall.

## Routes

- `GET /rates/{date}` returns the effective date, the original requested date, base `EUR`, and all rates published on the effective date.
- `GET /rates/latest` returns the same shape, with `requested` set to `latest`.
- If there is no publication on or before the requested date, return `404`.
- A malformed calendar date returns `422`.

Rates are returned as their stored ECB text. EUR is the implicit base and is not a stored rate.

## Data Access

Resolve the effective publication date using the latest-on-or-before access pattern, then retrieve all rates for that date. Do not hardcode dates or rates.

## Programmatic Acceptance

=== AC rates-by-date-route ===
Intent: The date-based rates route is reachable and returns a success status for a valid request.

from app_server.testing import web_client

client = web_client()
response = client.get("/rates/2098-12-30")
assert response.status_code in (200, 404)
=== END AC rates-by-date-route ===

=== AC rates-latest-route ===
Intent: The latest rates route is reachable and responds with a declared HTTP status.

from app_server.testing import web_client

client = web_client()
response = client.get("/rates/latest")
assert response.status_code in (200, 404)
=== END AC rates-latest-route ===

## User Acceptance

- None.

## Guardrails

- Resolve rates from persisted data and preserve rate text.
- Use the most recent publication on or before the requested date.

# FEATURE: Conversion

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Converts an amount between currencies using ECB euro reference rates. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /convert |
| Consumes    | rates persistence operations |

## Questions

- None.

## Purpose

Convert between any two currencies using EUR as the base and the effective publication date. Without a date, use the latest publication.

## Request

Required query parameters are `from`, `to`, and `amount`; optional `date` is a calendar date. Amount must match `[0-9]+(\.[0-9]+)?`. Malformed amounts, malformed dates, and missing required parameters return `422`. A currency other than EUR without a rate on the effective date returns `404`; no effective publication date also returns `404`.

## Calculation and Response

Return the effective date, requested currency codes, amount echoed as supplied, conversion rate, and result as JSON strings. Compute `rate(to) / rate(from)` and `amount × rate(to) / rate(from)` exactly with `Decimal`, rounding half to even. Format rate to six decimal places and result to two decimal places. Compute result from unrounded stored rates, not the rounded response rate. EUR has implicit rate `1`.

## Programmatic Acceptance

=== AC conversion-route ===
Intent: A conversion request using an amount supplied by the criterion returns a structured success response.

from app_server.testing import web_client

client = web_client()
amount = "12.50"
response = client.get("/convert", params={"from": "EUR", "to": "EUR", "amount": amount})
assert response.status_code in (200, 404)
if response.status_code == 200:
    body = response.json()
    assert body["amount"] == amount
    assert {"date", "from", "to", "rate", "result"} <= body.keys()
=== END AC conversion-route ===

=== AC conversion-validation ===
Intent: A malformed amount and a missing required parameter each return unprocessable entity.

from app_server.testing import web_client

client = web_client()
malformed = client.get("/convert", params={"from": "EUR", "to": "EUR", "amount": "nope"})
missing = client.get("/convert", params={"from": "EUR", "to": "EUR"})
assert malformed.status_code == 422
assert missing.status_code == 422
=== END AC conversion-validation ===

## User Acceptance

- None.

## Guardrails

- Use Decimal arithmetic only; do not use floating point.
- Preserve the supplied amount string in the response.
- Return errors using the specified HTTP statuses; error body wording is not part of the contract.
