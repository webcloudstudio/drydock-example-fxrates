# ARCHITECTURE: FxRates

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |

## Questions

- None.

## System Overview

The application is a Python 3.11 or newer service with a root-level `fxrates` executable. The CLI initializes and loads ECB rates; FastAPI serves JSON responses through uvicorn on `127.0.0.1`. SQLite persistence is accessed only through the generated `persistence` package.

## Technology Stack

| Technology | Application |
|---|---|
| Python | CLI, services, API, and tests; Python 3.11 or newer. |
| FastAPI | JSON API application factory and routes. |
| SQLite | Local rates store, accessed through the shipped persistence library. |
| CLI | Root executable `fxrates` with `init`, `load`, `fetch`, and `serve` commands. |
| pytest | Application test suite, run by `bin/test.sh`; FastAPI TestClient exercises routes. |
| ECB reference rates | CSV history from `eurofxref-hist.csv`, optionally extracted from the ECB ZIP archive. |
| Shell | POSIX `sh` test runner and supplied grader. |

## Modules and Boundaries

| Module | Ownership | Allowed low-level access |
|---|---|---|
| `cli` | Parses commands and dispatches to application services. | Calls services and the application server; no database driver access. |
| `app_server` | FastAPI factory, HTTP routes, request validation, and JSON responses. | Calls application services; no database driver access. |
| `services` | Rate loading, fetching, date resolution, conversion, and history calculations. | Calls `persistence.open_database` and declared repository operations only. |
| `persistence` | Generated persistence boundary for rates. | Shipped library owns SQLite connections and database operations. |
| `tests` | pytest coverage and stubbed fetch integration. | Uses public CLI/API interfaces and configured test database. |

The application reads the store location from `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. Rates remain published text; arithmetic uses `decimal.Decimal`, never floating point. The loader validates each entire file before its first write.

## Application Interfaces

- `app_server.main.create_app() -> FastAPI` constructs the API application; the module exposes `app` for uvicorn.
- `app_server.testing.web_client()` returns a FastAPI `TestClient` for in-process acceptance and tests.
- `cli.main(argv: list[str] | None = None) -> int` is the CLI entry point.
- `cli.testing.cli_runner(*args: str) -> tuple[int, str, str]` invokes the CLI in process and returns exit code, stdout, and stderr.
- The executable is `./fxrates`; `serve` runs in the foreground and exits cleanly on SIGTERM.

## Route Ownership

- Health, store statistics, and currencies: `FEATURE-HealthAndSummary.md`.
- Effective-date rates: `FEATURE-EffectiveRates.md`.
- Conversions: `FEATURE-Conversion.md`.
- Currency history: `FEATURE-CurrencyHistory.md`.

# FEATURE: Test Runner

|-------------|-------|
| Version     | 20261024 V1 |

| Provides    | bin/test.sh |

## Questions

- None.

## Purpose

The project test runner executes the pytest suite from the application root using the selected Python environment and returns zero only when the suite succeeds. Fetch coverage replaces the downloader with a stub, so tests open no network connection.

## Workflow

Run `sh bin/test.sh` from the application root. The script activates `.venv` when present and invokes the configured project test command. Test modules use a real temporary SQLite database configured for the application and FastAPI `TestClient` for route checks. Fetch tests stub the download boundary and assert behavior without connecting to the ECB or any other network service.

The suite covers each CLI command, each loader rule, each API endpoint, effective-date selection, decimal rounding, and error statuses. It is cumulative and runs after the implementation capabilities are available.

# FEATURE: Database Initialization

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Initializes an empty rates store through the CLI. |
| Depends On  | DATABASE.md, ARCHITECTURE.md |
| Provides    | fxrates init |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

`fxrates init` clears existing rate rows through the declared repository interface, leaving the generated rates table empty and ready for loading. It emits no standard output. Application code does not issue DDL or drop the generated table.

## Workflow

The command resolves the configured database using `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. It reads existing rates through `rates.list` and deletes each row through `rates.delete`. Successful initialization returns exit code 0. No output is written to standard output. This is idempotent: running it again on an empty store leaves the store empty.

## Database Interface

- `FEATURE-RATE-003` — write: delete a rate - supplies: `date`, `currency` - returns: `date`, `currency`

## Programmatic Acceptance

# FEATURE: ECB Rate Loader

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Validates and transactionally loads ECB CSV history files. |
| Depends On  | DATABASE.md, ARCHITECTURE.md, FEATURE-DatabaseInit.md |
| Provides    | fxrates load |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Load an ECB history CSV into the configured store while preserving each published rate's text. The entire file is parsed and validated before any repository write. Rates for the same date and currency are replaced on reload; `N/A` cells create no row.

## Workflow

`fxrates load <csv>` accepts a CSV whose first header field is `Date`, whose currency fields are three-letter uppercase codes, and whose optional final empty field is ignored. Each row must contain a real, unique `YYYY-MM-DD` date and one value per currency. Values are either `N/A` or nonzero decimal strings matching `[0-9]+(\.[0-9]+)?`.

A valid load writes each non-`N/A` value using `rates.upsert`, then reports a CSV header `dates,rates` followed by counts of dates with at least one stored rate and rates stored from the file. Rejected content returns exit code 3 and makes no writes. An unreadable file returns 1. Diagnostics use stderr; failing commands leave stdout empty.

## Database Interface

- `FEATURE-RATE-002` — write: replace a rate - supplies: `date`, `currency`, `rate` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

# FEATURE: ECB Rate Fetch

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Downloads and loads the ECB's zipped history file. |
| Depends On  | FEATURE-RateLoader.md, ARCHITECTURE.md |
| Provides    | fxrates fetch |
| Consumes    | fxrates load |

## Questions

- None.

## Purpose

Fetch the ECB history ZIP, extract `eurofxref-hist.csv`, and load it through the same validation and persistence behavior as the load command.

## Workflow

`fxrates fetch` downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts the named CSV from the ZIP, and applies the loader. A download failure returns exit code 1 with no standard output. The downloader is isolated behind a replaceable function so tests can provide ZIP bytes from memory and verify extraction and load behavior without network access.

## Programmatic Acceptance

Intent: The fetch command is exposed and reports an operational failure when its download stub raises an error.

=== AC fetch-stubbed-load ===
Intent: A stubbed archive containing a valid CSV completes fetch and persists rates through the loader.

import io
import zipfile
from unittest.mock import patch
from cli.testing import cli_runner
from persistence.testing import db_session

csv_bytes = b"Date,USD,\n2099-05-06,0.943,\n"
archive_stream = io.BytesIO()
with zipfile.ZipFile(archive_stream, "w") as archive:
    archive.writestr("eurofxref-hist.csv", csv_bytes)
archive_bytes = archive_stream.getvalue()

with patch("services.fetcher.download_archive", return_value=archive_bytes):
    code, stdout, stderr = cli_runner("fetch")

assert code == 0
with db_session() as db:
    rows = db.rates.list(date="2099-05-06", currency="USD")
assert len(rows) == 1
assert rows[0].rate == "0.943"
