# FEATURE: Health and Dataset Summary

| Field | Value |
|-------|-------|
| Version | 20261024 V1 |
| Description | Serves health, rate dataset statistics, and available currencies. |
| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | GET /health, GET /stats, GET /currencies |
| Consumes | rates repository operations |

## Questions

- None.

## Purpose

Expose service health and summaries derived from the stored rates.

## Routes

| Method | Path | Behavior |
|--------|------|----------|
| GET | `/health` | Returns `{"status":"ok"}`. |
| GET | `/stats` | Returns the number of publication dates with rates, total stored rates, and earliest and latest publication dates. Empty stores return zero counts and `null` dates. |
| GET | `/currencies` | Returns EUR as the base and the distinct currencies with stored rates in ascending order. |

## Database Interface

- `FEATURE-RATE-001` — read: list stored rates - supplies: — - returns: `date`, `currency`, `rate`

The `rates.list` operation is used without filters to compute summaries from persisted records. A date counts only when it has at least one stored rate.

## Programmatic Acceptance

=== AC health-route ===
Intent: The health route is reachable and returns a successful response.

from app_server.testing import web_client

response = web_client().get("/health")
assert response.status_code == 200
=== END AC health-route ===

=== AC summary-routes ===
Intent: The statistics and currencies routes return JSON summaries derived from stored records.

from app_server.testing import web_client
from persistence.testing import db_session

rate_date = "2099-01-02"
currency = "ZZZ"
rate_text = "0.943"

with db_session() as db:
    db.rates.upsert(date=rate_date, currency=currency, rate=rate_text)
    stats = web_client().get("/stats")
    currencies = web_client().get("/currencies")

    assert stats.status_code == 200
    assert currencies.status_code == 200
    assert stats.headers["content-type"].split(";")[0] == "application/json"
    assert currencies.headers["content-type"].split(";")[0] == "application/json"

    stats_body = stats.json()
    assert stats_body["dates"] >= 1
    assert stats_body["rates"] >= 1
    assert stats_body["first"] is not None
    assert stats_body["last"] is not None
    assert stats_body["first"] <= rate_date <= stats_body["last"]

    currency_body = currencies.json()
    assert currency_body["base"] == "EUR"
    assert currency in currency_body["currencies"]
    assert currency_body["currencies"] == sorted(currency_body["currencies"])
=== END AC health-route ===

## User Acceptance

- None.

## Guardrails

- Compute statistics and currency lists from repository data; do not hardcode counts, dates, or currencies.
- Store and return rate values as published text.
- Do not open a database driver outside the shipped persistence library.

# FEATURE: Effective Date Rates

| Field | Value |
|-------|-------|
| Version | 20261024 V1 |
| Description | Retrieves all rates for the latest ECB publication on or before a requested date. |
| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | GET /rates/{date}, GET /rates/latest |
| Consumes | rates repository operations |

## Questions

- None.

## Purpose

Return persisted rates for an effective publication date. The latest publication on or before a requested date is effective; a request before the first publication returns 404.

## Routes

| Method | Path | Behavior |
|--------|------|----------|
| GET | `/rates/{date}` | Validates a real calendar date, resolves its effective publication, and returns every stored rate for that date with the original requested date. |
| GET | `/rates/latest` | Returns every rate for the most recent publication, with `"requested":"latest"`. |

A date path that is malformed or impossible returns 422. No effective publication returns 404.

## Database Interface

- `FEATURE-RATE-001` — read: list stored rates - supplies: — - returns: `date`, `currency`, `rate`

The endpoint lists repository records and selects the maximum publication date not later than the request. It returns only currencies stored on that effective date.

# FEATURE: Currency Conversion

| Field | Value |
|-------|-------|
| Version | 20261024 V1 |
| Description | Converts amounts between currencies using exact decimal arithmetic. |
| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | GET /convert |
| Consumes | rates repository operations |

## Questions

- None.

## Purpose

Convert an amount from one currency to another using EUR as the base. EUR has an implicit rate of one. If no date is supplied, use the latest publication; otherwise use the latest publication on or before the requested date.

## Route

`GET /convert?from=<code>&to=<code>&amount=<amount>[&date=<date>]`

The amount must match `[0-9]+(\.[0-9]+)?` and is echoed as supplied. A malformed amount, missing required parameter, or malformed date returns 422. A date with no effective publication, or a non-EUR currency without a rate on that publication, returns 404.

The conversion rate is `rate(to) / rate(from)`, calculated exactly and rounded half-even to six decimal places. The result is the supplied amount times the unrounded ratio, rounded half-even to two decimal places. Both outputs are JSON strings with fixed decimal places.

## Database Interface

- `FEATURE-RATE-001` — read: list stored rates - supplies: — - returns: `date`, `currency`, `rate`

Rates and effective publication dates are derived from repository records; no rate is embedded in the service.

## Programmatic Acceptance

=== AC conversion-route ===
Intent: The conversion route returns the supplied amount and computes a conversion from persisted rate text.

from app_server.testing import web_client
from persistence.testing import db_session

target_rate = "3"

    db.rates.upsert(date=rate_date, currency=target_currency, rate=target_rate)
    response = web_client().get(
        "/convert",
        params={"from": source_currency, "to": target_currency, "amount": amount, "date": rate_date},

    assert response.status_code == 200
    body = response.json()
    assert body["date"] == rate_date
    assert body["from"] == source_currency
    assert body["to"] == target_currency
    assert body["amount"] == amount
    assert body["rate"] == "1.500000"
    assert body["result"] == "15.00"
=== END AC conversion-route ===

- Do not hardcode rates or publication dates.

# FEATURE: Currency History

| Field | Value |
|-------|-------|
| Version | 20261024 V1 |
| Description | Retrieves inclusive currency history ranges and exact summary statistics. |
| Depends On | ARCHITECTURE.md, DATABASE.md |
| Provides | GET /history/{code} |
| Consumes | rates repository operations |

## Questions

- None.

## Purpose

Return the stored history for a currency in ascending publication-date order. Optional start and end dates bound the returned points inclusively. The response includes count, minimum, maximum, and exact mean. Mean uses Decimal arithmetic, half-even rounding to six decimal places, and fixed-width string formatting. With no points in the requested range, return zero count, null statistics, and an empty point list. A currency with no stored history at all, including EUR, returns 404.

Malformed start or end dates return 422.

## Database Interface

- `FEATURE-RATE-001` — read: list stored rates - supplies: — - returns: `date`, `currency`, `rate`

History points and statistics are computed from records returned by the rates repository.

## Programmatic Acceptance

=== AC history-route ===
Intent: The history route returns ordered points and summary values for a stored currency.

from app_server.testing import web_client
from persistence.testing import db_session

currency = "ZZZ"
rate_one = "0.943"
rate_two = "1.25"
date_one = "2099-01-02"
date_two = "2099-01-03"

with db_session() as db:
    db.rates.upsert(date=date_one, currency=currency, rate=rate_one)
    db.rates.upsert(date=date_two, currency=currency, rate=rate_two)
    response = web_client().get(f"/history/{currency}")

    assert response.status_code == 200
    body = response.json()
    assert body["currency"] == currency
    assert body["count"] == 2
    assert [point["date"] for point in body["points"]] == [date_one, date_two]
    assert {point["rate"] for point in body["points"]} == {rate_one, rate_two}
    assert body["min"] in {rate_one, rate_two}
    assert body["max"] in {rate_one, rate_two}
    assert body["mean"] is not None
=== END AC history-route ===

=== AC history-range-and-errors ===
Intent: The history route applies inclusive bounds and distinguishes empty ranges, unknown currencies, and malformed dates.

from app_server.testing import web_client
from persistence.testing import db_session

currency = "ZZY"
rate_text = "2.5"
date_one = "2099-01-02"
date_two = "2099-01-03"

with db_session() as db:
    db.rates.upsert(date=date_one, currency=currency, rate=rate_text)
    db.rates.upsert(date=date_two, currency=currency, rate=rate_text)
    client = web_client()

    bounded = client.get(f"/history/{currency}", params={"start": date_one, "end": date_two})
    empty = client.get(f"/history/{currency}", params={"start": "2100-01-01"})
    unknown = client.get("/history/ZZX")
    malformed = client.get(f"/history/{currency}", params={"start": "2099-13-01"})

    assert bounded.status_code == 200
    assert [point["date"] for point in bounded.json()["points"]] == [date_one, date_two]
    assert empty.status_code == 200
    assert empty.json()["count"] == 0
    assert empty.json()["points"] == []
    assert empty.json()["min"] is None
    assert empty.json()["max"] is None
    assert empty.json()["mean"] is None
    assert unknown.status_code == 404
    assert malformed.status_code == 422
=== END AC history-range-and-errors ===

## User Acceptance

- None.

## Guardrails

- Preserve stored rate text in points and extrema.
- Calculate statistics with exact Decimal arithmetic.
- Never hardcode rates, dates, or computed summary values.
