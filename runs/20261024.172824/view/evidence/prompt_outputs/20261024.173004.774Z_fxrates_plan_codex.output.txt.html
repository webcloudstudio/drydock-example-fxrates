# ARCHITECTURE: FxRates

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Defines the application modules and boundaries for the FxRates service. |
| Provides    | app_server.main:create_app, cli.main, persistence.open_database |

## Questions

- None.

## Purpose

FxRates is a Python application with a CLI for initializing and loading ECB reference rates and a FastAPI service for querying them. The CLI and API share services and the generated persistence package.

## Technology Stack

| Technology | Use |
|------------|-----|
| Python | Application and tests, Python 3.11 or newer. |
| FastAPI | JSON API application and test client. |
| SQLite | Local rates database, accessed only through the generated persistence package. |
| CLI | Root `fxrates` executable with `init`, `load`, `fetch`, and `serve` commands. |
| pytest | Project test suite, invoked by `bin/test.sh`. |
| ECB reference rates | `eurofxref-hist.csv` history downloaded from the ECB archive. |
| Shell | POSIX shell launchers and supplied grader. |

## Module Boundaries

| Module | Owns | Allowed access |
|--------|------|----------------|
| `app_server` | FastAPI app factory and route registration | Calls application services. |
| `services` | Rate loading, validation, date resolution, conversion, and history calculations | Calls `persistence` operations. |
| `cli` | Command parsing and command dispatch | Calls services and the server runner. |
| `persistence` | Generated SQLite access layer and schema contract | Uses the shipped persistence library and selected database driver internally. |
| `bin` | POSIX test launcher | Runs pytest from the application root. |

The CLI and API do not open database connections or issue SQL directly. Route handlers call services; services call only declared `db.rates` operations. Configuration resolves `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`.

## Interfaces

- `app_server.main:create_app()` returns the FastAPI application; `app_server.main:app` is the uvicorn entry point.
- `cli.main(argv: list[str] | None = None) -> int` is the command dispatcher.
- `persistence.open_database(dsn)` and `db.rates` expose the generated persistence interface.
- `app_server.testing.web_client()` returns a FastAPI `TestClient` for acceptance criteria and project tests.
- `cli.testing.cli_runner(*args)` returns `(exit_code, stdout, stderr)` for in-process command checks.

# FEATURE: Load ECB History

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Validates and loads ECB history CSV files atomically. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | fxrates load |
| Consumes    | rates.upsert, rates.get |

## Questions

- None.

## Purpose

`fxrates load <csv>` validates the full ECB history CSV before its first write, then stores every non-`N/A` rate as its published text. Loading a matching date and currency replaces the stored value. A rejected file changes nothing.

## Input Rules

- The first header field is `Date`; subsequent fields are three-letter uppercase currency codes. Ignore the trailing empty field produced by the ECB's trailing comma.
- Each data row has a real `YYYY-MM-DD` calendar date not repeated within the file and one value per currency.
- A rate is either `N/A` or a nonzero value matching `[0-9]+(\.[0-9]+)?`.
- `dates` counts distinct file dates with at least one stored rate; `rates` counts stored non-`N/A` values.

## Workflow

Read and validate the complete file before writing. On valid input, upsert all rate rows. On invalid input, exit 3 without changing the database. On success, print the `dates,rates` header and the two counts.

## Database Interface

- `FEATURE-RATE-003` — write: replace a rate by its natural key - supplies: `date`, `currency`, `rate` - returns: `date`, `currency`, `rate`
- `FEATURE-RATE-001` — read: get a rate by date and currency key - supplies: `date`, `currency` - returns: `date`, `currency`, `rate`

# FEATURE: CLI Errors and Test Runner

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Defines CLI failure behavior and the project test launcher. |
| Depends On  | ARCHITECTURE.md |
| Provides    | fxrates usage and failure responses, bin/test.sh |
| Consumes    | fxrates init, fxrates load, fxrates fetch, fxrates serve |

## Questions

- None.

## Purpose

CLI usage errors, rejected files, and operational failures use the exit statuses declared for each condition. Every failed command writes no standard output and one diagnostic line to standard error. `bin/test.sh` runs the project pytest suite from the application root.

## CLI Failure Contract

- Exit `0`: success.
- Exit `1`: operational failure, including unreadable input or failed fetch download.
- Exit `2`: unknown command, wrong argument count, or non-integer `--port`.
- Exit `3`: rejected CSV file.
- Failure output is empty on standard output and one line on standard error.

## Test Launcher

Provide an executable POSIX-compatible `bin/test.sh` that runs pytest from the application root and exits zero only when every automated test passes.
