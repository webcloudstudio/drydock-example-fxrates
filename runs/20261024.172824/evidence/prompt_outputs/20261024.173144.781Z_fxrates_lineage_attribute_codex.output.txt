<requirement name="python-service-stack" stories="architecture,serve_api">
Implement in Python 3.11 or newer with FastAPI, served by uvicorn, over SQLite.
</requirement>
<requirement name="executable" stories="architecture,initialize_store,load_history,fetch_history,serve_api">
The product is an executable named `fxrates` at the application root.
</requirement>
<requirement name="initialize-rates-table" stories="database,initialize_store">
`fxrates init` | Drops the `rates` table if present and creates it empty. | Nothing.
</requirement>
<requirement name="load-ecb-history" stories="database,load_history">
`fxrates load <csv>` | Loads an ECB history file (rules below). | `dates,rates`, then the number of dates and of rates stored from the file.
</requirement>
<requirement name="fetch-ecb-history" stories="fetch_history,load_history">
`fxrates fetch` | Downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts `eurofxref-hist.csv`, and loads it as `load` does. | As `load`.
</requirement>
<requirement name="serve-http-api" stories="serve_api,architecture">
`fxrates serve [--port <n>]` | Serves the HTTP API on `127.0.0.1:<n>` with uvicorn until stopped. Default port `8000`. | Nothing required.
</requirement>
<requirement name="validate-ecb-csv-format" stories="load_history">
1. The file is CSV. The header's first field is `Date`, and every other field is a three-letter uppercase currency code. The ECB writes a trailing comma on every line, and the resulting empty last field is ignored.
2. Each row is a date (`YYYY-MM-DD`, a real calendar date, not repeated within the file) followed by one value per currency. The value `N/A` means no rate, and nothing is stored for it. Any other value must match `[0-9]+(\.[0-9]+)?` and be nonzero.
</requirement>
<requirement name="atomic-load-rejects-invalid-file" stories="load_history,database">
3. **A rejected file changes nothing.** The whole file is checked before the first write. A row with the wrong field count, an invalid or repeated date, or an invalid value rejects the file.
</requirement>
<requirement name="replace-existing-rates" stories="load_history,database">
4. A rate for a (`date`, `currency`) that is already stored replaces it, so loading the same file twice leaves the database unchanged.
</requirement>
<requirement name="report-load-counts" stories="load_history">
5. The reported `dates` counts the dates with at least one stored rate, and `rates` counts the rates stored.
</requirement>
<requirement name="cli-failure-diagnostics-and-codes" stories="cli_errors,load_history,fetch_history">
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="cli-exit-codes" stories="cli_errors,load_history,fetch_history,serve_api">
**Exit codes.** `0` success. `1` operational failure: the file cannot be read, or a `fetch` download fails. `2` usage error: unknown command, wrong argument count, `--port` not an integer. `3` rejected file.
</requirement>
<requirement name="health-endpoint" stories="api_health_stats">
`GET /health` | `{"status": "ok"}`
</requirement>
<requirement name="stats-endpoint" stories="api_health_stats,database">
`GET /stats` | `{"dates": <n>, "rates": <n>, "first": <date>, "last": <date>}`. `first` and `last` are `null` when the table is empty.
</requirement>
<requirement name="currencies-endpoint" stories="api_currencies,database">
`GET /currencies` | `{"base": "EUR", "currencies": [<code>, ...]}`: every currency with at least one stored rate, ascending.
</requirement>
<requirement name="rates-endpoint" stories="api_rates,database">
`GET /rates/{date}` | `{"date": <effective date>, "requested": <date>, "base": "EUR", "rates": {<code>: <rate>, ...}}`: every currency with a rate on the effective date.
</requirement>
<requirement name="latest-rates-endpoint" stories="api_rates,database">
`GET /rates/latest` | As `/rates/{date}` for the latest publication date, with `"requested": "latest"`.
</requirement>
<requirement name="convert-endpoint" stories="api_convert,database">
`GET /convert?from=<code>&to=<code>&amount=<amount>[&date=<date>]` | `{"date": <effective date>, "from": <code>, "to": <code>, "amount": <amount>, "rate": <rate>, "result": <result>}`. Without `date`, the latest publication date is used.
</requirement>
<requirement name="history-endpoint" stories="api_history,database">
`GET /history/{code}[?start=<date>][&end=<date>]` | `{"currency": <code>, "base": "EUR", "count": <n>, "min": <rate>, "max": <rate>, "mean": <mean>, "points": [{"date": <date>, "rate": <rate>}, ...]}` for the publication dates from `start` through `end` inclusive, ascending. Both bounds are optional. With no points, `count` is `0`, `min`, `max`, and `mean` are `null`, and `points` is `[]`.
</requirement>
<requirement name="rate-storage-and-decimal-arithmetic" stories="database,api_convert,api_history">
A rate is stored exactly as the ECB publishes it, as text. `0.943` stays `0.943`, never `0.9430` and never a float. Arithmetic on rates uses Python's `decimal` module.
</requirement>
<requirement name="convert-amount-and-rounding" stories="api_convert">
- `/convert` `amount` matches `[0-9]+(\.[0-9]+)?` and is echoed as given, as a JSON string.
- `/convert` `rate` is `rate(to) / rate(from)`, computed exactly and rounded half to even to six
  decimal places, written with exactly six decimals, as a JSON string: `"161.770000"`.
- `/convert` `result` is `amount × rate(to) / rate(from)`, computed exactly from the stored rates
  (not from the rounded `rate`) and rounded half to even to two decimal places, written with
  exactly two decimals, as a JSON string: `"82.01"`.
</requirement>
<requirement name="history-summary-rules" stories="api_history">
- `/history` `min` and `max` are the stored text of the smallest and largest rate by value.
  `mean` is the exact mean rounded half to even to six decimal places, written with exactly six
  decimals, as a JSON string.
</requirement>
<requirement name="http-error-statuses" stories="api_rates,api_convert,api_history">
| Status | Condition |
|---|---|
| `404` | No publication on or before the requested date; a `/convert` currency other than EUR with no rate on the effective date; a `/history` currency with no stored rate at all (including `EUR`). |
| `422` | A malformed date in the path or query, a malformed `amount`, or a missing required query parameter. FastAPI's request validation produces this status. |
</requirement>
<requirement name="live-load-visibility" stories="load_history,serve_api">
A load that completes while the server is running is visible to the next request.
</requirement>

The suite covers each command, each load rule, each endpoint, the effective-date rule, rounding, and each error status, against a real temporary database, with `fetch` stubbed.
</requirement>
