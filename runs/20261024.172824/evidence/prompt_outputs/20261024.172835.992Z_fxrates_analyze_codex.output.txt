## Story List

### Feature: ECB Rate Data

| ID | Story | High-level AC |
|---|---|---|
| DATA-001 | Initialize the rates store | `fxrates init` creates an empty rates store, replacing any existing table. |
| DATA-002 | Load ECB history files | `fxrates load` validates the whole CSV before writing, skips `N/A`, stores published rate text, replaces matching date and currency rates, and reports stored date and rate counts. |
| DATA-003 | Fetch ECB history files | `fxrates fetch` downloads and extracts the ECB history archive, then loads it using the same validation and storage rules. |

### Feature: Command Line

| ID | Story | High-level AC |
|---|---|---|
| CLI-001 | Handle command usage and failures | The executable returns the specified exit codes for success, usage errors, rejected files, and operational failures; failures print no standard output and one diagnostic line to standard error. |
| CLI-002 | Serve the API process | `fxrates serve` starts the API on the requested port, defaulting to 8000, bound to `127.0.0.1`. |

### Feature: Rates API

| ID | Story | High-level AC |
|---|---|---|
| API-001 | Report service health and rate statistics | `/health` reports status; `/stats` reports date and rate counts and first and last publication dates, using null bounds for an empty store. |
| API-002 | List available currencies | `/currencies` returns EUR as the base and stored currencies in ascending order. |
| API-003 | Retrieve rates for an effective date | `/rates/{date}` and `/rates/latest` return stored rates for the latest publication on or before the requested date; return 404 when none exists and 422 for malformed dates. |
| API-004 | Convert between currencies | `/convert` uses the latest publication by default or resolves the supplied date; it returns the exact rate rounded half to even to six decimal places and the result rounded half to even to two places. |
| API-005 | Retrieve currency history | `/history/{code}` returns ascending points and exact min, max, and mean statistics for inclusive optional date bounds; an empty range returns no points and null statistics. |

### Feature: Verification

## Planning Instructions

### Delivery Shape

Build an executable CLI and a FastAPI JSON service backed by SQLite. The CLI initializes the store and loads ECB CSV data; the API reads the resulting rates to answer health, statistics, currency, date-rate, conversion, and history requests. The main flow is initialize, load data, serve requests, then run the supplied grader.

### Test and Acceptance Strategy

Use focused tests for command behavior, CSV validation and atomicity, route responses, effective-date resolution, and exact decimal rounding. Stub fetch downloads in tests so tests do not open network connections. The terminal verification story runs the complete supplied grader once as the project conformance gate. Sea Trials separately records the supplied grader as the acceptance proof.

### Sequencing and Dependencies

Implement the persistence boundary and initialization before loading and API reads. Complete CSV validation before writes; build fetch on the load capability. Implement API routes and service startup before terminal verification. Stage the supplied harness and all three CSV fixtures before its run. The terminal verification story depends on all implementation stories.

### Source Conflicts and Gaps

No unresolved conflicts or human-owned decisions. The source specifies the product purpose, stack, persistence model, commands, API behavior, errors, and supplied acceptance harness.
