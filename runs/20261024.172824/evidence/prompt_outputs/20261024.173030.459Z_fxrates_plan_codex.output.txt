# FEATURE: Load ECB History

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Validates and loads ECB euro reference rate history CSV files atomically. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | fxrates load |
| Consumes    | rates.upsert |

## Questions

- None.

## Purpose

Load a local ECB history CSV into the configured rates store. Validate the entire file before the first write. A rejected file must leave the store unchanged.

## Trigger

`./fxrates load <csv>`

## Workflow

1. Read the specified file. A file that cannot be read is an operational failure.
2. Parse the CSV. The first header field must be `Date`; every other nonempty header field must be a three-letter uppercase currency code. Ignore the trailing empty field produced by the ECB's trailing comma.
3. For every row, require a real `YYYY-MM-DD` calendar date unique within the file and exactly one value for every currency column, excluding the ignored trailing empty field.
4. Accept `N/A` as a missing rate and do not store it. Every other rate must match `[0-9]+(\.[0-9]+)?` and be nonzero.
5. Validate all rows before writing any rate. If a row is invalid, reject the file without changing the database.
6. Upsert each non-`N/A` rate using its original text, replacing any existing value for the same date and currency.
7. Report the number of dates with at least one stored rate and the number of rates stored from this file.

## Output and failures

On success, stdout is CSV with header `dates,rates` and one data row containing the two counts. On a rejected file, return exit code `3`, write no stdout, and emit one diagnostic line to stderr. An unreadable file returns exit code `1` with the same failure-output convention.

## Programmatic Acceptance

=== AC load-stores-published-text ===
Intent: Loading a valid staged ECB file stores each non-N/A rate as published text and reports its date and rate counts.

import csv
import io
from pathlib import Path

from cli.testing import cli_runner
from persistence.testing import db_session

fixture = Path("sources/eurofxref-hist_2025-01.csv")
with fixture.open(newline="") as stream:
    rows = list(csv.reader(stream))
header = [value for value in rows[0] if value]
rates_by_date = {}
expected_rates = 0
for row in rows[1:]:
    row = [value for value in row if value]
    day, *values = row
    stored = {currency: rate for currency, rate in zip(header[1:], values) if rate != "N/A"}
    if stored:
        rates_by_date[day] = stored
        expected_rates += len(stored)

code, stdout, stderr = cli_runner("load", str(fixture))
assert code == 0
report = list(csv.reader(io.StringIO(stdout)))
assert report[0] == ["dates", "rates"]
assert report[1] == [str(len(rates_by_date)), str(expected_rates)]
with db_session() as db:
    for day, stored in rates_by_date.items():
        for currency, rate in stored.items():
            observed = db.rates.get(date=day, currency=currency)
            assert observed is not None
            assert observed.rate == rate
=== END AC load-stores-published-text ===

## User Acceptance

- None.

## Guardrails

- Preserve each published rate as text; do not normalize its decimal spelling.
- Do not store `N/A` values.
- Validate the complete file before the first database write.
- Use only the declared persistence operations for database access.
- Loading must not remove or overwrite rates for dates or currencies absent from the input.
- A failed load writes nothing to stdout and emits one diagnostic line to stderr.
- The automated suite stubs fetch downloads and does not use the network.

# FEATURE: Fetch ECB History

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Downloads the ECB history archive and loads its CSV through the validated load workflow. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-Load.md |
| Provides    | fxrates fetch |
| Consumes    | fxrates load, rates.upsert |

## Questions

- None.

## Purpose

Fetch the ECB history archive, extract `eurofxref-hist.csv`, and load its data under the same validation, atomicity, storage, and counting rules as `fxrates load`.

## Trigger and workflow

`./fxrates fetch` downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts the member named `eurofxref-hist.csv`, and processes it using the load workflow. Do not depend on the process working directory for extraction paths. A download failure is an operational failure with exit code `1`, no stdout, and one diagnostic line on stderr. A downloaded but invalid CSV follows the rejected-file behavior and returns exit code `3`.

## Programmatic Acceptance

=== AC fetch-download-is-stubbed ===
Intent: The fetch command loads a valid archive member using a stubbed download without opening a network connection.

from pathlib import Path
from unittest.mock import patch
from zipfile import ZipFile
import io

from cli.testing import cli_runner
from persistence.testing import db_session

source = Path("sources/eurofxref-hist_2025-02-03_04.csv").read_bytes()
archive_buffer = io.BytesIO()
with ZipFile(archive_buffer, "w") as archive:
    archive.writestr("eurofxref-hist.csv", source)
archive_bytes = archive_buffer.getvalue()

with patch("urllib.request.urlopen") as download:
    download.return_value.__enter__.return_value.read.return_value = archive_bytes
    code, stdout, stderr = cli_runner("fetch")
assert code == 0
with db_session() as db:
    first = db.rates.get(date="2025-02-03", currency="USD")
    second = db.rates.get(date="2025-02-04", currency="USD")
    assert first is not None and second is not None
    assert first.rate == "1.0274"
    assert second.rate == "1.0335"
=== END AC fetch-download-is-stubbed ===

=== AC fetch-rejects-download-error ===
Intent: A failed download returns the operational failure exit status.

from unittest.mock import patch

from cli.testing import cli_runner

with patch("urllib.request.urlopen", side_effect=OSError("offline")):
    code, stdout, stderr = cli_runner("fetch")
assert code == 1
=== END AC fetch-rejects-download-error ===

## User Acceptance

- None.

## Guardrails

- Download only the specified ECB archive URL.
- Automated tests replace the download with a stub and never use the network.
- Extract and process only the archive member `eurofxref-hist.csv`.
- Reuse the validated load behavior; do not create a separate parsing or persistence path.
- Keep rates in their published text form.

# FEATURE: Serve API

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Runs the FastAPI rates service on the requested local port. |
| Depends On  | ARCHITECTURE.md |
| Provides    | fxrates serve |
| Consumes    | app_server.main:create_app |

## Questions

- None.

## Purpose

`./fxrates serve [--port <n>]` runs the HTTP API in the foreground on `127.0.0.1`. The default port is `8000`. The process stays running until stopped and shuts down cleanly on SIGTERM.

## Workflow

Create and serve the application through the shared FastAPI application factory. Bind only to the loopback address and pass the selected port to uvicorn. If no port is supplied, use `8000`.

## Programmatic Acceptance

=== AC serve-uses-port-and-stops ===
Intent: The serve command starts the API on the requested loopback port and exits after SIGTERM.

import socket
import subprocess
import sys
import time
import urllib.error
import urllib.request

port_socket = socket.socket()
port_socket.bind(("127.0.0.1", 0))
port = port_socket.getsockname()[1]
port_socket.close()

process = subprocess.Popen(
    ["./fxrates", "serve", "--port", str(port)],
    stdout=subprocess.DEVNULL,
    stderr=subprocess.DEVNULL,
)
try:
    deadline = time.monotonic() + 15
    response = None
    while time.monotonic() < deadline:
        try:
            response = urllib.request.urlopen(f"http://127.0.0.1:{port}/health", timeout=1)
            break
        except (OSError, urllib.error.URLError):
            time.sleep(0.1)
    assert response is not None
    assert response.status == 200
finally:
    process.terminate()
    assert process.wait(timeout=10) == 0
=== END AC serve-uses-port-and-stops ===

## User Acceptance

- None.

## Guardrails

- Bind to `127.0.0.1`, not a public interface.
- Keep the server in the foreground.
- Honor the supplied port and default to `8000`.
- Stop cleanly on SIGTERM.

# FEATURE: Health and Rate Statistics

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Reports service health and summary statistics for stored rates. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /health, GET /stats |
| Consumes    | rates.list |

## Questions

- None.

## Purpose

Expose health and aggregate store statistics through JSON endpoints.

## Routes

| Method | Path | Behavior |
|--------|------|----------|
| GET | `/health` | Return `{"status": "ok"}`. |
| GET | `/stats` | Return publication date count, rate count, and first and last publication dates; bounds are null when there are no stored rates. |

## Database Interface

- `FEATURE-RATE-002` — read: list rates for a publication date - supplies: `date` - returns: `date`, `currency`, `rate`

The statistics route needs aggregate and date-bound queries across all rows. The declared `rates.list` operation filters by one date and cannot provide those queries; it does not expose an all-rates list when a date is omitted according to the frozen operation surface. This feature therefore reads through the declared persistence interface and computes its statistics from available returned rows; no raw SQL or driver access is permitted.

## Programmatic Acceptance

=== AC health-route ===
Intent: The health route responds successfully with a JSON object.

from app_server.testing import web_client

client = web_client()
response = client.get("/health")
assert response.status_code == 200
body = response.json()
assert isinstance(body, dict)
assert len(body) == 1
assert next(iter(body.values())) == "ok"
=== END AC health-route ===

=== AC stats-route ===
Intent: The statistics route reports counts and date bounds from stored rate rows.

from app_server.testing import web_client
from persistence.testing import db_session

with db_session() as db:
    date = "2001-03-04"
    db.rates.upsert(date=date, currency="USD", rate="1.2")
    db.rates.upsert(date=date, currency="JPY", rate="130")
    db.rates.upsert(date="2001-03-05", currency="CAD", rate="1.3")

response = web_client().get("/stats")
assert response.status_code == 200
body = response.json()
assert body["dates"] >= 1
assert body["rates"] >= 3
assert body["first"] is not None
assert body["last"] is not None
assert body["first"] <= body["last"]
=== END AC stats-route ===

## User Acceptance

- None.

## Guardrails

- All responses are JSON.
- Derive counts and publication bounds from persisted rows.
- For an empty store, return null for both date bounds.
- Access persistence only through the declared persistence library.

# FEATURE: List Currencies

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Lists EUR and currencies with stored rates in ascending order. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /currencies |
| Consumes    | rates.list |

## Questions

- None.

## Purpose

Return the EUR base and every currency with at least one stored rate, sorted by currency code in ascending order.

## Routes

| Method | Path | Behavior |
|--------|------|----------|
| GET | `/currencies` | Return the EUR base and the ascending list of currencies with stored rates. |

## Database Interface

- `FEATURE-RATE-002` — read: list rates for a publication date - supplies: `date` - returns: `date`, `currency`, `rate`

The repository operation supports listing by publication date, not all currencies. The implementation may derive the currency set from persisted data through the declared interface only; it must not open SQLite directly or introduce an undeclared query.

## Programmatic Acceptance
