# FEATURE: Rate Queries

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Retrieves ECB rates for a requested date or the latest publication. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /rates/{date}, GET /rates/latest |
| Consumes    | rates.list |

## Questions

- None.

## Purpose

Return the stored rates for the latest publication date on or before the requested date. The API uses the same effective-date rule for date requests and the latest publication for `/rates/latest`.

## Routes

| Method | Path | Behavior |
|--------|------|----------|
| GET | `/rates/{date}` | Resolve the supplied calendar date to the latest publication on or before it. |
| GET | `/rates/latest` | Return the rates for the latest publication, with `"requested": "latest"`. |

A successful response is `{"date": <effective date>, "requested": <requested date or "latest">, "base": "EUR", "rates": {<currency>: <stored rate text>, ...}}`. Include every stored currency rate on the effective publication date. Return 404 when no publication exists on or before the requested date. A malformed or impossible calendar date returns 422.

## Database Interface

- `FEATURE-RATE-001` — read: list rates by date and currency - supplies: `date`, `currency` - returns: `id`, `date`, `currency`, `rate`

## Programmatic Acceptance

=== AC effective-date ===
Intent: A date request resolves to a stored publication on or before the requested date.

from app_server.testing import web_client
from persistence.testing import db_session

    currency = "QAZ"
    rate = "1.234"

assert body["requested"] == date
assert body["base"] == "EUR"

# FEATURE: Currency Conversion

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Converts currency amounts using exact decimal arithmetic and half-even rounding. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /convert |
| Consumes    | rates.list |

## Questions

- None.

## Purpose

Convert between EUR and currencies with stored rates using the requested publication date, or the latest publication when no date is supplied. EUR has an implicit rate of one. The returned rate is `rate(to) / rate(from)` and the result is calculated directly from the unrounded stored rates.

## Route

`GET /convert?from=<code>&to=<code>&amount=<amount>[&date=<date>]`

A successful response contains `date`, `from`, `to`, `amount`, `rate`, and `result`. Echo `amount` as the supplied string. Render `rate` as a string with exactly six decimal places, rounded half-even; render `result` as a string with exactly two decimal places, also rounded half-even. Validate `amount` against `[0-9]+(\.[0-9]+)?`. Missing required query parameters, malformed amounts, and malformed or impossible dates return 422. A missing effective publication or unavailable non-EUR currency returns 404.

## Database Interface

- `FEATURE-RATE-001` — read: list rates by date and currency - supplies: `date`, `currency` - returns: `id`, `date`, `currency`, `rate`

## Programmatic Acceptance

=== AC conversion ===
Intent: Conversion echoes the input amount and returns the calculated rate and result for stored rates.

from app_server.testing import web_client
from persistence.testing import db_session

with db_session() as db:
    date = "2099-01-02"
    from_currency = "QAZ"
    to_currency = "WXY"
    from_rate = "2"
    to_rate = "3"
    amount = "10"
    db.rates.upsert(date=date, currency=from_currency, rate=from_rate)
    db.rates.upsert(date=date, currency=to_currency, rate=to_rate)

client = web_client()
response = client.get(
    "/convert",
    params={"from": from_currency, "to": to_currency, "amount": amount, "date": date},
)
assert response.status_code == 200
body = response.json()
assert body["date"] == date
assert body["from"] == from_currency
assert body["to"] == to_currency
assert body["amount"] == amount
assert body["rate"] == "1.500000"
assert body["result"] == "15.00"
=== END AC conversion ===

=== AC missing-amount ===
Intent: A conversion missing its required amount is rejected with the validation status.

from app_server.testing import web_client

=== END AC missing-amount ===

=== AC unavailable-currency ===

## User Acceptance

- None.

## Guardrails

- Use `decimal.Decimal` for all rate and amount arithmetic; never use binary floating point.
- Compute the result from unrounded source rates, not from the displayed rounded conversion rate.
- Apply half-even rounding at the specified precision.

# FEATURE: Currency History

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Retrieves a currency's published rate history and summary statistics. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /history/{code} |
| Consumes    | rates.list |

## Questions

- None.

## Purpose

Return a currency's rates by publication date in ascending order. Optional `start` and `end` bounds are inclusive. Return the number of points, the stored text rates with their dates, minimum and maximum by numeric value, and the exact mean rounded half-even to six decimal places. When the range has no points for a currency that has stored rates, return count zero, null min, max, and mean, and an empty points list. A currency with no stored rates, including EUR, returns 404. Malformed or impossible bounds return 422.

## Database Interface

- `FEATURE-RATE-001` — read: list rates by date and currency - supplies: `date`, `currency` - returns: `id`, `date`, `currency`, `rate`

## Programmatic Acceptance

=== AC history-points ===
Intent: History returns stored points in ascending order and reports their count.

    first_rate = "1.2"
    second_rate = "1.3"
