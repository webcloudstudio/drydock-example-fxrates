# ARCHITECTURE: FxRates

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |

| Provides    | app_server.create_app, cli.main, persistence.open_database |
| Consumes    | rates.list, rates.upsert, rates.delete |

## Questions

- None.

## System Overview

The application is a Python 3.11+ service with a root `fxrates` executable. The CLI initializes and loads ECB rates, fetches the ECB history archive, and starts a FastAPI application served by uvicorn. The API reads the same SQLite database used by the CLI. Rates remain ECB-published text in storage; calculations use `decimal.Decimal`.

## Module Ownership

| Boundary | Owner | Allowed access |
|----------|-------|----------------|
| Persistence | Generated `persistence/` package | Owns SQLite connections and schema operations; application modules call `open_database` and declared `db.rates` operations. No application module opens a database driver. |
| Configuration | `config.py` | Resolves `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. |
| File loading | `rate_loader.py` | Reads, parses, validates, and loads CSV files through the persistence interface. |
| ECB download | `rate_fetch.py` | Downloads and extracts the ECB archive; delegates rate validation and persistence to the loader. |
| CLI | `cli/` | Parses commands and arguments, delegates to loader, fetcher, and server startup. |
| API | `app_server/` | Creates FastAPI routes and obtains data through declared persistence operations. |

## Request and Command Boundaries

`fxrates init` uses the declared persistence boundary to drop and recreate the `rates` table. `fxrates load <csv>` validates the entire file before writing. `fxrates fetch` downloads the ECB ZIP archive and sends its CSV through the same loader. `fxrates serve [--port <n>]` runs the API on `127.0.0.1`, defaulting to port 8000.

The API provides health, database summary, sorted currencies, effective-date rates, conversions, and currency history. A load completed while the server is running is visible to the next request. API details and response contracts are specified in the feature Blueprints.

## Technology Stack

| Technology | Application |
|------------|-------------|
| Python | Application modules and CLI implementation, Python 3.11 or newer. |
| FastAPI | JSON API application and request validation. |
| SQLite | Persistent rates database, accessed only through the generated persistence package. |
| CLI | Root `fxrates` executable and its `init`, `load`, `fetch`, and `serve` commands. |
| pytest | Project test suite, run by `bin/test.sh`, with FastAPI `TestClient`. |
| ECB reference rates | CSV input from the history archive; published rate text is preserved. |
| Shell | POSIX shell launchers and supplied grader invocation. |

# FEATURE: Rate Loading

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Validates and atomically loads ECB CSV history into the rates database. |
| Depends On  | DATABASE.md, ARCHITECTURE.md |
| Provides    | fxrates load |
| Consumes    | rates.list, rates.upsert |

## Questions

- None.

## Purpose

Load a supplied ECB history CSV into the configured database while the application is running or stopped. Validate the whole file before its first write so a rejected file leaves every existing rate unchanged.

## Trigger and Workflow

The CLI accepts `fxrates load <csv>`. The loader reads the CSV, validates its header and all rows, then upserts each non-`N/A` rate by `(date, currency)`. It ignores one trailing empty CSV field on each line. A successful load reports the number of distinct dates that contain at least one rate and the number of rates stored from the file. A failure writes no standard output and one diagnostic line to standard error.

Header requirements: first field `Date`; remaining fields are three-letter uppercase currency codes. Each row has one date and one value per currency. Dates must be real `YYYY-MM-DD` calendar dates and unique within the file. Values are either `N/A` or nonzero values matching `[0-9]+(\.[0-9]+)?`. Wrong row width, malformed or repeated date, missing value, zero, or malformed rate rejects the whole file with exit code 3. An unreadable file is an operational failure with exit code 1.

## Database Interface

- `FEATURE-RATE-001` — read: list rates by optional date and currency - supplies: `date`, `currency` - returns: `id`, `date`, `currency`, `rate`
- `FEATURE-RATE-002` — write: replace a rate by date and currency - supplies: `date`, `currency`, `rate` - returns: `id`, `date`, `currency`, `rate`

# FEATURE: Rate Fetch

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Downloads and loads the ECB history archive through the shared CSV loader. |
| Depends On  | FEATURE-Rate-Loading.md, ARCHITECTURE.md |
| Provides    | fxrates fetch |
| Consumes    | fxrates.load |

## Questions

- None.

## Purpose

Fetch the ECB history ZIP archive and load its `eurofxref-hist.csv` file using the same validation, atomicity, persistence, and reporting behavior as `fxrates load`.

## Trigger and Workflow

`fxrates fetch` downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts the archive member named `eurofxref-hist.csv`, and passes that CSV to the shared loader. A download or unusable archive is an operational failure with exit code 1. Invalid CSV follows the loader's rejected-file behavior and exit code 3. The downloader is replaceable in tests; automated tests use a stub and make no network connection.

## Database Interface

- None — persistence is owned by FEATURE-Rate-Loading.md.

# FEATURE: CLI

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |

| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-Rate-Loading.md, FEATURE-Rate-Fetch.md |
| Provides    | fxrates init, fxrates load, fxrates fetch, fxrates serve |
| Consumes    | cli.main, rates.delete |

## Questions

- None.

## Purpose

Provide the executable `./fxrates` at the application root with the commands `init`, `load`, `fetch`, and `serve`. The module callable `cli.main(argv: list[str] | None = None) -> int` is the implementation entry point; the executable delegates to it.

## Commands

| Command | Behavior | Success output |
|---------|----------|----------------|
| `init` | Drop the existing `rates` table and recreate it empty through the persistence boundary. | Empty |
| `load <csv>` | Delegate to the shared loader. | Loader output |
| `fetch` | Delegate to the archive fetcher. | Loader output |
| `serve [--port <n>]` | Run uvicorn on `127.0.0.1`, default port 8000, until stopped. | No output required |

Each command has usable help that documents its supported arguments. No command argument or an unknown command is a usage error. Unknown command, wrong argument count, and non-integer `--port` return exit code 2. Operational failures return 1; rejected CSV returns 3. Failures write no stdout and one diagnostic line to stderr. `serve` stops cleanly on SIGTERM.

# FEATURE: API Overview

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Serves health, rate database summary, available currencies, and API reference documentation. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | GET /health, GET /stats, GET /currencies, GET /docs |
| Consumes    | rates.list |

## Questions

- None.

## Purpose

Expose service health, a summary of persisted rate history, the currencies present in storage, and FastAPI's API reference entry point. All values are derived from repository queries.

## Routes

### GET /health

Returns status 200 and JSON `{"status": "ok"}`.

### GET /stats

Returns status 200 with `dates`, `rates`, `first`, and `last`. `dates` counts distinct dates with stored rates; `rates` counts stored rows. `first` and `last` are the earliest and latest dates, or null when no rows exist.

### GET /currencies

Returns status 200 with base `EUR` and every currency with at least one stored rate, sorted ascending. EUR is the implicit base currency and need not appear in the stored list.

### GET /docs

Returns the FastAPI API reference entry point.

## Database Interface

- `FEATURE-RATE-001` — read: list all rates to derive service summary and currencies - supplies: `date`, `currency` - returns: `id`, `date`, `currency`, `rate`
