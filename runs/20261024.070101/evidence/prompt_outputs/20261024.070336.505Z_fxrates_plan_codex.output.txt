# FEATURE: Effective-Date Rates

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Resolves rate requests to the latest available ECB publication date. |
| Depends On  | DATABASE.md |
| Provides    | GET /rates/{date}, GET /rates/latest |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Return all rates stored for the latest publication on or before a requested date. The latest route uses the most recent publication and reports `"latest"` as the requested value. EUR is the base; published rates are returned as stored text. Return 404 if no publication exists on or before the requested date.

## Database Interface

- `FEATURE-RATE-002` — read: list rates with optional date and currency filters - supplies: `date`, `currency` - returns: `id`, `date`, `currency`, `rate`

## Programmatic Acceptance

Requires: python-package=httpx; scope=test

=== AC rates-effective-date ===
Intent: A date request returns the rates for the most recent publication on or before the requested date.

from persistence.testing import db_session
from app_server.testing import web_client

publication = "2099-01-02"
requested = "2099-01-03"
currency = "ZZZ"
rate = "1.2300"
with db_session() as db:
    db.rates.upsert(date=publication, currency=currency, rate=rate)

response = web_client().get(f"/rates/{requested}")
body = response.json()
assert response.status_code == 200
assert body["date"] == publication
assert body["requested"] == requested
assert body["rates"][currency] == rate
=== END AC rates-effective-date ===

=== AC rates-no-prior-publication ===

=== AC rates-latest ===
Intent: The latest route reports the latest stored publication and its rates.

## User Acceptance

- None.

## Guardrails

- Rate values remain the ECB-published text.
- Resolve effective dates from stored publications; do not hardcode rates or dates.

# FEATURE: Currency Conversion

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Converts an amount between currencies using exact decimal arithmetic. |
| Depends On  | DATABASE.md |
| Provides    | GET /convert |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Convert using rates for the latest publication on or before the supplied date, or the latest publication when no date is supplied. EUR has implicit rate `1`. Require `from`, `to`, and `amount`. Amounts must match `[0-9]+(\.[0-9]+)?`. Return the rate rounded half-even to six decimal places and the result rounded half-even to two places; compute the result from unrounded stored rates.

## Database Interface

- `FEATURE-RATE-002` — read: list rates with optional date and currency filters - supplies: `date`, `currency` - returns: `id`, `date`, `currency`, `rate`

## Programmatic Acceptance

Requires: python-package=httpx; scope=test

=== AC convert-exact-decimal ===
Intent: Conversion uses exact rate values and echoes the supplied amount and currencies.

from persistence.testing import db_session
from app_server.testing import web_client

publication = "2099-01-02"
source = "AAA"
target = "BBB"
source_rate = "3"
target_rate = "2"
amount = "10.00"
with db_session() as db:
    db.rates.upsert(date=publication, currency=source, rate=source_rate)
    db.rates.upsert(date=publication, currency=target, rate=target_rate)

response = web_client().get(
    "/convert",
    params={"from": source, "to": target, "amount": amount, "date": publication},

body = response.json()
assert response.status_code == 200
assert body["date"] == publication
assert body["from"] == source
assert body["to"] == target
assert body["amount"] == amount

=== END AC convert-exact-decimal ===

# FEATURE: Currency History

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Returns a currency's stored rate history and summary statistics. |
| Depends On  | DATABASE.md |
| Provides    | GET /history/{code} |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Return ascending publication-date points for a currency, optionally bounded by inclusive `start` and `end` dates. Rates, minimum, and maximum preserve stored text. Compute the exact mean with decimal arithmetic and half-even rounding to six decimal places. When the selected range has no points, return an empty points list, count zero, and null statistics. Return 404 when the currency has no stored rate at all.

## Database Interface

- `FEATURE-RATE-002` — read: list rates with optional date and currency filters - supplies: `date`, `currency` - returns: `id`, `date`, `currency`, `rate`

## Programmatic Acceptance

Requires: python-package=httpx; scope=test

# FEATURE: API Request Validation

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Enforces request validation and not-found responses across rate API requests. |
| Depends On  | FEATURE-API-Rates.md, FEATURE-API-Convert.md, FEATURE-API-History.md |
| Provides    | API request validation behavior |
| Consumes    | GET /rates/{date}, GET /convert, GET /history/{code} |

## Questions

- None.

## Purpose

Ensure malformed dates in path and query parameters, malformed conversion amounts, and missing required conversion parameters receive HTTP 422. Unknown currencies, currencies without a required rate, unknown history currencies, and dates without any prior publication receive HTTP 404. This specification owns validation and error-status behavior for the rates, conversion, and history routes.

# FEATURE: CLI Server

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Runs the JSON API on the requested local port until stopped. |
| Depends On  | ARCHITECTURE.md, FEATURE-API-Health-Stats.md |
| Provides    | fxrates serve |
| Consumes    | FastAPI application |

## Questions

- None.

## Purpose

`fxrates serve [--port <n>]` runs uvicorn in the foreground, binding the API to `127.0.0.1` at the requested port, defaulting to 8000. It continues until stopped and handles SIGTERM cleanly. It does not require standard output.

## Programmatic Acceptance

=== AC serve-stops-on-sigterm ===
Intent: The serve command starts the local API and exits after receiving SIGTERM.

import signal
import socket
import subprocess
import time

with socket.socket() as sock:
    sock.bind(("127.0.0.1", 0))
    port = sock.getsockname()[1]

process = subprocess.Popen(
    ["./fxrates", "serve", "--port", str(port)],
    stdout=subprocess.DEVNULL,
    stderr=subprocess.DEVNULL,
)
try:
    deadline = time.monotonic() + 10
    while time.monotonic() < deadline:
        if process.poll() is not None:
            raise AssertionError("serve exited before becoming available")
        try:
            with socket.create_connection(("127.0.0.1", port), timeout=0.2):
                break
        except OSError:
            time.sleep(0.05)
    else:
        raise AssertionError("serve did not bind the requested port")
    process.send_signal(signal.SIGTERM)
    assert process.wait(timeout=5) == 0
finally:
    if process.poll() is None:
        process.terminate()
        process.wait(timeout=5)
=== END AC serve-stops-on-sigterm ===

## User Acceptance

- None.

## Guardrails

- Bind only to `127.0.0.1`.
- Default to port 8000 when `--port` is omitted.
- Keep the server in the foreground and stop cleanly on SIGTERM.
