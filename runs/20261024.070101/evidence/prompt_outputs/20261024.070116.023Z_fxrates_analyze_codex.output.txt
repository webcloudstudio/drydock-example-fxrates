# Blueprint Analysis: FxRates

## Commander Expectations

- assert the product loads ECB euro reference history and serves date-based rates, conversions, and currency history through a JSON API.
- assert invalid history files are rejected without changing stored data.
- assert conversions and history statistics use exact decimal arithmetic with the specified rounding.

## Story List

### Feature: History Import and CLI

| ID | Story | High-level AC |
|---|---|---|
| CLI-001 | Initialize the rates store | `fxrates init` creates an empty rates table and prints nothing. |
| CLI-002 | Load ECB history files | Valid rows are stored as published text; `N/A` is skipped; repeated keys are replaced; output reports dates and rates stored. |
| CLI-003 | Reject invalid history files atomically | Invalid rows reject the entire file with exit code 3 and no database changes. |
| CLI-004 | Report CLI usage and operational errors | Usage errors exit 2; unreadable files exit 1; failures print no stdout and one diagnostic line to stderr. |
| CLI-005 | Fetch ECB history | Fetch downloads and extracts the ECB history archive, then loads it with the same rules; tests stub the download and use no network. |

### Feature: Rates and Conversion API

| ID | Story | High-level AC |
|---|---|---|
| API-001 | Serve health and database statistics | `/health` reports `ok`; `/stats` reports date and rate counts plus first and last dates, or null dates when empty. |
| API-002 | List available currencies | `/currencies` returns EUR as the base and currencies with stored rates in ascending order. |
| API-003 | Resolve rates by effective date | `/rates/{date}` and `/rates/latest` return the effective publication date, requested date, base, and that date's rates; no prior publication returns 404. |
| API-004 | Convert between currencies | `/convert` returns the effective date, input currencies and amount, the six-decimal rounded rate, and the two-decimal rounded result. |
| API-005 | Return currency history | `/history/{code}` returns ascending points and count, min, max, and six-decimal mean for inclusive optional date bounds; empty ranges return empty statistics. |
| API-006 | Validate API requests and currencies | Malformed dates and amounts and missing required parameters return 422; unknown currencies and unavailable rates return 404. |

## Planning Instructions

### Delivery Shape

Build a Python command-line application backed by SQLite and a FastAPI JSON service. The CLI initializes the store, loads ECB history files, optionally fetches the published archive, and starts the local server. The API exposes health, statistics, currencies, effective-date rates, conversions, and bounded currency history.

### Test and Acceptance Strategy

Keep focused tests scoped to each story: CLI initialization, load rules, error codes, fetch with a stubbed download, and API route behavior against a temporary database. Do not use network connections in tests. RUN-002 is the single terminal verification story; it depends on every implementation story and runs the complete supplied harness with `Suite: full`. Final project-wide acceptance is also recorded in SEA_TRIALS.

### Sequencing and Dependencies

The persistence boundary and database setup precede CLI and API behavior. CSV parsing and whole-file validation precede writes and load reporting. Store initialization and loading precede server-backed API checks. Implement API routes before the server command is used for end-to-end verification. RUN-002 follows all implementation stories. The fetch integration is tested with a stubbed download.

### Source Conflicts and Gaps

The instructions, fixtures, and harness provide consistent product behavior. They specify no authentication or protected resources, no sensitive data, and no human-facing UI. Deployment beyond the local server is not specified and is not needed for the stated local harness workflow.
