Planning Instructions

Delivery Shape

Build a Python command-line application backed by SQLite and a FastAPI JSON service. The CLI initializes the store, loads ECB history files, optionally fetches the published archive, and starts the local server. The API exposes health, statistics, currencies, effective-date rates, conversions, and bounded currency history.

Test and Acceptance Strategy

Keep focused tests scoped to each story: CLI initialization, load rules, error codes, fetch with a stubbed download, and API route behavior against a temporary database. Do not use network connections in tests. RUN-002 is the single terminal verification story; it depends on every implementation story and runs the complete supplied harness with Suite: full. Final project-wide acceptance is also recorded in SEA_TRIALS.

Sequencing and Dependencies

The persistence boundary and database setup precede CLI and API behavior. CSV parsing and whole-file validation precede writes and load reporting. Store initialization and loading precede server-backed API checks. Implement API routes before the server command is used for end-to-end verification. RUN-002 follows all implementation stories. The fetch integration is tested with a stubbed download.

Source Conflicts and Gaps

The instructions, fixtures, and harness provide consistent product behavior. They specify no authentication or protected resources, no sensitive data, and no human-facing UI. Deployment beyond the local server is not specified and is not needed for the stated local harness workflow.
