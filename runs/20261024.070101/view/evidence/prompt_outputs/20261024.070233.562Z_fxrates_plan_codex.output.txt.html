# FEATURE: CLI Load

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Validates and loads ECB history CSV files into the rates store. |
| Depends On  | DATABASE.md, ARCHITECTURE.md |

## Questions

- None.

## Purpose

`fxrates load <csv>` validates the entire file before writing, stores each non-`N/A` rate exactly as published, replaces an existing (`date`, `currency`) rate, and reports the number of dates and rates stored.

## File Rules

- The first header field is `Date`; remaining fields are three-letter uppercase currency codes. Ignore one trailing empty field.
- Each date is a real `YYYY-MM-DD` calendar date and appears at most once in the file. Each row has the expected number of fields.
- Each value is `N/A` or a nonzero value matching `[0-9]+(\.[0-9]+)?`.
- Reject the whole file if any row is invalid. Rejection exits with code `3` and writes no data.
- A successful load counts dates having at least one stored rate and counts the non-`N/A` rates from the file.

## Workflow

1. Read and validate the complete CSV before the first write.
2. Upsert each non-`N/A` value through `rates.upsert`.
3. Return success and the required date and rate counts.

## Reads and Writes

- Writes: `FEATURE-RATE-001` to store or replace each rate.
- A rejected file performs no repository writes.

## Programmatic Acceptance

## Questions

- None.

## Purpose

CLI failures use the specified response contract: usage errors exit `2`, operational failures exit `1`, and rejected input files exit `3`. A failing command writes no standard output and one diagnostic line to standard error; diagnostic wording is not part of the contract.

## Failure Classification

| Condition | Exit code |
|-----------|-----------|
| Unknown command, wrong argument count, or non-integer `--port` | `2` |
| Unreadable input file or failed fetch | `1` |
| Invalid history file | `3` |

## Purpose

`fxrates fetch` downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts `eurofxref-hist.csv`, and loads it using the same validation, replacement, and reporting behavior as `fxrates load`. Use Python standard-library HTTPS support. Tests stub the download and do not use the network.

## Workflow

1. Request the archive using the standard-library URL transport.
2. Read `eurofxref-hist.csv` from the ZIP archive.
3. Validate the complete CSV before writing.
4. Store valid non-`N/A` rates through the declared repository operation.

## Reads and Writes

- Writes: `FEATURE-RATE-001` to store or replace each rate.
- Failed downloads return the operational failure exit code and store nothing.

Intent: Fetch loads the stubbed archive's CSV through the normal repository path without a network request.

import io
import zipfile
from unittest.mock import patch
from cli.testing import cli_runner
from persistence.testing import db_session

csv_text = "Date,USD,JPY,\n2099-03-01,1.234,160.50,\n"
archive = io.BytesIO()
with zipfile.ZipFile(archive, "w") as zipped:
    zipped.writestr("eurofxref-hist.csv", csv_text)
archive_bytes = archive.getvalue()

with patch("urllib.request.urlopen", return_value=io.BytesIO(archive_bytes)):
    code, _, _ = cli_runner("fetch")

assert code == 0
with db_session() as db:
    usd = db.rates.list(date="2099-03-01", currency="USD")
    jpy = db.rates.list(date="2099-03-01", currency="JPY")
    assert len(usd) == 1
    assert len(jpy) == 1
    assert usd[0].rate == "1.234"
