# FEATURE: API Overview

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Provides health, rate coverage, and available-currency endpoints. |
| Depends On  | DATABASE.md, ARCHITECTURE.md |
| Provides    | GET /health, GET /stats, GET /currencies |
| Consumes    | `FEATURE-RATE-005` rates.list_all |

## Questions

- None.

## Purpose

Expose service health and a database-backed summary of stored rate coverage and currencies.

## Workflow

- `GET /health` returns a JSON object with `status` set to `ok`.
- `GET /stats` returns distinct publication-date count, stored-rate count, earliest date, and latest date. Empty stores return zero counts and `null` dates.
- `GET /currencies` returns EUR as the base and the distinct currencies with at least one stored rate, sorted ascending. EUR is implicit and is not included unless it has stored rates.

## Database Interface

- `FEATURE-RATE-005` — read: list all rates - supplies: — - returns: `date`, `currency`, `rate`

## Guardrails

- Derive counts, dates, and currencies from persisted rates on each request.
- Route access to persistence through the generated library.

# FEATURE: Effective-Date Rates

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Retrieves rates for the latest publication date on or before a requested date. |
| Depends On  | DATABASE.md, ARCHITECTURE.md |
| Provides    | GET /rates/{date}, GET /rates/latest |
| Consumes    | `FEATURE-RATE-002` rates.list_date, `FEATURE-RATE-005` rates.list_all |

## Questions

- None.

## Purpose

Return the ECB rates for the effective publication date. A requested date resolves to the latest stored publication date on or before it.

## Workflow

- `GET /rates/{date}` accepts a real calendar date in `YYYY-MM-DD` form. A malformed date returns 422. If no publication exists on or before it, return 404.
- `GET /rates/latest` resolves the latest stored publication and uses `latest` as the requested value. Return 404 when there are no rates.
- Successful responses contain the effective date, requested date, EUR base, and every rate stored for that date. Rate values remain published text strings.

## Database Interface

- `FEATURE-RATE-002` — read: list rates for a publication date - supplies: `date` - returns: `date`, `currency`, `rate`
- `FEATURE-RATE-005` — read: list all rates - supplies: — - returns: `date`, `currency`, `rate`

## Guardrails

- Resolve effective dates from stored rows; do not hardcode dates or rates.
- Do not convert rate text to floating point.

## Programmatic Acceptance

# FEATURE: Currency Conversion

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Converts amounts between currencies using exact decimal arithmetic. |
| Depends On  | DATABASE.md, ARCHITECTURE.md |
| Provides    | GET /convert |
| Consumes    | `FEATURE-RATE-001` rates.upsert, `FEATURE-RATE-002` rates.list_date, `FEATURE-RATE-005` rates.list_all |

## Questions

- None.

## Purpose

Convert an amount from one currency to another using rates for the effective publication date. EUR has the implicit rate `1`.

## Workflow

`GET /convert` requires `from`, `to`, and `amount`; `date` is optional and defaults to the latest publication. Amounts must match `[0-9]+(\.[0-9]+)?` and are echoed as supplied. Malformed or missing values return 422. A missing effective publication or unavailable non-EUR currency returns 404.

The response includes effective date, source and destination currencies, amount, rate, and result. Compute `rate = rate(to) / rate(from)` exactly from stored text and round half-even to six decimal places. Compute the result from the unrounded ratio and input amount, rounding half-even to two decimal places. Both results are fixed-width decimal strings.

## Database Interface

- `FEATURE-RATE-002` — read: list rates for a publication date - supplies: `date` - returns: `date`, `currency`, `rate`
- `FEATURE-RATE-005` — read: list all rates - supplies: — - returns: `date`, `currency`, `rate`

## Guardrails

- Use `decimal.Decimal` throughout; never use binary floating point.
- Compute the result from the unrounded conversion ratio.
- Keep request amount text unchanged in the response.

## Programmatic Acceptance

# FEATURE: Currency History

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Returns ordered currency rates and exact statistics over optional date bounds. |
| Depends On  | DATABASE.md, ARCHITECTURE.md |
| Provides    | GET /history/{code} |
| Consumes    | `FEATURE-RATE-003` rates.list_currency |

## Questions

- None.

## Purpose

Return stored history for a currency, with optional inclusive date bounds. Statistics are calculated from all returned points using exact decimals.

## Workflow

`GET /history/{code}` returns points in ascending date order. With no points in the selected range, return an empty list and null `min`, `max`, and `mean`. Otherwise `min` and `max` preserve the published text of the rates with the smallest and largest numeric values, and `mean` is rounded half-even to six decimal places as a fixed-width string.

Malformed `start` or `end` dates return 422. A currency with no stored rate anywhere returns 404, including EUR.

## Database Interface

- `FEATURE-RATE-003` — read: list rates for one currency - supplies: `currency` - returns: `date`, `currency`, `rate`

## Guardrails

- Use Decimal for comparisons and statistics; never use binary floating point.
- Apply date bounds inclusively.
- Distinguish a known currency with an empty selected range from a currency with no stored rates.

## Programmatic Acceptance

=== AC history-range ===
Intent: The history route returns its arranged points in order and reports the arranged rate values.

from persistence.testing import db_session
from app_server.testing import web_client

currency = "ZZZ"
first_date = "2098-05-01"
second_date = "2098-05-02"
first_rate = "1.00"
second_rate = "2.00"
with db_session() as db:
    db.rates.upsert(date=first_date, currency=currency, rate=first_rate)
    db.rates.upsert(date=second_date, currency=currency, rate=second_rate)
    response = web_client().get(
        f"/history/{currency}",
        params={"start": first_date, "end": second_date},
    )
    assert response.status_code == 200
    body = response.json()
    assert body["currency"] == currency
    assert body["base"] == "EUR"
    assert [point["date"] for point in body["points"]] == [first_date, second_date]
    assert [point["rate"] for point in body["points"]] == [first_rate, second_rate]
    assert body["count"] == 2
    assert body["min"] == first_rate
    assert body["max"] == second_rate
=== END AC history-range ===
