# ARCHITECTURE: FxRates Application

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Defines the application modules and ownership boundaries for the FxRates command line and API. |

## Questions

- None.

## Module Boundaries

| Module | Owns | Allowed dependencies |
|--------|------|---------------------|
| `cli` | The `fxrates` executable, argument handling, command dispatch, and diagnostics. | Feature services, configuration |
| `app_server` | The FastAPI application factory and HTTP route registration. | Feature services, configuration |
| `services` | ECB CSV validation and loading, fetching, store initialization, rate queries, and exact decimal calculations. | `persistence`, configuration, standard library |
| `persistence` | The generated relational layer and shipped database library. | Database engine and schema |
| `config` | Resolving the database location from `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. | Standard library |

HTTP handlers call services. CLI commands call services. Services call the generated persistence operations through the shipped persistence library. Only the persistence boundary reaches the database. No application module opens a database driver directly.

The load workflow validates the complete input file before its first write. The fetch workflow extracts the archive's CSV and passes it through the same validation and loading behavior. Rate calculations use `decimal.Decimal`; published values remain text in storage and API responses.

## Technology Stack

| Technology | Use |
|------------|-----|
| Python 3.11 or newer | Application, CLI, services, and tests |
| FastAPI | JSON HTTP API |
| uvicorn | Serving the API on `127.0.0.1` |
| SQLite | Local rates store, accessed through the shipped persistence library |
| pytest | Offline automated tests |
| FastAPI `TestClient` | In-process API checks |

# FEATURE: ECB CSV Loading

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Validates and loads ECB history CSV files atomically while preserving published rate text. |
| Depends On  | FEATURE-CLI.md, DATABASE.md |

## Questions

- None.

## Purpose

`./fxrates load <csv>` reads an ECB history file, validates the entire file before its first database write, then stores every rate other than `N/A`. A valid rate replaces the stored value for the same publication date and currency. On success, print CSV output with header `dates,rates` and one data row containing the number of dates with at least one rate and the number of rates stored from this file.

## CSV Rules

- The first header field is `Date`; subsequent fields are three-letter uppercase currency codes. Ignore the final empty field produced by the ECB trailing comma.
- Each row has a real, non-repeated `YYYY-MM-DD` date and exactly one value per currency, excluding the ignored trailing field.
- `N/A` denotes no rate and creates no stored row. Other values match `[0-9]+(\.[0-9]+)?` and are nonzero.
- A malformed header or row, wrong field count, invalid or repeated date, or invalid rate rejects the file. Reject it before writing any row.
- A file read failure is an operational failure. A rejected file and an operational failure produce no standard output; diagnostics go to standard error.

## Database Interface

- `FEATURE-RATE-001` — write: store or replace a published rate - supplies: `date`, `currency`, `rate` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

| Field       | Value |
|-------------|-------|
| Version     | 20261026 V1 |
| Description | Downloads and extracts the ECB history archive before loading its CSV through the shared loader. |
| Depends On  | FEATURE-Load.md |

## Questions

- None.

## Purpose

`./fxrates fetch` downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts `eurofxref-hist.csv`, and passes that file through the same validation, persistence, and reporting workflow as `./fxrates load`.

A download failure returns status 1, writes no standard output, and emits a diagnostic to standard error. Automated tests replace the download with a stub and do not access the network.

## Programmatic Acceptance

=== AC fetch-stubbed-success ===
Intent: Fetch loads the CSV from a stubbed ECB archive and reports its fixture-derived counts.
Requires: python-package=fastapi; scope=test
Requires: python-package=httpx2; scope=test

import csv
import io
import urllib.request
import zipfile
from unittest.mock import patch
from cli.testing import cli_runner
from persistence.testing import db_session

buffer = io.BytesIO()
with zipfile.ZipFile(buffer, "w") as archive:
    archive.writestr("eurofxref-hist.csv", "Date,USD,\n2099-06-01,1.25,\n")
payload = buffer.getvalue()

class Response:
    def read(self):
        return payload
    def __enter__(self):
        return self
    def __exit__(self, *args):
        return None

with patch("urllib.request.urlopen", return_value=Response()):
    code, stdout, stderr = cli_runner("fetch")

rows = list(csv.reader(stdout.splitlines()))
with db_session() as db:
    stored = db.rates.by_date(date="2099-06-01")
assert code == 0
assert rows[0] == ["dates", "rates"]
assert rows[1] == ["1", "1"]
assert len(stored) == 1
assert stored[0].currency == "USD"
assert stored[0].rate == "1.25"
