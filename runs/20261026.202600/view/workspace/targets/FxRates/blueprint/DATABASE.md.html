Programmatic Acceptance

=== AC rates-upsert ===
Intent: The repository stores a rate and replaces the value for the same date and currency.

from persistence.testing import db_session

date = "2099-01-02" currency = "QAA" rate = "1.234" replacement = "1.235"

with db_session() as db: first = db.rates.upsert(date=date, currency=currency, rate=rate) assert first.date == date assert first.currency == currency assert first.rate == rate

second = db.rates.upsert(date=date, currency=currency, rate=replacement) assert second.rate == replacement

stored = db.rates.by_date(date=date) assert len([row for row in stored if row.currency == currency]) == 1 assert next(row for row in stored if row.currency == currency).rate == replacement === END AC rates-upsert ===

User Acceptance

  • None.

Guardrails

  • Preserve every ECB rate as published text; do not store or compute rates as floating-point values.
  • Application code accesses the database only through the shipped persistence library and generated relational layer.
  • Database location resolves from DATABASE_URL, then DATABASE_PATH, then data/app.db.
  • Keep the (date, currency) uniqueness rule so loading an existing rate replaces that stored value.
