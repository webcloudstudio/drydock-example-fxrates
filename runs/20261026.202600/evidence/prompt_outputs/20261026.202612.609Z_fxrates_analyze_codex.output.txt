### Feature: Rates API

| ID | Story | High-level AC |
|---|---|---|
| API-001 | Report service health | `GET /health` returns status 200 and `{"status":"ok"}`. |
| API-002 | Report stored rate statistics | `GET /stats` returns date and rate counts and first and last publication dates, or null bounds when empty. |
| API-003 | List currencies with rates | `GET /currencies` returns EUR as base and currencies with stored rates in ascending order. |
| API-004 | Retrieve rates by effective date | `GET /rates/{date}` returns all rates for the latest publication on or before the requested date, or 404 if none exists. |

## Planning Instructions

### Delivery Shape

A Python command-line loader and FastAPI JSON service use the shared rates store. The CLI initializes the store, validates and loads local ECB CSV files, and can fetch and load the ECB archive. The service exposes health, store statistics, currency listing, effective-date rates, conversion, and bounded history. The end-to-end flow is initialize, load January data, start the service, request data locally, and verify live visibility after a later file load.

### Test and Acceptance Strategy

Use focused pytest coverage for each story's CLI or API behavior. Stub fetch downloads so automated tests remain offline and cover both successful loading and operational download failure. Use `sources/run.sh` as the terminal full-suite verification; TEST-002 depends on every implementation story and runs the complete harness. All other stories remain scoped to their own behavior.

### Sequencing and Dependencies

Implement the store boundary and its stable repository-call contracts before persisted CLI and API behavior. Initialize and CSV load precede API stories that read rates. CLI error handling applies across commands. Fetch reuses the load behavior and can follow CSV loading. Focused tests follow their behavior; complete grader verification follows all implementation stories. Stage all three CSV fixtures and `sources/run.sh` unchanged.

### Source Conflicts and Gaps

No conflicting source definitions or human-owned decisions remain. The instructions select Python 3.11+, FastAPI, uvicorn, SQLite, pytest, and `TestClient`; the product has no human-facing UI or protected resource requiring an auth decision. The load and fetch failures have explicit exit behavior; no separate deployment target is stated beyond local execution on `127.0.0.1`.
