## Story List

### Feature: Rate Data Operations

| ID | Story | High-level AC |
|---|---|---|
| DATA-001 | Initialize the rates database | `fxrates init` creates an empty rates table and prints nothing. |
| DATA-002 | Load ECB history files | `fxrates load` validates the complete file before writing, stores non-`N/A` rates as published text, replaces matching date/currency rates, and reports date and rate counts. |
| DATA-003 | Fetch ECB history | `fxrates fetch` downloads and extracts the ECB history file, loads it using the same validation and storage rules, and reports the counts. |

### Feature: HTTP Rates API

| ID | Story | High-level AC |
|---|---|---|
| API-001 | Serve the API and report health | The service binds to the requested local port (default 8000) and `GET /health` returns `{"status":"ok"}`. |
| API-002 | Report stored data statistics | `GET /stats` returns publication-date and rate counts and first/last dates, using null dates when empty. |
| API-003 | List available currencies | `GET /currencies` returns EUR as the base and stored currencies in ascending order. |
| API-004 | Resolve rates for a date | `GET /rates/{date}` returns every rate on the latest publication on or before the requested date, or 404 when none exists. |
| API-005 | Resolve the latest rates | `GET /rates/latest` returns every rate on the latest publication date and identifies the request as `latest`. |
| API-006 | Convert between currencies | `GET /convert` returns the effective date, echoed amount, exact cross-rate and result with the specified half-even decimal rounding; omitted dates use the latest publication. |
| API-007 | Retrieve currency history | `GET /history/{code}` returns ordered points and count, min, max, and mean for the inclusive optional date range, including the specified empty result. |
| API-008 | Reject invalid and unavailable API requests | Malformed dates or amounts and missing required parameters return 422; unknown currencies and unavailable dates return 404. |

## Planning Instructions

### Delivery Shape

A local command-line loader initializes SQLite, imports ECB history, and can fetch the published archive. A FastAPI JSON service reads the same persisted rates and serves health, summary, currency, date-rate, conversion, and history requests. The required flow is initialize, load history, then serve requests; fetch is an additional import path. The supplied grader runs the CLI, starts the API on a free local port, and checks its responses.

### Test and Acceptance Strategy

Write focused tests for each story: command behavior and loader rejection/replacement, endpoint response shapes and statuses, effective-date resolution, and exact decimal rounding. Stub the archive download in fetch tests and make no network connection. Keep these tests bounded to the story they cover.

The sole terminal verification story runs the complete automated suite and declares `Suite: full`; it depends on every implementation story. `sources/run.sh` is the supplied end-to-end acceptance command and is checked separately by Sea Trials.

### Sequencing and Dependencies

Implement initialization and the validated loader before fetch and persistent API reads. Implement effective-date selection before rates and conversion behavior that relies on it. Build focused tests alongside their stories. Stage the CSV fixtures and harness before terminal verification. Do not add a database driver path outside the shipped persistence library.

### Source Conflicts and Gaps

No unresolved source conflicts or human-owned planning questions. The brief specifies Python 3.11+, FastAPI, uvicorn, SQLite, pytest, and TestClient. It specifies a shipped persistence library generated from `DATABASE.md`; preserve that boundary when authoring repository contracts.
