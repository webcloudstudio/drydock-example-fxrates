# FEATURE: CLI Load

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Loads validated ECB history files into the rates store. |
| Depends On  | DATABASE.md, ARCHITECTURE.md |
| Provides    | `fxrates load` |
| Consumes    | `rates.upsert`, `rates.list` |

## Questions

- None.

## Purpose

Load an ECB history CSV, validating the entire file before writing. A successful load stores non-`N/A` rates as their original text, replaces existing date and currency pairs, and reports the number of dates with stored rates and the number of rates stored.

## Workflow

1. Read and parse the specified CSV, ignoring the trailing empty field produced by the ECB's final comma.
2. Validate the header, currency codes, row field counts, real calendar dates, unique dates, and every rate value.
3. Reject the file without writes if any row is invalid.
4. Upsert all non-`N/A` rates through the generated persistence package.
5. Print the load summary on success. On failure, print no standard output and write one diagnostic line to standard error.

Exit status is `0` on success, `1` when the file cannot be read, `2` for usage errors, and `3` for rejected file content.

## Programmatic Acceptance

=== AC load-stores-published-text ===
Intent: Loading a valid CSV stores each non-N/A rate as the exact input text and reports success.
Suite: scoped

from pathlib import Path
from cli.testing import cli_runner
from persistence.testing import db_session

csv_path = Path("load-valid.csv")
date = "2099-12-30"
currency = "ZZZ"
rate = "1.2300"
csv_path.write_text(f"Date,{currency},\n{date},{rate},\n", encoding="utf-8")

try:
    code, stdout, stderr = cli_runner("load", str(csv_path))
    assert code == 0
    with db_session() as db:
        row = db.rates.get(date=date, currency=currency)
        assert row is not None
        assert row.rate == rate
finally:
    csv_path.unlink(missing_ok=True)

# FEATURE: CLI Fetch

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Downloads and loads the ECB euro reference history archive. |
| Depends On  | FEATURE-CLI-LOAD.md, ARCHITECTURE.md |
| Provides    | `fxrates fetch` |
| Consumes    | `fxrates load` |

## Questions

- None.

## Purpose

Download the ECB history ZIP archive, extract `eurofxref-hist.csv`, and load it using the same validation, storage, and summary behavior as `fxrates load`.

## Workflow

1. Download `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`.
2. Extract the `eurofxref-hist.csv` member.
3. Pass the extracted CSV through the shared loader.
4. Return exit status `0` on success or `1` if the download fails. A rejected extracted CSV follows the loader's rejected-file behavior.

Automated tests replace the download with a stub and must not open a network connection.

## Programmatic Acceptance

=== AC fetch-loads-stubbed-archive ===
Intent: The fetch command loads the CSV supplied by a stubbed download.
Suite: scoped

from io import BytesIO
from zipfile import ZipFile
from unittest.mock import patch
from cli.testing import cli_runner
from persistence.testing import db_session

date = "2099-12-30"
currency = "ZZZ"
rate = "1.234"
archive_buffer = BytesIO()
with ZipFile(archive_buffer, "w") as archive:
    archive.writestr("eurofxref-hist.csv", f"Date,{currency},\n{date},{rate},\n")
archive_bytes = archive_buffer.getvalue()

with patch("cli.fetch.urlopen") as urlopen:
    urlopen.return_value.__enter__.return_value.read.return_value = archive_bytes
    code, stdout, stderr = cli_runner("fetch")
    assert code == 0

with db_session() as db:
    row = db.rates.get(date=date, currency=currency)
    assert row is not None
    assert row.rate == rate
=== END AC fetch-loads-stubbed-archive ===

=== END AC fetch-download-failure ===

## User Acceptance

- None.

## Guardrails

- Route archive contents through the same complete-file validation and load path as `fxrates load`.
- Fetch tests must stub the download and must not open a network connection.

# FEATURE: API Rates

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Resolves effective rates by requested or latest publication date. |
| Depends On  | DATABASE.md, ARCHITECTURE.md |
| Provides    | GET /rates/{date}, GET /rates/latest |
| Consumes    | rates.list |

## Questions

- None.

## Purpose

Return all rates stored for the latest publication date on or before a requested calendar date. A request before the first publication returns 404. The latest endpoint resolves the latest publication in the store.

## Routes

- `GET /rates/{date}` accepts a real date in `YYYY-MM-DD` format and returns the requested date, effective publication date, EUR base, and rates for that publication.
- `GET /rates/latest` returns the same shape with the requested value set to `latest`.

## Programmatic Acceptance

=== END AC rates-date-route-validates ===

Suite: scoped

from app_server.testing import web_client

=== END AC rates-latest-route-responds ===

## User Acceptance

- None.

## Guardrails

- Resolve requests to the latest publication date on or before the requested date.
- Preserve stored rate text in JSON strings; EUR has the implicit rate 1.
- Return 404 when no effective publication exists.
- A load completed while serving must be visible to the next request.
- Access persistent data only through the shipped persistence library.
