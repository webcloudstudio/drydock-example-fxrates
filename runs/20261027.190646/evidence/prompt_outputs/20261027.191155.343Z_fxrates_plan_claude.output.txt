# FEATURE: ECB History Parse

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Parse and fully validate an ECB euro reference rate history CSV into rate records without writing anything. |
| Depends On | ARCHITECTURE.md, FEATURE-CliFoundation.md |
| Provides | ecb.parse_history |
| Consumes | cli.main |

## Questions

- None.

## Purpose

`ecb.parse_history(text)` turns the text of an ECB `eurofxref-hist.csv` file into rate records. It performs every validation the source requires and touches no database, so a caller can check a whole file before its first write.

## Interface

- Module `ecb` (package `ecb/`), function `parse_history(text: str) -> list`.
- Each record is a `namedtuple` `Rate(date, currency, rate)` of three strings, so it unpacks as a plain 3-tuple. `rate` is the published text exactly as read.
- Records are returned for every non-`N/A` value. Record order is not part of the contract.
- On any violation the function raises `RejectedFile` (the class owned by the CLI foundation, exit code 3) and returns no records.

## Rules

1. The text is CSV. The header's first field is exactly `Date`, and every other field is a three-letter uppercase currency code. The ECB writes a trailing comma on every line; the resulting empty last field is ignored (one empty trailing field, in the header and in every row).
2. Each row has the same field count as the header and begins with a date in `YYYY-MM-DD` form that is a real calendar date and does not repeat elsewhere in the file.
3. Each value is either `N/A` (no rate; nothing is produced) or matches `[0-9]+(\.[0-9]+)?` and is nonzero (`0`, `0.0`, `0.00` are zero).
4. A row with the wrong field count, an invalid or repeated date, or an invalid value rejects the whole file. Validation covers every row before any record is returned.
5. Rate text is kept exactly as published (`1.10` stays `1.10`). No value is converted to a floating-point number; zero is detected with `decimal.Decimal` or by digits.

## Database Interface

- None — this module is pure parsing and reaches no repository.

## Programmatic Acceptance

=== AC ecb-parse-valid ===
Intent: Every non-N/A value becomes one record carrying the published text unchanged, N/A values and the trailing empty field produce nothing, and trailing zeros survive.

import csv
import io
from ecb import parse_history

header = ["Date", "USD", "JPY", "HRK", ""]
rows = [
    ["2025-01-03", "1.0299", "161.77", "N/A", ""],
    ["2025-01-02", "1.0321", "N/A", "N/A", ""],
    ["2025-01-06", "1.10", "162.5", "N/A", ""],
    ["2025-01-07", "N/A", "N/A", "N/A", ""],
]
buf = io.StringIO()
writer = csv.writer(buf, lineterminator="\n")
writer.writerow(header)
for row in rows:
    writer.writerow(row)

records = parse_history(buf.getvalue())
got = sorted((r[0], r[1], r[2]) for r in records)
expected = sorted(
    (row[0], header[i], row[i])
    for row in rows
    for i in range(1, len(header) - 1)
    if row[i] != "N/A"
)
print(got)
assert got == expected
assert all(isinstance(r[2], str) for r in records)
assert ("2025-01-06", "USD", "1.10") in got

import csv
import io
from ecb import parse_history

header = ["Date", "USD", "JPY", ""]
good = ["2025-01-03", "1.0299", "161.77", ""]


def build(head, rows):
    buf = io.StringIO()
    writer = csv.writer(buf, lineterminator="\n")
    writer.writerow(head)
    for row in rows:
        writer.writerow(row)
    return buf.getvalue()

    "short row": [good, ["2025-01-02", "1.0", ""]],
    "long row": [good, ["2025-01-02", "1.0", "2.0", "3.0", ""]],
    "impossible date": [good, ["2025-02-30", "1.0", "2.0", ""]],
    "unpadded date": [good, ["2025-1-2", "1.0", "2.0", ""]],
    "compact date": [good, ["20250102", "1.0", "2.0", ""]],
    "repeated date": [good, ["2025-01-03", "1.5", "2.5", ""]],
    "letters in value": [good, ["2025-01-02", "1.0x", "2.0", ""]],

    "zero decimals": [good, ["2025-01-02", "1.0", "0.00", ""]],

    "comma decimal": [good, ["2025-01-02", "1,5", "2.0", ""]],

# FEATURE: Rate Storage

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Store parsed rate records through the persistence library, replacing any rate already stored for the same date and currency. |
| Depends On | DATABASE.md, ARCHITECTURE.md |
| Provides | ratestore.store_rates |
| Consumes | db.rates.replace_rate |

## Questions

- None.

## Purpose

`ratestore.store_rates(db, records)` writes validated rate records into the `rates` table. It is the only write path for loaded rates and uses the declared upsert so reloading is idempotent.

## Interface

- Module `ratestore`, function `store_rates(db, records) -> tuple[int, int]`.
- `db` is an open persistence `Database`; `records` is any iterable of three-item sequences `(date, currency, rate)` such as `ecb.Rate` tuples.
- Each record is written with `db.rates.replace_rate(date=..., currency=..., rate=...)`.
- The return value is `(dates, rates)`: the number of distinct dates and the number of rates written from `records`.
- Empty `records` writes nothing and returns `(0, 0)`.
- The function neither opens nor closes the database and authors no SQL.

## Rules

1. A rate stored for a (`date`, `currency`) that already exists replaces the stored text.
2. Writing the same records again leaves the stored rows unchanged and returns the same counts.
3. Rate text is stored exactly as given.

## Database Interface

- `FEATURE-RATE-001` — write: store a rate, replacing the stored one - supplies: `date`, `currency`, `rate` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

# FEATURE: Atomic Load

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implement fxrates load, which validates the whole ECB history file before its first write and stores nothing when the file is rejected. |
| Depends On | FEATURE-CliFoundation.md, FEATURE-Init.md, FEATURE-EcbParse.md, FEATURE-RateStorage.md |
| Provides | fxrates load |
| Consumes | ecb.parse_history, ratestore.store_rates, cli.main, fxrates init |

## Questions

- None.

## Purpose

`fxrates load <csv>` loads an ECB history file into the store. The whole file is checked before the first write, so a rejected file changes nothing, and a rate already stored for the same date and currency is replaced.

## Interface

- `cli/commands/load.py` defines `load_file(path: str) -> tuple[int, int]` and `run(args) -> int`.
- `load_file` reads the file as UTF-8 text. A file that cannot be read raises `OperationalError` (exit 1).
- It calls `ecb.parse_history` on the full text. An invalid file raises `RejectedFile` (exit 3) before the database is opened for writing.
- It opens the store with `persistence.open_database(config.database_path())`, calls `ratestore.store_rates`, closes the database, and returns the `(dates, rates)` counts.
- `run` calls `load_file` and returns 0. Printing the summary is owned by FEATURE-LoadSummary.md; this story prints nothing to stdout on success.
- Failure output follows the dispatcher: nothing on stdout, one diagnostic line on stderr.

## Rules

1. Exit 0 on success, 1 when the file cannot be read, 3 when the file is rejected.
2. A rejected file leaves the database exactly as it was, including rows for dates the file shares with the store.
3. Loading the same file twice leaves the database unchanged.

## Database Interface

- None — persistence is reached through `ratestore.store_rates`.

## Programmatic Acceptance

# FEATURE: Load Summary

## Questions

- None.

## Purpose

After a successful `fxrates load`, standard output reports how many dates and rates the file contributed to the store.

## Interface

- `cli/commands/load.py` `run(args)` prints, after `load_file` returns `(dates, rates)`, exactly two lines: `dates,rates` and then `<dates>,<rates>`, each newline-terminated.
- `dates` counts the dates in the file with at least one stored rate. A date whose values are all `N/A` is not counted.
- `rates` counts the rates stored from the file. These are counts from the file, not changes: loading the same file again prints the same numbers.
- On failure (exit 1, 2 or 3) nothing is written to standard output.

## Database Interface

- None — the counts come from `load_file`'s return value.

## Programmatic Acceptance

# FEATURE: Fetch

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Implement fxrates fetch, which downloads the ECB history zip, extracts the CSV and loads it exactly as load does, testable with a stubbed download. |
| Depends On | FEATURE-LoadSummary.md, FEATURE-EcbParse.md |
| Provides | fxrates fetch |
| Consumes | fxrates load summary output, ecb.parse_history |

## Questions

- None.

## Purpose

`fxrates fetch` retrieves the ECB's published history file and loads it with the same validation, atomicity, storage and summary as `fxrates load`.

## Interface

- `ecb.download_history() -> str` performs the whole download. It calls `urllib.request.urlopen("https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip", timeout=...)` through the module attribute, reads the bytes inside a `with` block, opens them with `zipfile`, and returns the decoded text of the member `eurofxref-hist.csv`.
- Any failure (network error, non-zip data, missing member) raises `OperationalError` (exit 1).
- `cli/commands/fetch.py` `run(args)` calls `ecb.download_history()` through the module attribute `ecb`, so tests can replace it, then runs the same parse, store and summary path as `load` on that text (sharing a text-level helper with `load`). It takes no arguments.
- Exit codes follow `load`: 0 success, 1 download failure, 3 rejected file. Failures write nothing to stdout and one diagnostic line to stderr.
- Automated tests never open a network connection: they replace `ecb.download_history`, or replace `urllib.request.urlopen`.

## Database Interface

- None — storage is reached through the shared load path.

=== AC fetch-zip-extraction ===
Intent: With only the HTTP call replaced, fetch extracts eurofxref-hist.csv from the zip and loads it, while a zip lacking that member exits 1.
Requires: executable=python3; scope=test

import csv
import io
import zipfile
from unittest import mock
from cli.testing import cli_runner
from persistence.testing import db_session


class FakeResponse:
    def __init__(self, data):
        self._data = data

    def read(self, *args):
        return self._data

    def __enter__(self):
        return self

    def __exit__(self, *exc):
        return False


def make_zip(member, text):
    raw = io.BytesIO()
    with zipfile.ZipFile(raw, "w") as zf:
        zf.writestr(member, text)
    return raw.getvalue()


d = "1800-08-10"
header = ["Date", "ZZA", ""]
row = [d, "6.75", ""]
buf = io.StringIO()
writer = csv.writer(buf, lineterminator="\n")
writer.writerow(header)
writer.writerow(row)
text = buf.getvalue()

good = FakeResponse(make_zip("eurofxref-hist.csv", text))
with mock.patch("urllib.request.urlopen", return_value=good):
    code, out, err = cli_runner("fetch")
print(out, err)
assert code == 0
with db_session() as db:
    back = db.rates.history(currency="ZZA", start_date=d, end_date=d)
    assert [(r.date, r.rate) for r in back] == [(d, row[1])]

wrong = FakeResponse(make_zip("other.csv", text))
with mock.patch("urllib.request.urlopen", return_value=wrong):
    code, out, err = cli_runner("fetch")
assert code == 1
assert out == ""
