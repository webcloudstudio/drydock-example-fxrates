# FEATURE: Effective Date

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Service function that resolves the latest publication date on or before a requested date and returns that date's rates. |
| Depends On | DATABASE.md, ARCHITECTURE.md |
| Provides | rates.effective_publication |
| Consumes | db.rates.list_through |

## Questions

- None.

## Purpose

The ECB publishes on working days only. A request for date `D` uses the latest publication date on or
before `D`. This service is the single place that rule lives; the rates and conversion routes call it.

## Interface

Module `services/effective_date.py` (a top-level `services` package):

`effective_publication(db, requested: str | None) -> tuple[str, dict[str, str]] | None`

- `requested` is an ISO `YYYY-MM-DD` string, or `None` meaning the latest publication.
- Makes exactly one `db.rates.list_through(...)` call: with `through_date=requested` when a date is given,
  with no bound when `None`.
- The rows arrive ordered by date descending then currency ascending. The first row's date is the
  effective date. The rates are the rows carrying that date, as a mapping of currency code to stored rate text.
- Returns `None` when no row exists on or before the requested date.
- Dates are compared as ISO strings. Rate values are the stored text, never converted to a number.

## Database Interface

- `FEATURE-RATE-002` — read: list rates on or before a date - supplies: `through_date` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

=== AC effective-date-exact-and-between ===
Intent: A requested date that is a publication uses itself, and a later requested date uses the latest earlier publication; only the effective date's rates are returned as stored text.
Requires: executable=python3; scope=test

from persistence.testing import db_session
from services.effective_date import effective_publication

older = "1800-05-08"
newer = "1800-05-10"
later_request = "1800-05-12"
older_rates = {"ZZA": "1.1000", "ZZB": "9.9"}
newer_rates = {"ZZA": "2.2500", "ZZB": "8.8", "ZZC": "7"}

with db_session() as db:
    for cur, rate in older_rates.items():
        db.rates.replace_rate(date=older, currency=cur, rate=rate)
    for cur, rate in newer_rates.items():
        db.rates.replace_rate(date=newer, currency=cur, rate=rate)

    found = effective_publication(db, newer)
    assert found is not None
    date, rates = found
    assert date == newer
    assert rates == newer_rates

    found = effective_publication(db, later_request)
    assert found is not None
    date, rates = found
    assert date == newer
    assert rates == newer_rates

    found = effective_publication(db, "1800-05-09")
    assert found is not None
    date, rates = found
    assert date == older
    assert rates == older_rates

# FEATURE: Rates By Date

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Serve GET /rates/{date}, returning every currency's rate on the effective publication date. |
| Depends On | FEATURE-WebFoundation.md, FEATURE-EffectiveDate.md |
| Provides | GET /rates/{date} |
| Consumes | rates.effective_publication |

## Questions

- None.

## Purpose

`GET /rates/{date}` answers what the euro reference rates were on a date, falling back to the latest
publication on or before it.

## Routes

| Route | Behavior |
|-------|----------|
| `GET /rates/{date}` | 200 with `{"date": <effective date>, "requested": <date>, "base": "EUR", "rates": {<code>: <rate>, ...}}`. Rates are the stored text as JSON strings. 404 when no publication is on or before the date. 422 when the path date is malformed. |

- The path date must match `YYYY-MM-DD` and be a real calendar date; otherwise respond 422 through
  FastAPI request validation.
- The effective date and rates come from `services.effective_date.effective_publication`.

## Database Interface

- None — persistence is reached through `rates.effective_publication` in FEATURE-EffectiveDate.md.

# FEATURE: Convert

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Serve GET /convert for an explicit date, converting an amount between two currencies with exact decimal arithmetic. |
| Depends On | FEATURE-WebFoundation.md, FEATURE-EffectiveDate.md |
| Provides | GET /convert |
| Consumes | rates.effective_publication |

## Questions

- None.

## Purpose

Convert an amount from one currency to another using the euro reference rates on the effective date.

## Routes

| Route | Behavior |
|-------|----------|
| `GET /convert?from=<code>&to=<code>&amount=<amount>&date=<date>` | 200 with `{"date": <effective date>, "from": <code>, "to": <code>, "amount": <amount>, "rate": <rate>, "result": <result>}`; every value is a JSON string. |

## Behavior

- The router lives in `app_server/routers/convert.py`, included by `create_app()`. Parameters are
  `from` (Python name via alias), `to`, `amount` and `date`.
- The effective date and rates come from `services.effective_date.effective_publication`.
- EUR has the implicit rate `1`; any other currency takes its stored rate on the effective date.
- All arithmetic uses `decimal.Decimal` from the stored text. Never use floats.
- `rate` = `rate(to) / rate(from)`, rounded half to even to six decimals, written with exactly six decimals.
- `result` = `amount * rate(to) / rate(from)`, computed from the stored rates and never from the rounded
  `rate`, rounded half to even to two decimals, written with exactly two decimals.
- `amount` is echoed exactly as given, as a string, and must match `[0-9]+(\.[0-9]+)?`.
- Handling of missing publications, unknown currencies and invalid parameters is specified by
  FEATURE-ConvertErrors.md; this story implements the successful conversion.

## Database Interface

- None — persistence is reached through `rates.effective_publication` in FEATURE-EffectiveDate.md.

## Programmatic Acceptance

=== AC convert-cross-currency-fallback-date ===
Intent: A cross conversion on a non-publication date uses the earlier effective date and returns rate and result derived from the stored rates with half-even rounding.
Requires: executable=python3; scope=test
Requires: python-package=fastapi; scope=test
Requires: python-package=httpx2; scope=test

from decimal import Decimal, ROUND_HALF_EVEN
from persistence.testing import db_session
from app_server.testing import web_client

published = "1800-07-01"
requested = "1800-07-05"
from_cur, to_cur = "ZZA", "ZZB"
from_rate, to_rate = "1.0298", "0.84453"
amount = "100"

with db_session() as db:
    db.rates.replace_rate(date=published, currency=from_cur, rate=from_rate)
    db.rates.replace_rate(date=published, currency=to_cur, rate=to_rate)
    client = web_client()
    response = client.get(
        "/convert",
        params={"from": from_cur, "to": to_cur, "amount": amount, "date": requested},
    )
    assert response.status_code == 200
    body = response.json()

    rf, rt, amt = Decimal(from_rate), Decimal(to_rate), Decimal(amount)
    rate = (rt / rf).quantize(Decimal("0.000001"), rounding=ROUND_HALF_EVEN)
    result = (amt * rt / rf).quantize(Decimal("0.01"), rounding=ROUND_HALF_EVEN)
    assert body["date"] == published
    assert body["from"] == from_cur
    assert body["to"] == to_cur
    assert body["amount"] == amount
    assert body["rate"] == f"{rate:.6f}"
    assert body["result"] == f"{result:.2f}"
=== END AC convert-cross-currency-fallback-date ===
