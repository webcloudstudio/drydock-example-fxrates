# ARCHITECTURE: FxRates

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Modules, boundaries, configuration resolution and test runner for the FxRates currency rates service. |
| Depends On | DATABASE.md |
| Provides | config.database_path, bin/test.sh |

## Questions

- None.

## Purpose

FxRates keeps the ECB euro reference rate history in SQLite. A command line (`fxrates init`, `load`, `fetch`, `serve`) fills and runs it, and a FastAPI JSON API serves rates on a date, conversions and currency history. The product is an executable named `fxrates` at the application root.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file is the decision of record.

| Technology | Where it applies |
|------------|------------------|
| Python 3.11+ | All application code. |
| FastAPI served by uvicorn | The `app_server` package, bound to 127.0.0.1. |
| SQLite | The one store, reached only through the shipped `persistence` package. |
| CLI | The `cli` package and the `fxrates` executable. |
| pytest | The test suite behind `bin/test.sh`; FastAPI `TestClient` for the API. |
| ECB reference rates | Input format: `eurofxref-hist.csv`, downloaded as `eurofxref-hist.zip`. |
| POSIX sh | `bin/test.sh` and the launchers in `bin/`. |

## Project Root

| Item | Rule |
|------|------|
| `pyproject.toml` | Python 3.11 or newer; dependencies fastapi, uvicorn, pytest, httpx2. |
| `uv.lock` | Committed. |
| `.venv` | Created by `uv venv`; activated by the launchers in `bin/`. |
| `bin/test.sh` | POSIX sh. Runs `pytest -q` from the application root and exits nonzero when any test fails. |
| `fxrates` | Executable at the application root; owned by the CLI foundation. |
| `sources/` | Read-only scoring assets; never modified and never read by application code. |

## Modules and Ownership

| Boundary | Owning module | Allowed low-level access |
|----------|---------------|--------------------------|
| Configuration | `config.py` (`database_path()`) | Environment variables `DATABASE_URL`, `DATABASE_PATH`. |
| Persistence | `persistence/` (shipped and generated) | The only code that imports a database driver. |
| Command line | `cli/` | Calls `persistence` and services; never a driver. |
| HTTP API | `app_server/` | Opens the store per request through `persistence.open_database`. |
| ECB parsing and download | `ecb` module (later stories) | Network access only in `ecb.download_history`. |
| File store | none | The loader reads one CSV path given on the command line. |
| External services | `ecb.download_history` | One GET of the ECB zip; stubbed in every test. |

## Configuration

`config.database_path()` resolves the database location in this order: `DATABASE_URL` (a file path, optionally prefixed `sqlite://`), then `DATABASE_PATH`, then `data/app.db`. An unset or empty variable is skipped. The function reads the environment on every call.

## Technical Decisions

- Rates are stored as the ECB's published text and all arithmetic uses `decimal`; floating point is never used for a rate.
- Only `fxrates init` creates the schema, through `persistence.initialize_database(dsn)`. Ordinary opens never initialize.
- Diagnostics go to standard error and are never compared. A failing command writes nothing to standard output.
- Exit codes: 0 success, 1 operational failure, 2 usage error, 3 rejected file.
- Tests stub the ECB download and never open a network connection.

# FEATURE: CLI Foundation

## Questions

- None.

## Purpose

Provide the command-line entry point every command story plugs into without editing shared files.

## Interface

| Symbol | Contract |
|--------|----------|
| `cli.main(argv: list[str] \| None = None) -> int` | Dispatches `argv` (default `sys.argv[1:]`) and returns the exit code. |
| `cli.testing.cli_runner(*args) -> (code, stdout, stderr)` | Calls `main` in process with output captured. |
| `cli.errors` | `OperationalError` (`exit_code` 1), `UsageError` (2), `RejectedFile` (3); each subclasses `Exception`. |
| `cli.dispatch.execute(handler, args) -> int` | Calls `handler(args)`; returns its integer result, or maps a raised error to its `exit_code`, writing one diagnostic line to stderr and nothing to stdout. |
| `cli.commands.<name>.run(args) -> int` | Handler contract. The dispatcher imports the module for the first argument and calls `run` with the remaining arguments, so command stories add modules only. A command whose module cannot be imported is a `UsageError`. |
| `fxrates` | Executable at the application root: activates `.venv` when present and calls `cli.main`, exiting with its result. |

## Database Interface

- None — persistence is owned by DATABASE.md.

=== AC dispatch-exit-codes ===
Intent: execute maps a clean handler to its result and each error class to exit codes 1, 2 and 3, with empty stdout and a single stderr line.
Requires: executable=python3; scope=test

import contextlib
import io

from cli.dispatch import execute
from cli.errors import OperationalError, RejectedFile, UsageError

assert OperationalError.exit_code == 1
assert UsageError.exit_code == 2
assert RejectedFile.exit_code == 3


def raiser(exc):
    def handler(args):
        raise exc
    return handler


def run(handler):
    out, err = io.StringIO(), io.StringIO()
    with contextlib.redirect_stdout(out), contextlib.redirect_stderr(err):
        code = execute(handler, [])
    return code, out.getvalue(), err.getvalue()


code, out, err = run(lambda args: 0)
assert code == 0
assert out == ""

for cls in (OperationalError, UsageError, RejectedFile):
    code, out, err = run(raiser(cls("probe failure")))
    assert code == cls.exit_code
    assert out == ""
    assert len(err.strip().splitlines()) == 1
=== END AC dispatch-exit-codes ===

# FEATURE: Init Command

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | The fxrates init command creates missing tables and indexes and preserves stored rates. |
| Depends On | FEATURE-CliFoundation.md, DATABASE.md |
| Provides | fxrates init |
| Consumes | cli.main, config.database_path |

## Questions

- None.

## Purpose

Initialize the rates store explicitly; it is the only place the schema is created.

## Behavior

`cli/commands/init.py` exposes `run(args) -> int`. It calls `persistence.initialize_database(dsn)` with the location from `config.database_path()`, closes the returned database, writes nothing to standard output and returns 0. Repeating init succeeds and preserves every stored rate. It never drops a table, deletes a row or migrates an existing table, and application code contains no DDL.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance

=== AC init-fresh-store ===
Intent: init on a fresh store exits 0 with empty stdout and leaves a store whose rates operations work.
Requires: executable=python3; scope=test

from cli.testing import cli_runner
from drydock_acceptance import database_environment
from persistence import open_database

date, currency, rate = "1800-05-01", "ZZA", "1.2300"

with database_environment(url="init.db") as root:
    code, out, err = cli_runner("init")
    assert code == 0
    assert out == ""
    db = open_database(str(root / "init.db"))
    try:
        stored = db.rates.replace_rate(date=date, currency=currency, rate=rate)
        assert stored.rate == rate
        rows = db.rates.history(currency=currency)
        assert [(r.date, r.rate) for r in rows] == [(date, rate)]
    finally:
        db.close()
=== END AC init-fresh-store ===

=== AC init-repeat-preserves ===
Intent: Running init again succeeds and leaves previously stored rates unchanged.
Requires: executable=python3; scope=test

from cli.testing import cli_runner
from drydock_acceptance import database_environment
from persistence import open_database

points = [("1800-06-01", "3.10"), ("1800-06-02", "4.5")]

    db = open_database(str(root / "repeat.db"))

    assert out == ""

    try:
        rows = db.rates.history(currency=currency)
        assert [(r.date, r.rate) for r in rows] == sorted(points)
    finally:
        db.close()

# FEATURE: Usage Errors

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Command-line argument validation that reports usage errors with exit status 2 before any handler runs. |
| Depends On | FEATURE-CliFoundation.md |
| Provides | fxrates usage validation |
| Consumes | cli.main |

## Questions

- None.

## Purpose

Reject malformed invocations uniformly and hand valid ones to handlers as parsed values.

## Behavior

`cli.usage.parse(argv) -> (name, args)` validates before any handler runs and raises `cli.errors.UsageError` on a violation. `main` calls it first, so a usage error exits 2 with one stderr line and empty stdout.

| Command | Accepted arguments | `args` handed to `run` |
|---------|--------------------|------------------------|
| `init` | none | `[]` |
| `fetch` | none | `[]` |
| `load` | exactly one path | `[path]` |
| `serve` | optional `--port <n>`, `n` an integer, default 8000 | `[port]` with `port` an `int` |

No command, an unknown command, the wrong argument count, an unknown option, or a `--port` value that is missing or not an integer is a usage error.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance
