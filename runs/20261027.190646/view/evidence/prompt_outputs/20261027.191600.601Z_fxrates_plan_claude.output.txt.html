# FEATURE: Convert Errors

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Error statuses of GET /convert: 404 for a missing publication or rate and 422 for malformed or missing parameters. |
| Depends On | FEATURE-ConvertLatest.md |
| Provides | GET /convert errors |
| Consumes | GET /convert latest default |

## Questions

- None.

## Purpose

`GET /convert` refuses requests it cannot answer with the status the source defines. Decisions recorded: EUR to EUR still needs a publication on or before the effective date (Q-004).

## Routes

| Route | Condition | Status |
|-------|-----------|--------|
| `GET /convert` | No publication on or before the requested date | 404 |
| `GET /convert` | A currency other than EUR has no rate on the effective date | 404 |
| `GET /convert` | `amount` does not match `[0-9]+(\.[0-9]+)?` | 422 |
| `GET /convert` | Malformed `date`, or `from`, `to` or `amount` missing | 422 |

## Behavior

- Validation is FastAPI request validation; the 422 comes from the framework, not hand-built responses.
- EUR has the implicit rate `1` and never needs a stored rate, but the effective date must exist.
- The effective date is resolved first from the requested date, then each non-EUR currency is looked up on it.
- Error response bodies are not part of the contract.

## Database Interface

- None — persistence is owned by DATABASE.md.

# FEATURE: History

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | GET /history/{code} returns a currency's rates over a period with exact minimum, maximum and mean. |
| Depends On | DATABASE.md, FEATURE-WebFoundation.md |
| Provides | GET /history/{code} |
| Consumes | db.rates.history |

## Questions

- None.

## Purpose

Report one currency's stored rates between optional inclusive `start` and `end` dates, with statistics computed exactly from the stored text.

## Routes

| Route | Response 200 |
|-------|--------------|
| `GET /history/{code}[?start=<date>][&end=<date>]` | `{"currency", "base": "EUR", "count", "min", "max", "mean", "points": [{"date", "rate"}, ...]}` |

## Behavior

- Points come from `db.rates.history` ascending by date; both bounds are inclusive and optional.
- `count` is the number of points.
- `min` and `max` are the stored text of the smallest and largest rate by `Decimal` value, not by string order.
- `mean` is the exact `Decimal` mean of the point rates, rounded half to even to six decimals and written with exactly six decimals, as a JSON string.
- Point `rate` values are the stored text as JSON strings.
- Empty ranges and unknown currencies are owned by later stories (FEATURE-HistoryEmpty.md, FEATURE-HistoryRejects.md).

## Database Interface

- `FEATURE-RATE-004` — read: list a currency's history over a period - supplies: `currency`, `start_date`, `end_date` - returns: `date`, `rate`

## Programmatic Acceptance

# FEATURE: Live Visibility

| Field | Value |
|-------|-------|
| Version | 20261027 V1 |
| Description | Integration proof that a load completed while the application is running is visible to the next request. |
| Depends On | FEATURE-Serve.md, FEATURE-Stats.md, FEATURE-LoadSummary.md |
| Provides | live load visibility |
| Consumes | GET /stats, fxrates load, fxrates serve |

## Questions

- None.

## Purpose

Assembly and intent: each request opens its own database handle through `persistence.open_database`, so a load committed after the app was created is reflected by the next `/stats` and `/rates/latest` request. Fix any seam that breaks this; no new interface is introduced.

## Routes

| Route | Role |
|-------|------|
| `GET /stats` | Counts and first/last dates reflect a load made after the app was created |
| `GET /rates/latest` | Latest publication reflects a load made after the app was created |

## Behavior

- The web client is created once, before the load; a long-lived connection or cached result would hide the load and fail this feature.
- Loading goes through the `load` command, not direct repository writes.
- Reloading changed rates replaces them and the next request shows the new values.

## Database Interface

- None — persistence is owned by DATABASE.md.

## Programmatic Acceptance
