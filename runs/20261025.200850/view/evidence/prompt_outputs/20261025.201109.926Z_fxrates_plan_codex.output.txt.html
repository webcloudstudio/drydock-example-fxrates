# FEATURE: ECB Fetch

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Downloads the ECB history archive and loads its CSV through the existing load workflow. |
| Depends On  | FEATURE-ECB-Loading.md |
| Provides    | fxrates fetch |
| Consumes    | fxrates load |

## Questions

- None.

## Purpose

Fetch the ECB history archive, extract `eurofxref-hist.csv`, and delegate its contents to the established load workflow.

## Trigger and Sequence

`fxrates fetch` downloads `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip`, extracts `eurofxref-hist.csv`, and loads it using the same validation, replacement, reporting, and exit-code behavior as `fxrates load`.

A download failure is an operational failure: exit `1`, no standard output, and one diagnostic line on standard error. Tests replace the downloader with a stub; they do not use the network.

## Programmatic Acceptance

=== AC fetch-command ===
Intent: The fetch command is available and reports operational failure when the stubbed downloader fails.

from cli.testing import cli_runner
import cli.fetch as fetch_module

def fail_download():
    raise OSError("stubbed download failure")

fetch_module.download_archive = fail_download
code, stdout, stderr = cli_runner("fetch")
assert code == 1
assert stdout == ""
assert stderr.count("\n") == 1
=== END AC fetch-command ===

=== AC fetch-stubbed-archive-load ===
Intent: A stubbed archive is extracted and passed to the load workflow without network access.

from cli.testing import cli_runner
import cli.fetch as fetch_module
import io
import zipfile
from persistence.testing import db_session

csv_data = "Date,USD,\n2099-01-02,1.2300,\n"
archive = io.BytesIO()
with zipfile.ZipFile(archive, "w") as zipped:
    zipped.writestr("eurofxref-hist.csv", csv_data)
archive_bytes = archive.getvalue()
fetch_module.download_archive = lambda: archive_bytes

with db_session() as db:
    before = len(db.rates.list())
code, stdout, stderr = cli_runner("fetch")
assert code == 0
assert stderr == ""
with db_session() as db:
    rows = db.rates.list(currency="USD")
stored = next(row for row in rows if row.date == "2099-01-02")
assert stored.rate == "1.2300"
=== END AC fetch-stubbed-archive-load ===

## Guardrails

- Tests stub the downloader and never open a network connection.
- Use the existing load workflow so validation, atomicity, replacement, and summary behavior remain consistent.
- Do not modify files under `sources/`.

## Purpose

Expose health and database-derived summaries through the JSON API.

## Routes

- `GET /health` returns status 200 and `{"status":"ok"}`.

## Database Interface

# FEATURE: Effective Rates

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Retrieves published rates for a requested date or the latest available publication. |
| Depends On  | FEATURE-API-Foundation.md, DATABASE.md |
| Provides    | GET /rates/{date}, GET /rates/latest |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Return the rates for the latest publication date on or before a requested calendar date, or the latest publication for the dedicated latest route.

## Routes

- `GET /rates/{date}` accepts a real `YYYY-MM-DD` date. It returns the effective publication date, echoes the requested date, base `EUR`, and all rates on that publication date.
- `GET /rates/latest` returns the latest publication with `"requested": "latest"`.
- A date before the first publication returns 404. A malformed date returns 422.

## Database Interface

- `FEATURE-RATE-003` — read: list stored rates - supplies: `currency`, `start_date`, `end_date` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

# FEATURE: Currency Conversion

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Converts an amount between currencies using effective ECB rates and exact decimal arithmetic. |
| Depends On  | FEATURE-API-Foundation.md, DATABASE.md |
| Provides    | GET /convert |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Convert an amount from one currency to another using EUR as the base. If `date` is omitted, use the latest publication.

## Request and Response

`GET /convert` requires `from`, `to`, and `amount`, with optional `date`. Amounts must match `[0-9]+(\.[0-9]+)?` and are echoed as supplied. The response includes effective date, source and target currencies, amount, conversion rate, and result as strings.

Compute the conversion rate as `rate(to) / rate(from)` using exact decimal arithmetic, rounded half to even to six decimal places. Compute the result from the unrounded rates, rounded half to even to two decimal places. Return 404 when no effective publication exists or a non-EUR currency has no rate on that date. Malformed dates, amounts, or missing required parameters return 422.

## Database Interface

- `FEATURE-RATE-003` — read: list stored rates - supplies: `currency`, `start_date`, `end_date` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance

# FEATURE: Currency History

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Retrieves a currency's ordered rate points and exact summary statistics over optional date bounds. |
| Depends On  | FEATURE-API-Foundation.md, DATABASE.md |
| Provides    | GET /history/{code} |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Return a currency's stored publication points in ascending date order, optionally restricted by inclusive `start` and `end` dates.

## Request and Response

For a currency with rates, return currency code, base `EUR`, point count, published-text minimum and maximum by numeric value, six-place half-even mean text, and ordered points. If filters select no points, return count zero with null min, max, and mean and an empty point list. A currency with no stored rate at all, including EUR, returns 404. Malformed date bounds return 422.

## Database Interface

- `FEATURE-RATE-003` — read: list stored rates - supplies: `currency`, `start_date`, `end_date` - returns: `date`, `currency`, `rate`

## Programmatic Acceptance
