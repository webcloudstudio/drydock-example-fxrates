# FEATURE: Effective-Date Rates

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Resolves requested and latest publication dates to their stored ECB rates. |
| Depends On  | FEATURE-API-Foundation.md, DATABASE.md |
| Provides    | GET /rates/{date}, GET /rates/latest |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Expose the ECB rates for a requested date using the latest publication on or before that date. Also expose the latest publication directly.

## Routes

| Method | Path | Behavior |
|--------|------|----------|
| GET | `/rates/{date}` | Resolve the effective publication date and return its rates. |
| GET | `/rates/latest` | Return rates from the latest publication, with `requested` set to `latest`. |

The response includes the effective `date`, the original `requested` value, `base` set to `EUR`, and a `rates` object containing every currency stored for the effective date. Rate values remain strings exactly as stored.

If no publication exists on or before the requested date, return 404.

## Programmatic Acceptance

=== AC date-resolves-to-effective-publication ===
Intent: The requested-date route returns the effective stored publication and preserves the requested date.

from persistence.testing import db_session
from app_server.testing import web_client

date = "2098-01-02"
requested = "2098-01-03"
currency = "ZZZ"
rate = "7.654321"
with db_session() as db:
    db.rates.upsert(date=date, currency=currency, rate=rate)

client = web_client()
response = client.get(f"/rates/{requested}")
assert response.status_code == 200
body = response.json()
assert body["date"] == date
assert body["requested"] == requested
assert body["base"] == "EUR"
assert body["rates"][currency] == rate
=== END AC date-resolves-to-effective-publication ===

=== AC latest-rates-route-works ===
Intent: The latest route returns a successful response and the latest stored publication.

from persistence.testing import db_session
from app_server.testing import web_client

date = "2098-02-04"
currency = "ZZY"
rate = "8.765432"
with db_session() as db:
    db.rates.upsert(date=date, currency=currency, rate=rate)

client = web_client()

assert response.status_code == 200
body = response.json()
assert body["date"] == date
assert body["requested"] == "latest"
assert body["base"] == "EUR"
assert body["rates"][currency] == rate
=== END AC latest-rates-route-works ===

=== AC no-publication-before-date-is-not-found ===
Intent: A date with no earlier stored publication returns 404.

from app_server.testing import web_client

response = web_client().get("/rates/1900-01-01")
assert response.status_code == 404
=== END AC no-publication-before-date-is-not-found ===

## User Acceptance

- None.

## Guardrails

- Effective-date lookup uses stored publication dates and never a hardcoded rate, date, or computed answer.
- EUR is the implicit base; only stored currencies with rates for the effective publication are returned.

# FEATURE: Currency Conversion

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Converts an amount between currencies using exact decimal arithmetic. |
| Depends On  | FEATURE-API-Foundation.md, DATABASE.md |
| Provides    | GET /convert |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Convert an amount from one currency to another at the latest effective publication date, or at the latest publication on or before an optional requested date.

## Route

`GET /convert?from=<code>&to=<code>&amount=<amount>[&date=<date>]`

The response contains the effective date, the supplied `from`, `to`, and `amount`, plus `rate` and `result`. `amount` is echoed as a string. The rate is `rate(to) / rate(from)`, rounded to six decimal places using half-even rounding. The result is calculated directly from the stored rates and amount, not from the rounded rate, then rounded to two decimal places using half-even rounding. Both computed values are strings with fixed decimal places.

EUR has an implicit rate of one. A non-EUR currency without a rate on the effective date returns 404. Malformed amounts, malformed dates, or missing required query parameters return 422.

## Programmatic Acceptance

=== AC convert-route-returns-computed-values ===
Intent: The conversion route returns the echoed inputs and values derived from the supplied rates.

from decimal import Decimal, ROUND_HALF_EVEN
from persistence.testing import db_session
from app_server.testing import web_client

date = "2098-03-04"
source_currency = "ZZX"
target_currency = "ZZW"
source_rate_text = "3.125"
target_rate_text = "6.75"
amount_text = "10.10"
with db_session() as db:
    db.rates.upsert(date=date, currency=source_currency, rate=source_rate_text)
    db.rates.upsert(date=date, currency=target_currency, rate=target_rate_text)

client = web_client()
response = client.get(
    "/convert",
    params={"from": source_currency, "to": target_currency, "amount": amount_text, "date": date},
)
assert response.status_code == 200
body = response.json()
expected_rate = (Decimal(target_rate_text) / Decimal(source_rate_text)).quantize(
    Decimal("0.000001"), rounding=ROUND_HALF_EVEN
)
expected_result = (Decimal(amount_text) * Decimal(target_rate_text) / Decimal(source_rate_text)).quantize(
    Decimal("0.01"), rounding=ROUND_HALF_EVEN
)
assert body["date"] == date
assert body["from"] == source_currency
assert body["to"] == target_currency
assert body["amount"] == amount_text
assert body["rate"] == f"{expected_rate:.6f}"
assert body["result"] == f"{expected_result:.2f}"
=== END AC convert-route-returns-computed-values ===

=== AC euro-conversion-uses-implicit-unit-rate ===
Intent: EUR conversions use the implicit unit rate without requiring an EUR row.

from persistence.testing import db_session
from app_server.testing import web_client

date = "2098-03-05"
currency = "ZZV"
rate = "2.5"
amount = "4"
with db_session() as db:
    db.rates.upsert(date=date, currency=currency, rate=rate)

response = web_client().get(
    "/convert", params={"from": "EUR", "to": currency, "amount": amount, "date": date}
)
assert response.status_code == 200
body = response.json()
assert body["amount"] == amount
assert body["rate"] == rate + "0" * (6 - len(rate.rsplit(".", 1)[1])) + ("0.000000" if "." not in rate else "")
=== END AC euro-conversion-uses-implicit-unit-rate ===

## User Acceptance

- None.

## Guardrails

- Use `decimal.Decimal` for rate and amount arithmetic, never binary floating point.
- Compute the result from unrounded source and target rates, independently of the rounded response rate.

# FEATURE: Currency History

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Returns bounded currency rate history with exact summary statistics. |
| Depends On  | FEATURE-API-Foundation.md, DATABASE.md |
| Provides    | GET /history/{code} |
| Consumes    | rates repository operations |

## Questions

- None.

## Purpose

Return publication points for a currency, optionally bounded by inclusive `start` and `end` dates. Points are ordered by publication date ascending. The response includes `currency`, `base` (`EUR`), `count`, `min`, `max`, `mean`, and `points`.

`min` and `max` are the stored text of the smallest and largest rate by numeric value. `mean` is calculated exactly and rounded half-even to six decimal places, with exactly six decimals in its string representation. When the requested bounds contain no points, return count zero, null summary values, and an empty points array. A currency with no stored history at all returns 404.

## Programmatic Acceptance

=== AC history-route-returns-bounded-summary ===
Intent: The history route returns the supplied points and summary derived from their rates.

from decimal import Decimal, ROUND_HALF_EVEN
from persistence.testing import db_session
from app_server.testing import web_client

currency = "ZZU"
dates = ["2098-04-01", "2098-04-03"]
rates = ["1.25", "2.75"]
with db_session() as db:
    for date, rate in zip(dates, rates):
        db.rates.upsert(date=date, currency=currency, rate=rate)

response = web_client().get(
    f"/history/{currency}", params={"start": dates[0], "end": dates[-1]}
)
assert response.status_code == 200
body = response.json()
expected_mean = (sum((Decimal(value) for value in rates), Decimal(0)) / len(rates)).quantize(
    Decimal("0.000001"), rounding=ROUND_HALF_EVEN
)
assert body["currency"] == currency
assert body["base"] == "EUR"
assert body["count"] == len(dates)
assert body["min"] == min(rates, key=Decimal)
assert body["max"] == max(rates, key=Decimal)
assert body["mean"] == f"{expected_mean:.6f}"
assert [point["date"] for point in body["points"]] == dates
assert [point["rate"] for point in body["points"]] == rates
=== END AC history-route-returns-bounded-summary ===

=== AC history-route-empty-range ===
Intent: A currency with stored history returns the declared empty summary for a range with no points.

from persistence.testing import db_session
from app_server.testing import web_client

currency = "ZZT"
date = "2098-04-05"
rate = "1.25"
with db_session() as db:
    db.rates.upsert(date=date, currency=currency, rate=rate)

response = web_client().get(f"/history/{currency}", params={"start": "2098-04-06"})
assert response.status_code == 200
body = response.json()
assert body["count"] == 0
assert body["min"] is None
assert body["max"] is None
assert body["mean"] is None
assert body["points"] == []

# FEATURE: API Request Validation

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Applies request validation statuses for malformed API input and unknown currencies. |
| Depends On  | FEATURE-Rates.md, FEATURE-Convert.md, FEATURE-History.md |
| Provides    | API request validation behavior |
| Consumes    | GET /rates/{date}, GET /convert, GET /history/{code} |

## Questions

- None.

## Purpose

Malformed dates in a route or query, malformed conversion amounts, and missing required conversion parameters return 422. Unknown currencies return 404. Error response bodies are not part of this contract.

Validation applies to `/rates/{date}`, `/convert`, and `/history/{code}` date parameters. Conversion requires `from`, `to`, and `amount`.

## Guardrails

# FEATURE: CLI Usage Errors

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Returns the documented usage exit status for invalid CLI invocations. |
| Depends On  | FEATURE-CLI-Foundation.md |
| Provides    | CLI usage error behavior |
| Consumes    | ./fxrates entry point |

## Questions

- None.

## Purpose

Unknown commands, wrong argument counts, and a non-integer value for `serve --port` are usage errors. Each returns exit code 2 and writes no standard output. Diagnostic wording on standard error is not contractual.
